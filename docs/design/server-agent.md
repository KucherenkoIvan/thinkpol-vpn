# thinkpol-vpn — Server agent design

Server nodes: the supervisor, one worker per space, and egress. The entry point is [DESIGN.md](../../DESIGN.md); `RRn` are rows of [RESIDUAL-RISKS.md](../../RESIDUAL-RISKS.md).

## Server agent: one worker per space

Server nodes run a **supervisor** and **one worker process per space**, from M0 on, even while a node serves only one space.

- **Each worker lives in its own Linux network namespace** with its own TUN, WireGuard devices, routing table, firewall rules, resolver and per-space node keys. Spaces can't see each other's packets or routes because they don't share a network stack, not because code is careful. A crash in one space's worker leaves the others running.
- **Workers are sandboxed and tied to the supervisor.** A worker's privileges apply only inside its own namespaces, and it never outlives the supervisor; a crashed one restarts in a fresh namespace. Resource limits: RR38.
- **The root namespace keeps the spaces apart.** A worker owns its veth, so isolation can't rest on the spaces' routes: in the root namespace a space can send only from its own transit address and receive only replies to its own flows, so a forged packet or ICMP error can't touch another space's flows or the root's.
- **The supervisor owns the public address**, the scarce resource. It authenticates every incoming connection or datagram, maps the credential to a space by the map that listed it (never by what the map says), and hands the traffic to that space's worker. Unauthenticated traffic goes to the camouflage target, so a probe sees one ordinary site whatever the number of spaces (no camouflage exists yet: RR30). With ingress off, a node accepts only other servers, and its address is never written into a device's section; the node enforces that itself.
- **A worker answers its peers, never anyone else.** Its replies leave only to addresses its space's own authenticated, fresh, non-replayed datagrams recently came from, so it can't use the node's public address to reach anyone else, whatever egress its space has. A replay, which needs only a passive tap, is dropped before it reaches a worker or costs its space anything while the supervisor runs; after a restart, one sealed before the supervisor started is dropped too, which leaves the gaps RR34 lists.
- **Pre-authentication parsing moves out of the root supervisor** into an unprivileged, sandboxed **gatekeeper** holding no space keys beyond what verification needs, so a memory-safety bug there doesn't cost a root process with every space's credentials (RR37). For symmetric `udp`, verifying is forging: whether the gatekeeper gets keys that can only verify, separate admission and content keys (it can admit a datagram but not inject its contents), or its sandbox as the boundary, is TP-063's to decide (RR33).
- **A replay must not be an oracle.** In the planned stream transports a replayed handshake takes exactly the camouflage path, with the same upstream connection and timing: dropping or resetting it would tell a member's handshake from a stranger's. `udp` drops replays; after a restart, those sealed before it, which leaves the gaps RR34 lists.
- **A restart reopens the replay window only narrowly** (decided in TP-069). Replay memory lives in the receiving process and dies with it, together with the workers' WireGuard devices, which would answer a replayed initiation as new. So a Router, and a device-mode node's listener, refuse every datagram sealed before the second they started in, that second read on the current wall clock (the time less the monotonic time since the start, so an NTP step after the start moves it along). A worker's listener behind a Router has no such rule: the Router in front already refuses those datagrams, so a worker restart costs nothing. What still gets through (RR34): a capture sealed in the start's own second, so a restart that finishes within a second leaves that second's captures open; the start's second is taken because the sealed send time has a one-second resolution, and refusing it would refuse genuine traffic for up to a second after every start, and every test on a real clock. A capture from a sender whose clock runs ahead of the node's, as far as it runs ahead. And since the rule has only the node's clock to go by, a capture from as far before the start as the node's clock was behind when it started (before its first NTP sync, until the sync), or as far as a step back after the start moved it (an attacker who can spoof NTP to the node can make one). The cost: a datagram sealed before the start can be genuine too, from a dialer whose clock runs behind the node's, and that dialer is refused for as long as it is behind after each start, at most five minutes. Rejected: persisting each credential's sender state, which would write each credential's last activity to the node's disk (see [Node safety](security.md#node-safety)) and still lose whatever a crash kept from being written; holding the listeners closed for a clock window after each start, which would cut every link for five to ten minutes per restart.
- **Bounded state.** Everything kept about unauthenticated or replayable traffic is bounded, so no peer can grow a node's state without limit; a bound that is hit refuses rather than forgets wherever forgetting would let a replay back in (`udp`'s memory of evicted senders forgets: RR36).
- **The camouflage target is chosen per node**, not defaulted fleet-wide: one default shared by every node is a fingerprint of the fleet, and the target should be plausible for the node's address and network (RR32).
- **Egress:** all spaces exit from the node's public IP. A space's traffic reaches the internet only for the families its map grants and the uplink carries, never the destinations no space should reach (metadata services, private networks), enforced in its namespace and again in the root. Forwarding the supervisor turns on carries only the spaces' traffic and is put back when no space needs it or the supervisor closes; a host that already forwards is left alone, its forwarding unconfined. Egress is a Linux server's worker forwarding and masquerading its space's internet traffic (NAT66 for IPv6); a node in device mode never forwards, whatever its section says.
- **Fair share:** the supervisor enforces each guest space's bandwidth cap and splits spare capacity under load (not wired yet: RR38).
- **Node-level control** (updates, which spaces it serves, caps) is the **node owner's**, within [the node's ceiling](overlay.md#node-agent); a guest space configures only its own worker, through its own map.
