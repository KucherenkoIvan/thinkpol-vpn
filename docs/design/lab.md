# thinkpol-vpn — Censor lab design

The censor lab: the test suite and the definition of done for a transport. The entry point is [DESIGN.md](../../DESIGN.md); `RRn` are rows of [RESIDUAL-RISKS.md](../../RESIDUAL-RISKS.md).

## Censor lab

The test suite, and the definition of "done" for a transport. Docker Compose with a client, a **censor** container between client and entry, an entry, an exit, an "internet" target and a real site for camouflage. Censor modules, each switchable:

- IP and SNI blocklists
- WireGuard and OpenVPN fingerprints
- fully-encrypted-traffic heuristics (as in *How the Great Firewall of China Detects and Blocks Fully Encrypted Traffic*, USENIX Security 2023)
- active prober, with the upstream tell: on every failed probe the entry dials the camouflage target, which a censor sees from a vantage on the entry's uplink. The tell is reported, not gated: REALITY dials the target on every connection by design and can't avoid the dial, so the M2 gate's reality rows run the prober with `upstreamTell: "report"` and are judged on the probes' answers (owner, 2026-11-09; RR31)
- the server hello's JA3S/JA4S, extension order and ALPN, compared with the camouflage site's answer to the same ClientHello
- JA3/JA4 fingerprint filtering
- whitelist mode: everything whose destination address isn't listed is dropped first, then the name in the handshake is checked; UDP is dropped even to listed addresses; variants throttle the rest (to about 14 kb/s), reset it, or let it time out. A name-only check, still seen on some lines, is a separate, weaker module
- volume-based throttling
- WireGuard rhythm inside TLS: the handshake pair WireGuard sends every 2 minutes and its fixed-size keepalives, visible as record sizes and timing in an encrypted stream (an M2 gate check, [milestones.md](milestones.md#milestones); flow shape beyond it is not tested at M2)

The censor sees streams, not only packets: each direction of a TCP connection is reassembled in order as a Linux receiver reads it, linked to its reverse, and its first bytes kept for active modules to replay. Where copies of the same bytes differ, it keeps the copy Linux keeps; what Linux discards (a bad checksum, data without ACK, on a SYN or an RST, a segment far past any window) never enters the stream; a new connection on an old one's addresses and ports starts over once the server accepts it. The few discards it doesn't make as Linux does are listed in the package doc's Limits: a transport that passes the censor by one of them proves nothing. A passive module can tag a flow as suspect for an active one, and one module can be both. Verdicts compose by one rule: only drop and reset end the module walk, so one module letting a flow through or throttling it never stops another, or the prober, from blocking it, and a flow's verdict only gives way to a more severe one. Reset sends RSTs to both ends of an established connection; throttling polices both directions of a connection to a rate and never holds packets. The camouflage site sits behind the censor on a network of its own (`lab.Upstream`), so an entry's connection to it crosses the censor as a client's does: the prober's upstream tell is visible there. The package doc of `lab/censor` has the mechanism.

Besides censor modules, the lab runs two non-censor checks:
- **Isolation:** two spaces share an entry, and every attempt to reach across fails.
- **Seizure:** a snapshot of a node's disk and memory is searched for member IPs, names and destinations.

`make lab` runs every transport against every module and regenerates a pass/fail matrix committed as `lab/RESULTS.md`. A cell passes only when data crossed over IPv4 and IPv6 and fails only when it crossed over neither: one family alone is partial, which fails the run, so a censor one family slips past never scores as blocking. The one exception is a reference row whose result is chance by nature (a WireGuard initiation is exempt from fully-encrypted about one time in four): its cell varies, accepting any result and saying why, and each family that didn't cross must still be blamed on the case's module; a thinkpol transport's row, a gate row, never varies. A cell whose censor can't be trusted (censord died, the kernel dropped queued packets, an active module missed a snapshot, the module the cell is about never compared what it should) is an error, never a pass: the matrix is honest or not written. An active module (the prober) judges a connection only after it has crossed, so a cell with one probes twice and scores the probe after the module's verdicts. The prober's upstream tell flags an entry that relays to the camouflage site by default (the `relay-tcp` reference row shows it); its `upstreamTell` setting makes it a report instead, which the gate's reality rows use. A row asks for it in its entry of `transports` in `lab/results_test.go`, `moduleSettings: {"prober": {"upstreamTell": "report"}}`, which overrides the active prober case's settings in that row's cells only; `relay-tcp` keeps the default. Every TCP gate row (a row whose name ends in neither ` (control)` nor ` (reference)` and whose underlay isn't UDP) must be listed in the active prober case's `verdictSays`, with what its verdict must say: the prober probes a TCP connection only once its client's first bytes settle (a whole ClientHello, bytes that can't start one, or the bytes the censor keeps), so a hello that never settles is never probed, and without the listing the cell passes unprobed. With it, each family's connections need a flag that says it, read once every tagged connection of the scored probe has its verdict. UDP gate rows aren't listed: the prober never probes UDP, and the `udp` row's fully-encrypted exemption (about 1 in 400) would leave its cell with no verdict to check. Every TLS gate row (one whose underlay is TLS naming the camouflage site, marked `tls` in `transports`; `reality`) must be listed in the server-hello case's `verdictSays` too: its comparison needs the site's answer to the same ClientHello, and a cell whose site dial timed out says "not compared", which only the listing turns into an error rather than a pass. The matrix fails the run on an unlisted TCP gate row, an unlisted TLS gate row, on a row that sets a case's reported module's settings without being listed, and on a row that sets settings of a module that doesn't exist; a module refuses a setting it doesn't have.

## Device testing

What the lab can't show (macOS's routing socket, mDNSResponder, pf, sudo) is shown on a real Mac by `devicetest` ([lab/devicetest](../../lab/devicetest/doc.go)), a Go tool in this repository run only by the owner. Its predecessor was a private bash kit of about 12k lines that ran the checks, judged them and restored the Mac; its bugs cost whole device runs (a guard that voided every capture, decodes to empty text that made checks unable to fail), and its tests were stubs that couldn't reproduce root, routing or setuid behaviour.

Decisions:

- **Record, don't judge.** A run saves evidence (root reads, a capture, snapshots, `thinkpol diag`, timestamps) and never decides PASS or FAIL; an agent judges the evidence afterwards, and a judgement that recurs becomes a Go test over a recorded fixture or a `diag` field.
- **Go, in this repository**, against Python or keeping bash. Go calls the product's own readers (firewall's pf readers, trusteddir, netcfg's default-route lookup, the lab's pcap reader) where Python or bash would re-parse what the product writes and drift from it, as the kit's copy of the route-record format did. Its safety machinery gets real tests: real processes, kill -9 and fsync on any machine, real root in lab nodes; bash's stubs gave false greens. A static binary runs under sudo with no interpreter to set up. Python would be quicker for one-off steps; a plan is data, so it needs neither.
- **A frozen safety core** ([lab/devicetest/safety](../../lab/devicetest/safety/doc.go)) is the only root code, in a binary of its own that links no plan: typed changes, each with its undo synced to a journal before it is made, a dead-man process, and a restore that compares the Mac with its baseline and keeps a run pending until it is clean, or, in a later boot, until nothing of the run's can be left (RESET-BY-REBOOT) or the owner closes it by name (FORGOTTEN); neither is ever CLEAN. It is pinned by a hash test; changing it takes its own ticket and the owner's approval.
- **Plans are data,** one per ticket, and do only what they list; a ticket's plan is never bigger than its change.
- **A broken recorder is caught before any change:** the capture must see a marker, miss a filtered one and decode through the evidence path within 10 s.
- **Private stays private:** evidence lives outside every git checkout (`~/thinkpol-evidence/`, never pruned), and what names a server will come from a private file, read only by plans that need it.
- **One terminal,** every line timestamped; physical steps are asked for there.
- **Reboot tests print a recovery sheet;** the harness installs nothing that acts at boot.

Migration: the old kit runs the end-of-phase device run as it is, and is retired right after it. Then the harness gains its exit-server driver (a container on the owner's server, everything naming it in the private file), then one plan per M2 ticket as each reaches its device run, then the end-of-phase checklist as a plan. The kit's judging code, stub tests and two-terminal sessions are not ported.
