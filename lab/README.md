# The lab

Docker containers on separate networks, driven by Go tests: the censor lab of [lab.md](../docs/design/lab.md#censor-lab) and the place where every Linux networking test runs. All it needs is Docker 27 or later (with Compose v2) and Go; nothing in the lab touches the host's network stack.

```sh
make lab-test     # both streams at once, then tear down (see "Streams")
make lab-harness  # the harness's own tests (make lab-test runs them when the harness changed)
make lab          # the same, ending in the censor matrix: lab/RESULTS.md
make lab-test-default   # the default stream alone: lab tests and every package's tests in a node, under LAB_BUDGET
make lab-test-long      # the long stream alone: the tests that wait minutes on real timers
make lab-gotest PKG=./internal/dataplane/netcfg/... RUN=TestRoutes   # one package, in a node (SKIP=regexp, COUNT=n repeats, LAB_TIMEOUT=d; fails if all skip)
make lab-up       # the standard topology for poking around (prints addresses)
make lab-down     # remove every lab this checkout started
make lab-perf     # performance gates, alone on the host (see "Performance gates")
make lab-test-rhythm-real   # the censor matrix's rhythm cells with WireGuard's real timers, 10 to 15 minutes (see "WireGuard's timers")
```

**Censor modules** are `lab/censor`'s (its package doc lists them and how they compose); the matrix runs every transport against each, one module per cell, and new ones join it as a row of `censorCases` in `results_test.go`. Each transport's row runs in a lab with four of `lab.Upstream()`'s nodes, taken from the censor pool (`startRow` in `matrixreset_test.go`; see [Pools](#pools)): device-a and server-1, the transport's ends; the router, which runs censord; and the camouflage site, which the prober and server-hello compare every row's server with, the relay-tcp and reality rows splice to, and the thinkpol rows' maps are built on (outside the space, as its admin's machine would be, and not the censor's box). No cell reaches device-b, server-2 or internet, so a lab starts 4 containers. A slow row splits its cells across two or three labs (`labs` in its `transport`, dealt in turn by `rowLabs`; the subtests `reality`, `reality lab 2`, `reality lab 3`; a held cell stays in the lab named after the row, alone there when the row has other labs, which is the lab `make lab-test-rhythm-real` selects), each lab running the row's `off` cell first as its own gate (the row's first lab records it): a split trades a lab's start, 4 containers and the off cell, for the cells the other labs take off the row. The labs run in parallel (the longest expected first, by each row's measured time per cell, `cellTime`, and the holds: `matrixLabs`; go test starts fewer parallel tests at once than there are lab slots) and a lab's cells one after another, its `off` cell first; every cell sets its transport up afresh, and after it the lab is reset to the state the row recorded when it took the lab, the camouflage site running (`matrixRow.reset`, `Lab.Reset`, see [Pools](#pools)): what still runs is killed, censord with it, every TCP connection left is aborted (`ss -K`: a killed process's orphaned sockets, and the camouflage site's ends of them, would retransmit into the next cell's conntrack; the reset fails if a connection is left, as on a kernel without `INET_DIAG_DESTROY`, where `ss -K` kills nothing and exits 0, and the test log lists the connections each node had aborted), what the cell left is removed (the router's `censor` table with the other tables, the verdict log with `/run/censor`), and every node's conntrack is flushed until it stays empty (the queue rule's ct match keeps conntrack on, so a cell's flows would outlive it). Then the reset is checked: every node in the recorded state, no conntrack entry anywhere. A reset that didn't hold makes the cell an error, and every later cell of its lab. `ip-blocklist` and `sni-blocklist` block listed addresses (either end) and the names a ClientHello asks for (read from the reassembled stream, so a ClientHello split over segments or TLS records is read whole); `wireguard-fingerprint` and `openvpn-fingerprint` block WireGuard's messages by type and size and OpenVPN's handshake by its opcodes, on any port. Besides the transports, the matrix has control rows (plain TCP, and HTTPS to a site no list names) and reference rows: real kernel WireGuard and OpenVPN over UDP and TCP between device-a and server-1, one tunnel per underlay family, whose handshakes start in the probe, after censord is up, so the fingerprints see them from the first packet. In the `reality` row, server-1 serves reality through its shared listener (`thinkpol up -mode server`, from `lab/maps/reality.yaml`), its target the camouflage site, and device-a comes up in the cell's probe or hold, after censord, so the censor reads its TLS connection from the first byte; in the `udp` row too, device-a comes up there, so the censor sees its link from the first datagram. `wireguard-rhythm` blocks a connection whose records (a TLS connection's application-data records, a UDP flow's datagrams) show WireGuard's rhythm by timing, at any record size: an exchange that stands out (its sizes not seen in the rekey period before it, or after 5 s quiet) three times in a row, each 2 to 3.5 minutes after the one before; a steady run of unanswered idle records; the difference of the record counts each way, read after 300 ms of quiet, stepping by one amount three times in a row 2 to 3.5 minutes apart and flat in between (a WireGuard handshake leaves its initiator one record ahead), a move counting as a step once the readings find its latest value unchanged 2 s after the records that made it, and each step timed as the span of records around it, so the handshake lies inside however busy the connection was (steps whose spans are L long chain from 2 minutes - L to 3.5 minutes + L apart); or a burst of records within 10 ms of each other with one more one way than the other (3 against 2 for a rekey under a ping) recurring with the same counts three times in a row 2 to 3.5 minutes apart. The count and burst signals read no sizes, so padding doesn't hide them; they miss a handshake whose records come further apart at the censor than 10 ms or with other records among them (burst), a connection whose count moves between rekeys (unanswered records one way, answers later than 2 s, requests answered later than 300 ms leaving a different number in flight at each reading: random requests a second answered 0.3 to 1.9 s later), and both miss a rekey whose handshake is answered later than 5 s (a second initiation: the count steps by two, the burst holds one more); they flag a busy or quiet connection that repeats one imbalance about 2 to 3.5 minutes apart, wider for the count by its spans (a poll answered in one record more than its request, a one-way heartbeat): `lab/censor`'s package doc has the measured risks. Its thresholds are WireGuard's timers (REKEY_AFTER_TIME, REJECT_AFTER_TIME, REKEY_TIMEOUT, KEEPALIVE_TIMEOUT, a 25 s persistent keepalive). It reads recurrence from the records alone, so a cell against it says something only when the tunnel runs long enough for three rekeys (up to 7 minutes, up to about 10 minutes when batched) or three idle keepalives. Its case holds the reality row's tunnel and the udp row's for 7.5 minutes first, in use, with the transports' default settings (these two held cells are the long stream's, see "Streams"): a ping every 2 s (with the lab's sped-up WireGuard timers the hold is 55 s, the rekey period 12 s and a ping every 0.4 s, see [WireGuard's timers](#wireguards-timers)), and the hold fails the test unless all its pings came back but 10% (at least 4) and those of one redial per block the module logged (7 s at real time at any timer scale, what a block of the held connection costs its redial); a cell fails if the module blocked the connection meanwhile (the cell quotes its reason), a held cell is an error if the censor didn't read its connection from the start (reality's: the module couldn't frame it; udp's: the censor's first verdict on its tunnel is later than device-a's link came up, so it joined a tunnel already up), reality is expected to fail, caught by its record counts (each rekey leaves the device one record ahead), and its cell says that is a known tell RR65 accepts until cover records go both ways (an expected fail is a correct cell, as udp's is), and the test log sums up the module's trace of the held connection (`trace`: every record's size and timing, what stood out; `THINKPOL_LAB_TRACES` keeps it whole). udp carries WireGuard with its timing untouched: it is the control, and the run fails unless a held case has the udp row, held and caught. The idle case (one ping, then nothing) is out of the matrix until TP-080 (liveness rides on data, idle path probes back off) brings it back: an idle thinkpol tunnel shows no WireGuard rhythm, so udp can't be caught there, and thinkpol's own path probes, one fixed exchange every 1 to 2 s, are the idle tell (TP-223). `fully-encrypted` blocks a connection whose client's first data looks random by Wu et al.'s exemptions (set bits per byte, printable bytes, a TLS or HTTP start), UDP's first datagram too, and then, as residual censorship, every packet from that client to the server's address and port (Wu et al.'s 3-tuple) for 180 s, TCP's after a TCP block and both protocols' after a UDP one, so a redial whose first datagram happens to pass an exemption (an 84-byte random one is more than half printable about one time in 175, a fresh draw on every new flow's first datagram) is still dropped, and an exempt flow's accept names its exemption and the address that opened it, which each cell's test log lists (evidence the score doesn't read); the `random-tcp` reference row, a naive echo server fed random bytes, is what it and the prober must block. `prober` probes the server of a suspect TCP connection from the router (replayed and random bytes, and a TLS handshake of its own when the connection names the camouflage site, as the https row's does) and compares every answer with nginx's on the camouflage node, and flags the upstream tell (or only reports it, `upstreamTell: "report"`), counting server-1's two addresses as one host (`hosts`), as a censor that knows them would, so the reality row, whose target is IPv4 only, shows the tell on every probe over either family, unless server-1 dials the site outside the probes at half their rate or more, over the time the prober has watched outside them, at least as long as the probing (REALITY dials it for device-a's own connections too): the tell is then reported unattributable, never flagged, and the cell scores `not judged`, never a pass; so does a tell reported over a baseline shorter than the probing (the prober starts with censord, so how long it watched before the first probe is a race with the transport's setup, and a cell judged on it would pass or not by timing); the `relay-tcp` reference row, server-1 splicing every connection to the camouflage site as REALITY does with what it doesn't recognize, is what the tell must block; `server-hello` compares a connection's ServerHello (JA3S, JA4S, extensions, ALPN) with the camouflage site's answer to the same ClientHello. Their cells probe twice, scoring the probe after the module's verdicts, since an active module judges a connection only after it has crossed.

**Known flakes.** A cell expected to fail that a censor working as meant lets through by a known chance is marked a known flake in its case (`flakes` in `results_test.go`, with the ticket that measured it and the rate). Only a `partial` there is covered: the cell's detail then starts `KNOWN FLAKE (<ticket>): …`, in the test log and in RESULTS.md, and the cell doesn't fail the run; a `pass` (both families crossed) still fails it, and so does a partial in any other cell. Every flake that occurs is counted: the matrix's test log and RESULTS.md's header say `KNOWN FLAKES: <n> (<cells>)`, and `make lab-test`'s last line says it too, counted from the lists the streams write next to their shares of the matrix, so it shows whichever streams ran (`make lab-test-default` and `-long` too) and whether or not the run failed. One cell carries the mark: udp against `fully-encrypted` (TP-236, owner 2026-11-19), where about 1 run in 120 one family crosses, because a new client/server pair's first datagram passes one of Wu et al.'s exemptions by chance and the censor judges each new pair afresh. The same known flake in consecutive runs is a regression, not chance: a regression that always lets one family through would otherwise show only as a count.

**M0 acceptance** (device ↔ server and relayed device ↔ device pings, the relay proof, no WireGuard at the router) is `TestM0`; what it runs and proves is in [M0.md](M0.md).

## How it is built

- **One image**, `lab/Dockerfile`: Debian slim, pinned by digest, with iproute2, nftables, iputils, tcpdump, curl, wireguard-tools (`wg`; kernel WireGuard for the matrix's reference row), openvpn (the other reference VPN), openssl (`s_server` as a TLS target), nginx (pinned: the camouflage site and the https row's server), netcat, socat (the random-tcp row's echo server), the lab CA and the camouflage site's certificate (see "The standard topology"), and dbus-daemon with systemd-resolved (installed, never started by the image: a test that needs a device resolving through resolved starts both). It is tagged with a hash of the Dockerfile and the platform, so checkouts share it and a changed Dockerfile builds a new tag (one build per tag, serialized host-wide by a lock file next to the slot locks; the first build takes about a minute).
- **No Go inside.** `thinkpol`, and the lab's own tools (`labdns`, a stand-in for resolvers out in the world that answers every name with fixed addresses and prints who asked what; with `-server` and `-query`, asks one resolver one A question and prints the reply's rcode (with ` aa` when authoritative); `censord`, the censor of [lab.md](../docs/design/lab.md#censor-lab), run in the router), are cross-compiled on the host (`GOOS=linux CGO_ENABLED=0`, `GOARCH` of the Docker server, override with `THINKPOL_LAB_GOARCH`) into the run's own binary directory, which every node of the run mounts read-only at `/opt/thinkpol/bin` (on `PATH`). The checkout is mounted read-only at `/src` for test data.
- **Binaries per run.** Each process that starts labs (a `go test` binary of `lab/`, `labctl gotest`) builds once into `lab/bin/run-*`, a directory of its own, so two runs from one checkout never rebuild a binary the other's containers are running. The run removes it when it ends, and `lab/bin` goes with the last one; every test package that starts labs calls `lab.Main(m)` from its `TestMain` for that, and a lab test in a package without it fails. A run that dies first (Ctrl-C, SIGKILL, a test binary's `-timeout`) leaves its directory unlocked: the next run from the checkout, `make lab-down`, and the end of `make lab-test` (unless `THINKPOL_LAB_KEEP` is set) remove it. With `THINKPOL_LAB_KEEP` set, a run lists every lab it starts in its directory's `.kept`; a lab kept for a failed test (or left up by a run that died) keeps the directory, and only `make lab-down` (or `labctl down -tests`, or a later `make lab-test`'s clean-up) removes it, once none of the labs it lists is up: a kept lab another run's clean-up skips, or one Docker failed to remove, keeps its binaries. One gap is accepted: if a run dies while its `docker compose up` is still creating a kept lab, and `make lab-down` asks Docker before that lab exists, the directory goes and the lab comes up without binaries. `make lab-up`'s lab outlives `labctl`, so its binaries live in its own `lab/.run/<project>/bin` and go with the lab.
- **Every node** runs as root with `NET_ADMIN`, `NET_RAW` and `SYS_ADMIN`, `/dev/net/tun`, AppArmor off (its Docker profile blocks the mounts network namespaces need), and the seccomp profile `lab/seccomp.json`: Docker's default plus one rule allowing `pivot_root` with `SYS_ADMIN`, which every worker sandbox needs and the default denies even then. `make lab-seccomp` generates it (`lab/seccompgen`) from `github.com/moby/profiles/seccomp` v0.2.4, the version Docker 29.9.3 vendors; the file is committed, so a lab run needs neither the network nor the generator. `make lint` regenerates it into a temporary file and fails if the committed one differs (`make lab-seccomp-check`), so a hand edit can't pass. The generator is a module of its own so the product's `go.mod` doesn't depend on moby/profiles. To follow a newer Docker, raise the version in `lab/seccompgen/go.mod`, run `make lab-seccomp` and update the version here; `TestSeccompProfileAllowsPivotRootOnlyWithSysAdmin` pins what the profile allows of `mount`, `unshare`, `setns`, `bpf`, `clone3`, `keyctl`, `ptrace` and `pivot_root`, so a new default that changes those fails it until someone looks. Docker Desktop runs containers without seccomp, so only a Linux host shows the denial; declaring the profile gives the nodes the same one on both. That covers namespaces, TUN, nftables (queue rules included) and network sysctls: `/proc/sys/net` is writable, the rest of `/proc/sys` is not. Nodes are **not privileged**; `NodeSpec.Privileged` exists for a need these can't meet, with the reason written next to it. Each node has `THINKPOL_LAB=1` and `LAB_NODE=<name>` in its environment and runs `sleep infinity` under an init unless the topology says otherwise.
- **The lab is sealed.** Before a node's own `Command` runs (it waits for a marker the harness writes last), the harness, in every node: deletes Docker's default routes (a node with a `Gateway` routes IPv4 and IPv6 through it instead); cuts the node off from Docker's bridge, the Docker VM's end of every lab network and the only way out: its addresses are blackholed and an nftables `netdev` table per interface (`tplab_<interface>`) drops every frame to or from its MAC, which also covers its IPv6 link-local address (published ports of other projects listen in the VM); points `/etc/resolv.conf` at nothing (lab names resolve through `/etc/hosts`, which lists every node); and the networks don't masquerade. Docker's own resolver, still at `127.0.0.11` for anything that asks it directly, forwards a name it doesn't know to the node's nameserver, `lab.DeadEndNameserver` (198.18.0.53, in the benchmarking range no lab network or test uses), from the node itself, so the sealing stops the forward. Without it Docker forwards to the host's nameservers from the host's network namespace, which no sealing reaches: Docker 29 does that for every nameserver in the host's resolv.conf, Docker 27 for loopback ones such as systemd-resolved's. A lab node can reach other lab nodes and nothing else, which `TestSmoke/hermetic` checks. Tests must not delete the `tplab_*` tables (no `nft flush ruleset` in a node: flush your own tables).
- **Topologies are declared in Go** and rendered to a Compose file under `lab/.run/<project>/` (ignored by git). There is no shared `compose.yaml` to edit: a test that needs another node declares it.

## The standard topology

```
device-a, device-b ── [devices] ── router ── [servers] ── server-1, server-2, internet
```

`lab.Standard()`: networks `devices` and `servers` (dual-stack), the `router` on both with forwarding on, devices and servers routing through it, `internet` (the target for egress and "direct" traffic) on the servers side. Servers have forwarding on too (relays, exits). Everything between the two sides crosses the router: that is where packets are captured, and where the censor sits. The censor reads each TCP connection as a Linux receiver would (what it still reads differently, and so what evades it, is in the Limits of `lab/censor`'s package doc).

`lab.Upstream()` adds a `camouflage` node on a network of its own, `world`, joined by the router: a server's connection to it crosses the router too, where the censor sees it (the prober's upstream tell, [lab.md](../docs/design/lab.md#censor-lab)). `lab.StartCamouflage(t, l)` runs the camouflage site there: nginx, TLS 1.2 and 1.3, HTTP/2 and HTTP/1.1, on port 443 of both its addresses, with a certificate for `camouflage.example.net` (and `www.example.net`) signed by the lab CA. The image makes the lab CA when it is built and puts it in the system roots, so every node verifies the site as it would a real one: a reality listener's certificate check passes, and REALITY's own detection learns the site's post-handshake records. It is the target reality's listener splices to, and the site the prober and the server-hello comparison point at (the matrix's cases start it with `lab.StartCamouflage` too).

## Writing a lab test

Lab tests drive containers from the host, so they need Docker: put them in `lab/` behind the `lab` build tag. `make test` doesn't run them; `make lab-test` does. A test declares only the nodes it drives, with `Only` (`lab.Standard().Only(lab.Router, lab.DeviceA, lab.Server1)`): every node is a container to start, and the lab's Docker starts only so many a minute. A node the claim is about stays even when the test only checks that nothing reaches it; a node that only builds the map (`newM0Space`'s builder) is one the test already has, such as the router. Every test gets a lab of its own while it runs (its own from `lab.Start`, or one from a pool, below), so tests can be `t.Parallel()`, and every test that takes a lab is: Go runs the tests that aren't before any that are, so one slow serial test holds up the whole package. A test that would hold one lab through a long sequence splits by the behaviour each part proves into parallel subtests, each with a lab of its own (`lab.StartOwnSlot`) and an agent set up afresh. More container starts, but the test takes as long as its longest part. Each part logs how long it held its lab (`in use`), the start apart. A test that needs a setting the harness reads from the environment (`THINKPOL_LAB_PROJECT`) takes it as a parameter (`startAs`, `checkoutProject`, `downRun`) rather than `t.Setenv`, which Go refuses in a parallel test. No lab test needs the host to itself today; the performance gates, which do, are `make lab-perf`'s.

```go
//go:build lab

package lab_test

func TestRelayPing(t *testing.T) {
	t.Parallel()
	l := tunnelPool.Acquire(t) // router, device-a, server-1 (pools_test.go)
	dev, srv := l.Node(lab.DeviceA), l.Node(lab.Server1)

	space := newM0Space(t, l.Node(lab.Router), srv)
	envelope, version := space.build(t)
	space.install(t, srv, "server-1", envelope)
	space.install(t, dev, "device-a", envelope)
	startUp(t, srv) // `thinkpol up -mode server`, stopped at the end
	startUp(t, dev)
	waitStatus(t, dev, mapApplied(version), linkUp)
	s4, _ := space.overlay(1)
	dev.MustExec(t, "ping", "-c", "1", s4.String())
}
```

- **Nodes:** `l.Node(name)` gives `IPv4(network)`, `IPv6(network)`, `Interface(network)` (eth0, …), `Exec(ctx, args...)` (a non-zero exit is an error, `Result` has stdout, stderr and the code), `MustExec(t, args...)` (returns stdout), `WriteFile(t, path, data)`, `Start(t, args...)` for background processes (`Stop`, `Done`, `Output`; their output goes to the test log on failure), and `ExportFS(ctx, w)`, the node's filesystem as a tar stream (what a node leaves on disk).
- **systemd:** a node with `Systemd: true` runs systemd as its PID 1 (unprivileged: its own cgroup namespace, made writable before systemd starts; `/run` a tmpfs; systemd-resolved, systemd-networkd and nginx masked), for tests of the service (`thinkpol service install`). `WaitBooted(ctx)` waits for its boot; `Restart(ctx)` is a reboot: the node seals itself again before systemd starts (its sealing script is kept in `/etc/lab/seal.sh`), and Restart checks it did (its addresses, frame filters, blackholed bridges, default routes), and `/run` is fresh, though the kernel's boot id is the Docker VM's and stays. Processes `Start` ran in it are gone after a restart.
- **Files and disks:** tests read and write nodes' files through these helpers only. They never touch block devices or the Docker VM's disks, and never write to `/src` or `/opt/thinkpol/bin`: the `:ro` mounts don't stop root with `SYS_ADMIN` from remounting them, and they are the checkout.
- **Waiting:** `lab.Eventually(t, timeout, func() error)` polls until nil.
- **Starting nodes and reading what they do** (`nodestatus_test.go`): every test starts `thinkpol up` through `startUp(t, node, args...)`, or `upCommand(node, env, args...)` for a command line it runs another way; a `server-*` runs in server mode unless the args name a mode (`startUpWithoutMode` is the one exception, for TP-111's case: a server started without `-mode` runs as a device). A fact `thinkpol status -json` reports (mode, connection, the map version applied, health and its problems, the overlay's MTU, links, counters, a server's uplink) is read from it, never from a log line: `waitStatus(t, node, checks...)` with checks such as `mapApplied(version)` (on a server, also its workers ready, which exist only after its first serve), `inMode`, `connection`, `health`, `problem`, or `readStatus` for one read. A log line is asserted only where the line is what the test is about or the status doesn't report the fact (a server's worker applying a map, `workerApplied`; a blob fetched; the map's ingress and egress flags), and a check of the status's text view only where that view is what is tested.
- **Failing tests** print the containers' logs. With `THINKPOL_LAB_KEEP=1` a failed test's lab stays up for inspection (`docker compose -p <project> exec <node> bash`, the project is in the log); `make lab-down` removes it.

### Pools

A lab start costs a minute or more on a busy Docker, and most tests hold their lab for seconds to a minute, so tests of one topology share labs one after another: `lab.NewPool(topo, size)` is the process's pool of up to `size` started labs of `topo` (the `lab/` tests' pools are declared together in `pools_test.go`), and `pool.Acquire(t)` gives the test one. A test calls it first, before it registers anything that uses the lab: its clean-up, registered there, runs after the test's own. Then the lab is reset to the state it came up in and checked (`Lab.Snapshot` right after the start, `Lab.Reset` after each test, the censor matrix's per-cell reset too), and goes to the next test only if the check passed:

- **What the reset puts back**: it kills every process the clean state didn't have and aborts every TCP connection left (`ss -K`), then, in rounds until nothing is left to undo, unmounts what was mounted, deletes the nftables tables, links and policy rules added, removes every path added outside `/usr` (and under `/usr/local`), puts `/etc` back from a copy taken with the snapshot (content written in place, as `/etc/resolv.conf` and `/etc/hosts` are bind mounts; files removed extracted again; mode and owner), removes the routes (every table) and addresses added and adds back those removed, writes back the network sysctls that changed and links' MTU and state; then it flushes the route cache and every node's conntrack until it stays empty (Docker's DNS nat table keeps conntrack on in every node).
- **What the check reads** (`nodeStateScript` in `snapshot.go`): processes, links with their flags, MTU and master, addresses, routes in every table, policy rules, the nftables ruleset line by line by table, NFQUEUE queues bound, mounts, xfrm states and policies, qdiscs, the `net.*` sysctls, and the filesystem but `/usr` (every path by type; `/etc` by content, mode and owner, symlinks by target; other regular files by mode, size and mtime, `/var/log` by name only), plus every node's conntrack count. Anything the reset can't put back (a rule changed in a table the lab came up with, a file outside `/etc` changed, an `/etc` symlink re-pointed, a clean link or process gone) fails the check: it is never guessed at.
- **Retired labs**: a lab whose check failed, or whose test failed, never goes back: it is torn down (a failed test's lab is kept with `THINKPOL_LAB_KEEP`, and its log gets the containers' logs since the test took it), and the next test gets a fresh one. The test log says why, and the test binary's last lines count each pool's starts, uses and retirements (`lab pool <nodes>: N labs started for M tests, K retired`); with `THINKPOL_LAB_TIMELINE` set, each take, retirement and tear-down is a `pool-*` line there.
- **Slots and waiting**: each pooled lab holds a lab slot of its own while it lives. A test that finds no idle lab starts one while the pool has fewer than `size`, or waits, first come first served, for one to come back (as long as a slot wait may last). An idle lab waits for its next test as long as its own start took (its slot wait included; at least 15 seconds, at most 3 minutes), then is torn down: waiting longer would cost the slot more than a new start costs the next test, and tearing it down sooner throws away a start the next test of the topology, a minute or two behind under load, would have used (with a fixed 15 seconds, most pooled labs went down after one test). `lab.Main` tears down what the pools still hold.
- **Who gets a fresh lab**: a test that checks the lab's own start (`TestSmoke`, the harness tests), drives a systemd node (units, their enablement and a node's restart are outside what the check reads: `NewPool` refuses such a topology), or is the only test of its topology calls `lab.Start` (or `lab.StartOwnSlot`). A test whose topology a pool has, but for a node the test doesn't drive, can take that pool's lab: the idle node costs nothing next to a start (`TestCensorSeesUpstream`, `TestTheCLIExitsBySysexits`, `TestDNSFollowsTheRulesOnAServerExit` and `TestIngressOffAdmitsOnlyServers` do).

### Adding a node or a network

Declare it in the test, never in a shared file:

```go
topo := lab.Standard().With(
	lab.NodeSpec{Name: "server-3", Networks: []string{lab.NetServers}, Gateway: lab.Router, Forward: true},
)
// or a network of its own, joined by the router:
topo = topo.WithNetworks(lab.Network{Name: "mobile", IPv4Only: true}).With(
	lab.NodeSpec{Name: lab.Router, Networks: []string{lab.NetDevices, lab.NetServers, "mobile"}, Forward: true},
	lab.NodeSpec{Name: "phone", Networks: []string{"mobile"}, Gateway: lab.Router},
)
```

`With` replaces a node of the same name, so the second call above re-declares the router on three networks. A topology from scratch is just a `lab.Topology{Networks: ..., Nodes: ...}`. A node can have a `Command` (its main process) and `Env`. Only the gateway's default route is set up; anything more (a second router, static routes) the test does with `MustExec(t, "ip", "route", ...)`.

### Capturing packets

```go
c := l.Node(lab.Router).Capture(t, "udp")          // tcpdump filter, "" for everything
// ... traffic ...
p := c.WaitFor(t, 5*time.Second, func(p lab.Packet) bool { return p.DstPort == 51820 })
all := c.Stop()                                      // every packet; also stopped at the end
```

A `Packet` has `Src`, `Dst`, `Proto`, `SrcPort`, `DstPort`, `Payload` (after the TCP/UDP header; the whole message for ICMP), the whole `IP` packet, and where it was seen: `Network` (the lab network of the interface, "" for one the lab didn't create, e.g. a TUN) and `Outgoing`. Capture returns once tcpdump is listening, so nothing sent after it is missed. `Complete()` stops the capture and errors if tcpdump reported packets dropped by the kernel or interface (or no statistics at all); a capture's clean-up fails the test the same way, and a check that something is *absent* from a capture should call `Complete` first.

The router sees each forwarded packet **twice**: arriving (`Network: "devices", Outgoing: false`) and leaving (`"servers"`, `Outgoing: true`); filter on one side when counting. Capture works on any node, not only the router.

## Tests that run inside a node

Unit tests that need root, network namespaces, netlink, nftables or a TUN live next to their code, with the usual guard:

```go
if os.Getenv("THINKPOL_LAB") == "" {
	t.Skip("needs the lab")
}
```

`make lab-test` compiles **every** package's tests for Linux and runs each package, as root, in a fresh lab node of its own with `THINKPOL_LAB=1` (working directory: the package's directory under `/src`), so these tests run there and skip everywhere else. The node is alone on one dual-stack network with no route out: tests create the namespaces, veths and TUNs they need. In `make lab-test`, packages run as many at once as the lab slot cap allows, their test builds `LAB_P` at a time (`labctl gotest -p` and `-build-p`; see "Tests under load"), each binary with `-test.timeout=10m` unless given its own. For one package: `make lab-gotest PKG=./internal/... RUN=regexp` (`SKIP=regexp` skips tests, `labctl gotest -skip`; `LAB_TIMEOUT=d`, from the environment or the command line, is every test binary's `-timeout`). From a lab test, `node.RunGoTests(t, "./internal/agent/...", "-test.run", "X")` runs packages inside any node of a topology (that node, not a fresh one).

**Cached passes.** In-node runs go through `docker exec`, so go test's own cache never sees them; labctl keeps its own. A package whose tests passed in a node before, on this machine, with nothing they depend on changed, is not run again: its line reads `=== lab gotest <package> (cached)` (with `-v`, as `make lab-gotest` runs, `(cached: N passed, M skipped)`), no lab starts for it, and the run's last line counts the cached packages. The key is the test binary's sha256 (so any change to code it compiles in), the lab image's ID (labs run the image by that ID, not by its tag), the Docker engine's version, kernel and CPU count and whether its kernel has br_netfilter, labctl's own binary (how nodes are set up; `make lab-test` and `make lab-gotest` build it alike, `-trimpath -buildvcs=false`, so a commit that doesn't change labctl's code keeps its records) and `lab/seccomp.json`, the working directory, the args the binary gets (`RUN` included) and its extra environment. On top of that come the files the test binary opened, stat'ed or changed into under `/src` (testdata, a file of another package's such as `lab/maps/m0.yaml`, a directory's listing, a file it found missing) and under the binary directory (`thinkpol`, `labdns`, `censord`, built without the VCS stamp so a commit that doesn't change them leaves them as they were), hashed by content: the binary writes them to its `-test.testlogfile`, which go test's cache uses the same way, and labctl reads it back before the lab goes down. Files of the image itself and the node's scratch space are covered by the image or start fresh. Only a pass is recorded, and not when one of its inputs under `/src` (a file, a directory, or for a missing one the nearest directory above it that exists), or a directory above it up to the checkout's root, was modified or had its inode changed since the package started (its mtime or ctime, which a file copied or moved over it with old times, `cp -p` or `mv`, can't fake, nor a directory renamed or a directory symlink re-pointed over the input's path, `mv` or `ln -sfn`; a change up to 2 s before the start counts too, for coarse file clocks): the run may not have read what is there now. A file added or renamed in one of those directories during the run (an editor's save beside an input) keeps it from being recorded too. `lab/seccomp.json` is checked the same way, since Compose reads it only when the package's lab starts, after it may have waited for a slot. The binary directory is the run's own, written while other packages run, so its files are only hashed. A pass serves for 7 days from when it was recorded, however often it is used, so a test that depends on the date (a testdata certificate that expires) runs again at least weekly. The test binary gets `-test.paniconexit0`, as under go test, so a test that calls `os.Exit(0)` fails the run instead of ending it green with the rest unrun. Blind spots, as in go test: what a test reads without package os in its own process (a subprocess reading the checkout, an absolute path it executes without stat'ing it first) isn't seen, so such a test stats the file itself. A pass in which tests skipped because of the host (`nproc` below 2, no `/proc/sys/net/bridge`) is cached against the CPU count and br_netfilter in the key: on a Linux host running its own engine labctl looks at the host's `/proc/sys/net/bridge`, elsewhere (Docker Desktop) it starts one container of the lab image per run to look. When asking the engine fails, labctl says so and the run's packages all run uncached, without asking again. Not in the key: where a symlink under `/src` points (it is followed on the host, which may differ from what the node sees when it points out of the checkout), the Compose plugin's version and the daemon's own configuration (`daemon.json`); after changing those, run once with `LAB_NOCACHE=1`. `-count` (`COUNT=1` included, for `make lab-test`'s node phase too) and `make lab-perf` run every package and record nothing, as does `LAB_NOCACHE=1`. The records are files under the user's cache directory (`thinkpol-lab/gotest`, `~/.cache` on Linux), shared by every checkout and run of the user on the machine: each is written to a temporary file and renamed into place, so concurrent runs see a whole record or none, and a record that doesn't decode or names another key is a miss. Records unused for 30 days go, checked at most once a day. A cache that can't be set up (no cache directory, an unwritable one) never fails a run: labctl says so and runs every package, or, when only the trim failed, says so and keeps using it.

`make lab-gotest` takes any package pattern, `./lab/...` included. It runs the tests each package has without the `lab` build tag in a fresh node, as above. Then, for every package with tests behind the tag (today `./lab` and `./lab/prototypes/reality`), it runs `go test -tags lab` for that package on the host, the way `make lab-test`'s `lab/` phase does (`labctl gotest -tagged`, timeout `60m` unless given). Those are lab tests: they start their own labs and run in-node tests there. A node can't run them, since it has no Docker; without the host run they would not be compiled in, and in-node tests that need one of them to set things up (`TestRealityClientInterop` needs `TestRealityPrototype`, the reality transport's `TestStockXray` needs `./lab`'s `TestRealityStockXray`) only skip. `make lab-gotest` fails a package in which tests ran and every one skipped, counting both runs, and fails a run in which no test ran at all (`labctl gotest -fail-skipped`, which implies `-v`). A warning would scroll past in the output while the exit status stayed green, and that green status is what a ticket cites as evidence. `RUN` applies to both runs; a package where `RUN` matches nothing is not a failure as long as some other package ran a test. An in-node test that a lab test runs is reached through that lab test: `RUN=TestRealityClientInterop` alone only skips it twice and fails, `RUN=TestRealityPrototype` runs it. `make lab-test` passes neither flag: its `lab/` phase already runs the lab tests, and its node phase over `./...` includes packages whose tests skip in a bare node by design. That is also why `make lab-gotest` needs `PKG` and stops with an error without one: over `./...` it would fail by design and run every lab test on the host under one time limit. `make lab-test` is the target that runs everything.

## Streams

`make lab-test` runs two streams at once, under one run id, and tears down after both, on Ctrl-C too (unless `THINKPOL_LAB_KEEP` is set):

- **default**: the `lab/` packages' tests (`THINKPOL_LAB_STREAM=default`; the harness's own tests skipped), every package's tests in a node (the node phase) and the harness phase (below, "Tests under load"), under a time budget. `make lab-test-default` runs it alone.
- **long**: the lab tests that wait minutes on real timers, which no watcher can see sooner, or on timers only the lab's build speeds up (still the longest waits): the tests under `lab/` that `LAB_LONG_TESTS` in the Makefile names, run with `THINKPOL_LAB_STREAM=long`. The default stream doesn't wait for it: its budget and verdict are taken when its own phases end. It is not free, though: it draws lab slots from the same cap as the default stream (two slots for its 4 to 6 minutes or so today, with the sped-up WireGuard timers; about 12 at real time), so a default stream short of slots waits for them. `make lab-test-long` runs it alone. Today it is the censor matrix's held cells: the `wireguard-rhythm` case's reality and udp cells, each holding its tunnel through three of WireGuard's own rekeys, whose timers are constants in wireguard-go and are what the module watches: 7.5 minutes at real time, 55 s with the timers the lab's build speeds up (see "WireGuard's timers"). Each held row runs in a `lab.Upstream()` lab of its own in the long stream (two more labs, four containers each), its `off` cell again first, as the held cell's gate; the default stream runs every other cell, the held rows' other cells included.

A test that waits minutes on real timers joins the long stream: it calls `lab.LongTest(t)` first, which skips it in the default stream, and its name goes in `LAB_LONG_TESTS`. A test with long parts and short ones calls `lab.SplitStreams(t)` instead, which says which stream it runs in, and runs only that stream's parts (the censor matrix does); outside a stream, as under a plain `go test`, everything runs. `TestLongTestsNamed` fails unless `LAB_LONG_TESTS` names exactly the tests that call one of the two, and fails on any other use of either, under whatever name `lab` is imported as: a call must be one of a top-level test's own statements (not in a subtest, a helper or an `if`), in a package under `lab/` (a test elsewhere runs in the node phase, which no stream reaches). The long stream runs `LAB_LONG_TESTS` over every package under `lab/`.

**RESULTS.md needs both streams.** `make lab-test` builds `./lab`'s test binary once, at its start, and both streams and the assembly run that binary, so a checkout edited or switched mid-run can't change what writes RESULTS.md. Each stream writes its share of the matrix's cells to `THINKPOL_LAB_RESULTS_DIR` (the run's temporary directory), with the commit the run started from (`THINKPOL_LAB_COMMIT`, `git rev-parse HEAD`, `-dirty` with uncommitted changes); once both have ended, `make lab-test` assembles RESULTS.md from the two shares (`TestAssembleCensorMatrix`). Each share also says the factor its stream ran WireGuard's timers sped up by, and RESULTS.md's header says the shares' factor, not the assembling process's. A share missing, short of its cells, of another commit or stream than its file's, of a factor out of 1 to 10 or other than the other share's, holding an errored cell, or from a stream whose matrix failed fails the run, and RESULTS.md is not written; so does an assembly that didn't pass (it skipped, or matched no test). A stream run alone writes no RESULTS.md and says so. `go test -tags lab -run TestCensorMatrix ./lab` by hand, with no stream set, runs every cell in one process and writes RESULTS.md itself.

**The budget.** The default stream fails when it runs longer than `LAB_BUDGET` (default `15m`, a Go duration; `0` turns the check off and only reports the time; empty or negative is an error before anything runs). It's measured as wall time from the start of the run (`make lab-test`'s or `make lab-test-default`'s recipe: building labctl and the `./lab` test binary, removing stale labs, every lab's setup and teardown included) to the end of the default stream's last phase, the harness phase included; the long stream doesn't count. The budget fits the machine the lab runs on: a slower machine sets its own in its environment (`export LAB_BUDGET=25m`). Every run prints the default stream's time against its budget, and the long stream's time. Over budget, the report lists the 10 slowest tests, each with its wall time: the `lab/` tests and their direct subtests (the matrix's rows; a test whose subtests are listed is left out, its time is theirs), the harness's tests when they ran, and the node phase's packages (from the package's lab start to its end; a cached one, or one that never ran, isn't listed). The `lab/` phases run `go test -json` (`./lab` through `go tool test2json`) through `labctl testjson`, which prints what go test without `-v` would: a failed test's output with that of its failed subtests, not its passed ones', and without the `=== RUN`, `PAUSE`, `CONT` and `NAME` lines, cut to its first and last MiB; a test that never ended (a panic, a timeout's goroutine dump) whole. It keeps each test's time for the report.

**Exit status.** Over budget fails the run, but apart from a test failing: the last line says which. A run in which a test, the assembly or the tear-down failed exits 1 and ends `lab-test: FAILED: <what>` (adding `; also OVER BUDGET (<took> > <budget>)` when it was); a run in which everything passed but the default stream ran over its budget exits 3 and ends `lab-test: tests passed, OVER BUDGET (<took> > <budget>)`; a clean run ends `lab-test: passed`. Each of those lines ends `; KNOWN FLAKES: <n> (<cells>)` when a stream that ran had a known flake (see "Known flakes"). make itself exits 2 whenever a recipe fails and quotes the recipe's own status (`Error 1`, `Error 3`).

## Tests under load

Several agents run `make lab-test` at once, so every test runs on a busy machine: a goroutine, a tcpdump or a whole node can be held up for hundreds of milliseconds. A test that passes only on an idle machine is a broken test. What holds up:

- **Synchronize, don't sleep.** Wait for the event itself (a counter, a log line, a kernel flag, a channel), with a generous deadline; a fixed sleep before an assertion is a race. Sleeps are fine only for "nothing happens" windows, which load can only make pass, and each says why no watcher can see it. An absence in the censor's verdict log is read after its watermark (`censor.EventWatermark`) has caught up with the queue, not after a few seconds of polling; a cell that should be blocked stops probing after a failed attempt during which the log shows its blocker dropping or resetting a flow to or from server-1's address of the family probed (either family on a one-underlay row) and not accepting that flow after: any such flow in the attempt's window counts, not only the probe's own. A product timer that is the behaviour under test runs sped up in the lab rather than waited out: the kill switch's re-apply tick and its direct destinations' expiry (`THINKPOL_LAB_KILL_SWITCH_REAPPLY`).
- **Lossy paths retransmit or count.** UDP over loopback or a lab network drops a datagram when its reader is held up and the socket buffer fills. A ping-pong resends after a timeout, a burst goes in batches the receiver has room for, and an exact count comes from the protocol's own counters, not from packets that crossed a socket.
- **Time bounds prove a mechanism, not a speed.** Bound an elapsed time only to tell two mechanisms apart (a retry on the test's interval versus the default one), with the bound far from both.
- **Performance belongs to `make lab-perf`** (below): throughput, loss under load and latency targets. `make lab-test` keeps a check of the same path that load can't change.
- **Statistical checks** state their false-failure probability in a comment; keep it negligible (one in tens of millions of runs, or rarer).
- **Captures** have a ring of about 500 frames: pace what you send, and filter to one side of a router (`outbound`) when you count.

`make lab-test` runs its phases **at the same time**: the `lab/` tests, the in-node packages and the harness's own tests (the default stream), and the long stream, each phase's output prefixed (`[lab]`, `[node]`, `[harness]`, `[long]`), one exit status for all, the tear-down after all. They draw lab slots from the same cap, so a concurrent run competes with all of this run's labs at once.

The harness's own tests, named `TestHarness…` (two labs isolated from each other, an IPv4-only network, a command starting sealed, labs belonging to their checkout and run, subnets of labs starting at once, another run's binaries), check the lab rather than the product, so the `lab/` phase skips them and `make lab-harness` runs them. `make lab-test` runs them only when what they check changed: it hashes the non-test Go files under `lab/` (the harness, `labctl`, the lab's tools and censor), the `lab/harness*_test.go` files, `lab/Dockerfile`, `lab/seccomp.json`, `go.mod`, `go.sum` and the Go, Docker, Docker kernel and Compose versions (`make lab-harness-hash` prints the hash), and a pass leaves a stamp named by that hash in `LAB_HARNESS_CACHE` (default `~/.cache/thinkpol-lab/harness`, shared by checkouts, since the hash names the content); with a stamp, the phase says so and runs nothing. A pass in which a harness test skipped leaves no stamp, and says so. Nothing else under `lab/` (the maps, the camouflage site's config, the censor's test data) changes the hash: the harness tests don't use them. A new harness test takes the `TestHarness` prefix and goes in a `lab/harness*_test.go` file, with every helper it reaches: `TestTheHarnessHashCoversWhatItsTestsReach` fails on a harness test that reaches a declaration in another test file, since a change there would weaken it without rerunning it. `TestSmoke` stays in the `lab/` phase: every test relies on the sealing it checks.

**How much runs at once** is the machine's setting, not the job's: `make lab-test` starts as many labs at once as the lab slot cap (`THINKPOL_LAB_MAX_LABS`, default 12, the Makefile's `LAB_SLOTS`) allows. The `lab/` phases' tests run with `-parallel` set to it (Go's default, the number of CPUs, would leave slots idle on a machine with fewer cores than slots; the harness phase's is never under 4, which one harness test needs to start its labs together, since `-parallel` counts tests, not labs), and the node phase runs that many packages at once, each in a lab of its own. A machine with less memory, or a Docker that starts containers slowly, sets a lower cap in its environment (`export THINKPOL_LAB_MAX_LABS=8`), and every run there follows it. The slots bound every phase of every run that shares the `TMPDIR` together, so a second run beside the first queues for slots rather than multiplying the labs. `LAB_P` (default 4) bounds only the CPU-bound part, the node phase's package test builds at once: it is the CPU share the job has on the machine, so builds run ahead of the labs, which mostly wait on containers. A package waits for a lab only once its build is done, and a cached one never takes a lab. `labctl gotest` takes them as `-p` (labs) and `-build-p` (builds), each at least 1. Neither is lowered when the host is busy: the load that matters comes from other runs, which a run can't control, and the Docker VM's load isn't the host's load average. The `lab/` phase has `LAB_TIMEOUT` (default `60m`, as `make lab-gotest COUNT=…` has) for its `go test`: its censor matrix alone has taken 21 minutes on a slower host, the whole phase 2932 s there (82% of the cap) on 2026-11-15, and a hung run only costs that cap.

`labctl gotest -count n` (`make lab-gotest PKG=... RUN=... COUNT=n`) repeats tests in one node, and the package's lab tests on the host, to show a fix holds. `make lab-test COUNT=n` passes it to the node phase (the `lab/` phase always runs with `-count=1`), so `COUNT=1` runs every package uncached.

## WireGuard's timers

The `thinkpol` the lab puts in its nodes runs WireGuard's timers sped up, by 10 unless `THINKPOL_LAB_WG_TIMER_SCALE` says otherwise (1 to 10; 1 is real time). The lab's build of it, and nothing else, reads a go.mod of its own (`go build -modfile`, written to a temp dir with the checkout's go.sum): the checkout's go.mod plus `replace golang.zx2c4.com/wireguard => <copy>`, the copy being wireguard-go with its `device/constants.go` timers (REKEY_AFTER_TIME, REKEY_ATTEMPT_TIME, REKEY_TIMEOUT and its jitter, REJECT_AFTER_TIME, KEEPALIVE_TIMEOUT, the cookie refresh, the initiation rate limit, the under-load time) divided by the factor, their relations kept (the jitter's whole milliseconds round down), and its counts and sizes left as they are. (`go build -overlay` can't do it: it refuses to replace files in the module cache.) The copy lives in the user cache, `<os.UserCacheDir>/thinkpol-lab/wgtimers/<version>-<hash>` (`~/.cache` on Linux, `~/Library/Caches` on macOS), one per wireguard-go version and factor, so the binary stays the same from run to run; each build checks the copy's content against the module and makes it again if it differs, and removes copies a killed build left unfinished. Delete the directory to reclaim it. go.mod, `make build`, release builds and the package tests run in nodes never see it.

The build fails if `device/constants.go`'s constants change (one missing, renamed or added), so an upgrade of wireguard-go can't run real timers there unnoticed. It checks that file only: a timer written as a literal elsewhere in wireguard-go would keep real time unnoticed.

Every lab test runs with these timers, not only the rhythm cells, and so does product code that derives from them: at the default factor the exit handshake deadline (`dataplane.ExitHandshakeDeadline`, 3 × REKEY_TIMEOUT) is 1.5 s, WireGuard gives up a handshake after 9 s (REKEY_ATTEMPT_TIME) and drops a session after 18 s (REJECT_AFTER_TIME). The real values are proven only by a full lab at real time, `THINKPOL_LAB_WG_TIMER_SCALE=1 make lab-test`, run at milestone gates.

At the default factor a tunnel rekeys every 12 s, and the matrix's `wireguard-rhythm` cells hold their tunnels 55 s instead of 7.5 minutes, the module's `rekey` period set to match. The module scales the windows that are wireguard-go's timers (REJECT_AFTER_TIME and REKEY_TIMEOUT in the rekey window, the quiet before an idle record, the pair window's cap at REKEY_TIMEOUT); the persistent keepalive in the rekey window is a peer's setting and its own choices are about the network (the count's 300 ms settle, the 10 ms burst gap, the idle run's jitter), so they keep real time (`lab/censor` package doc). The hold's ping scales too, to every 0.4 s at the default factor: each end sends before KEEPALIVE_TIMEOUT (1 s), so wireguard-go adds no passive keepalive, and records come closer together than the quiet (0.5 s) and further apart than the count's settle, the same order as a 2 s ping against the real timers. That order is why the factor stops at 10.

What a scaled cell can't show: everything else keeps real time (reality's own timing, TCP, thinkpol's path probes), so each rekey comes with less of their noise around it than at real time, and a signal that real-time noise would break (a count step lost to a request in flight, a burst split by a stray record) can still fire here. A scaled cell that is expected to fail and fails, by the signals the real-timer run shows, says what it says; a cell expected to pass (after cover records go both ways, TP-237) must be judged on the real-timer run. `make lab-test-rhythm-real` runs the rhythm cells, with their labs' off cells, at real time (10 to 15 minutes): run it for every change to transport shaping or to the rhythm rules.

## Performance gates

Throughput targets (PRD Performance) depend on what else the Docker VM is doing, so `make lab-test` doesn't gate on them: a perf test there checks only that the path works, in a way load can't change (flow-controlled, so nothing may be lost), and doesn't measure. `make lab-perf` runs the gates: `labctl gotest -perf` waits until no other lab of any run sharing this `TMPDIR` holds a slot, keeps new ones from starting while it runs (every lab slot holds `perf.lock` shared, a perf run holds it exclusively; its own labs don't wait), builds every package's tests before its first lab starts, so no compile shares the CPU with a measurement, and sets `THINKPOL_LAB_PERF=1` in the node. A gated test measures once and, if it misses a target, twice more, and fails on the median of the three.

A perf test checks `THINKPOL_LAB_PERF` itself (packages under `internal/` can't import `lab`), is named `Test…Throughput`, and its package is listed in the Makefile's `LAB_PERF_PKGS`. Today that is `TestSharedListenerThroughput` (`internal/agent/supervisor`): under 0.5% loss at 100 Mbit/s and at least 50 Mbit/s one way and echoed, all on one CPU; in `make lab-test` it sends 2000 echoes through the handoff with at most 32 in flight, which no queue on the path can overflow, and every one must come back. The lock doesn't see labs from `make lab-up` once `labctl` has exited, runs with another `TMPDIR`, or other projects on the Docker VM; a busy host can also keep a perf run waiting.

## Isolation and safety

- **Names.** Every lab is a Compose project named `tplab-<checkout>-<hash of its path>` for `make lab-up`, plus `-t-<run>-<test>-<hash>` for a test's lab and `-gotest-<run>-<hash>` for in-node tests (the hash covers the package and test, and the process that started the lab) (`go run ./lab/labctl project` prints the prefix). `<run>` is the run's id: `make lab-test` gives both its phases one (`THINKPOL_LAB_RUN`, from `labctl run-id`), and any other process that starts labs (a `go test` of `lab/`, `make lab-gotest`) makes up its own, so two runs from one checkout never share a lab's name. Each process also hashes an id of its own into its labs' names, so two processes of one run (a retry, or shards of the same tests) never claim the same lab either. `THINKPOL_LAB_PROJECT` replaces the checkout part (`[a-z0-9][a-z0-9-]*`, at most 40 characters), never the `tplab-` prefix. No container names are fixed.
- **Ownership is the checkout's path, not the name.** Every lab container and network is labelled `org.thinkpol.lab=1` and `org.thinkpol.lab.root=<checkout path>`. `make lab-down` and the clean-ups find labs by those labels, and remove a project only if its name starts with `tplab-` and every container and network in it carries `org.thinkpol.lab=1` and exactly this checkout's path. Volumes are never removed (the lab has none). Starting a lab under a name this checkout already uses replaces the old lab; under a name another checkout's lab uses (two checkouts with the same `THINKPOL_LAB_PROJECT`), it fails instead, and neither checkout can remove the other's labs.
- **Compose sees only the lab.** Tear-down runs `docker compose` from an empty directory with no `COMPOSE_*` variables, so no compose file or setting of anyone else's is ever loaded.
- **Subnets.** Each lab network gets a /24 from `172.16.0.0/16` and a /64 from a random unique-local /48. That range is the /16 just below Docker's default address pools (which start at `172.17.0.0/16`), so labs don't use up the addresses other projects on the daemon get; if it clashes with something of yours, set `THINKPOL_LAB_SUBNET_POOL`. The choice is checked against every network on the daemon and every live reservation, and retried if Docker still reports an overlap (a network someone created while the lab waited for its slot, outside every reservation), on a read of the daemon that began after the overlap. A pool that the read before the slot shows full gets one more try on a read that began after the slot, as networks may have gone since. The read inspects the daemon's networks four at a time, at most eight inspects at once. Only the choice is serialized host-wide, by a lock file next to the slot locks, and only for a few file operations: a lab reads the daemon's subnets first, before it waits for its lab slot (the lab starts of one process that ask while a read runs take that read's answer), then, holding the slot, under the lock reads the live reservations, picks its own and records them as a reservation (a file in the lock directory's `reservations/`, which the lab's process keeps locked), and lets go; its `docker compose up` runs beside other labs' start-ups. The reservation lasts until the lab is torn down or kept (its networks then stay on the daemon, which every allocation reads). A reservation nobody holds the lock of (its process died) is reclaimed by the next allocation and by `make lab-down`. `THINKPOL_LAB_TIMELINE=<file>` makes every lab start append lines to the file: how long its read of the daemon's subnets took (`subnet-read`); how long it waited for its lab slot and whether it got one (`slot-wait`); when it waited for the lock, held it, and ran `docker compose up`; how long it took from the slot to its sealed nodes, and each step of that (`start`: `create`, the subnets and `docker compose up`; `inspect`, the containers' addresses; `bridges`, each network's bridge; `seal`); and how long its tear-down took (`down`); a pool's takes, retirements and tear-downs are `pool-*` lines (see [Pools](#pools)); runs that share the file give one timeline. `make lab-gotest PKG=./lab RUN=TestLabStartTimes` with `THINKPOL_LAB_START_TIMES=<n>` starts n labs each of one node (as the node phase's), four (a censor matrix row's) and `lab.Upstream()`'s seven, one after another (`THINKPOL_LAB_START_TIMES_PARALLEL=<k>`: k at once), and logs each start's steps, how `docker compose up` spent its time by Docker's events (networks created, containers created, started), and the medians; without it the test skips.
- **A cap on labs.** At most `THINKPOL_LAB_MAX_LABS` (default 12) slots are held at once by labs from tests and in-node runs. A lab's start has three bounds, so a lab queued behind others under load doesn't fail its start before it began: 15 minutes for what comes before the slot (a leftover lab removed, the image and binaries built), 45 for the wait for a slot, and 10 for the start counted from when it holds one. In a test, none runs past the test binary's deadline (`go test -timeout`, `LAB_TIMEOUT`) less 2 minutes for the tear-down, and the slot wait ends at least 10 minutes before that, so a lab still waiting fails with what it waited for, not in the timeout's panic. The price: under the default 60-minute `LAB_TIMEOUT`, a lab whose slot wait begins after about minute 48 has no wait left and fails at once (`no lab slot within 0s, cut short by the test's deadline`) even if a slot would have come free later; a clear failure is taken over the timeout's panic, which would come anyway. An expired bound names itself: `no lab slot within …`, `start not done … after the slot`, `not ready for a lab slot within …`. The cap is kept with lock files in the temporary directory, so it is shared by everything that uses the same `TMPDIR` (normally all of one user's runs); runs with different `TMPDIR`s don't see each other's slots. **Slots go first come, first served**, whichever run a waiter belongs to: each waiter takes a numbered ticket in the lock directory's `slot-queue/` (a file it holds locked while it waits), only the oldest waiter tries the slots, and each of the others watches the ticket just ahead of its own, so a freed slot goes to the oldest waiter and a waiter far back in the queue costs next to nothing. A waiter that is killed loses its ticket's lock with its process, and the next waiter that meets the ticket removes it; one whose wait runs out removes its own; one that is alive but hasn't refreshed its ticket for 15 seconds (a stopped process, a machine that slept) is passed over, and if it comes back the waiter that passed it lines up behind it again (the oldest waiter looks at the queue again every second). Nothing in `slot-queue/` can keep a free slot from being taken: entries that aren't tickets are ignored, a ticket that can't be opened or locked is skipped with a warning on stderr, and a queue that can't be used at all (say `slot-queue` is a file, or `slot-queue.lock` has been held for over 15 seconds by a process stopped mid-scan) makes waiters fall back to polling the slots in no order, each noting it in the timeline (`slot-wait unqueued: <reason>`). All the labs one top-level test starts share one slot, so a test starting a second lab never waits for itself; a test whose subtests each start one lab (the censor matrix's rows, TestM0) gives each subtest its own slot instead (`lab.StartOwnSlot`). Don't mix the two in one top-level test: a parent holding a `lab.Start` slot while its subtests wait in `lab.StartOwnSlot` can wait on itself. A pool's lab holds a slot of its own for as long as it lives, whichever test has it (see [Pools](#pools)). `make lab-up`'s lab doesn't count once `labctl` has exited.
- **Leftovers.** `make lab-test` first removes labs whose checkout no longer exists (`labctl down -stale`), then, at the end, its own run's labs (`labctl down -run <id>`) and the binary directories of this checkout's runs that have ended (unless `THINKPOL_LAB_KEEP` is set). Another run's labs from the checkout stay, running or not. A process of the run that was killed and retried under the same run id leaves its labs beside the retry's (the process is hashed into their names); the final `labctl down -run` removes them too, so they stay only if `THINKPOL_LAB_KEEP` is set or `make` itself is killed; `make lab-down` removes every lab of the checkout, kept ones and leftovers of killed runs included, and `labctl down -tests` every test and gotest lab of it.

Several checkouts, and several runs from one checkout, can run `make lab-test` (or `make lab-gotest`) at once, and `make lab-down` only removes its own checkout's labs.

## Gotchas

- A run's clean-up removes only its own labs, so the labs a killed run left up (Ctrl-C during `make lab-test` leaks the labs its tests had running) stay until `make lab-down`: another run's clean-up, the next `make lab-test`'s included, leaves them. After an interrupted run, run `make lab-down` (once no other run from the checkout is going: it removes all of the checkout's labs).
- Lab networks are not Docker `internal` networks on purpose: Docker drops forwarded IPv4 between internal networks, which would break the router. The sealing above keeps the lab closed instead.
- Lab networks use Docker's `routed` gateway mode. In the default `nat` mode Docker 28 and later drop, in the host's raw `PREROUTING`, every packet to a container's address that didn't arrive on that container's own bridge; on a host with `br_netfilter` loaded that catches the frames a node sends to the router for a node on another lab network, so nothing crosses the router. `routed` has no such rule and no NAT; Docker 27.0 and later accept it, while `nat-unprotected`, the other mode without that rule, needs 28. The networks also keep `enable_ip_masquerade=false`, redundant with `routed`, as a second guard.
- `getent hosts <node>` prefers IPv6; use `getent ahostsv4` for the IPv4 address.
- The image's tags accumulate as the Dockerfile changes; remove old ones with `docker image rm thinkpol-lab:<tag>`.
