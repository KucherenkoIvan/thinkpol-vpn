## Goal
The node's public address belongs to the supervisor, which authenticates every connection and hands it to the right space's worker.

## Scope
- Supervisor listens on the configured public ports of each transport.
- Runs the transport's authentication, maps the credential to a space, hands the connection over: stream connections by passing the file descriptor (`SCM_RIGHTS`), datagram flows by forwarding per connection id over the worker socket.
- Unauthenticated connections go to the camouflage handler and never reach a worker.
- Per-space credential tables loaded from each space's map.

## Acceptance
- [x] in the lab, two spaces on one server (hand-made maps): each worker receives only its own links. `supervisor.TestTwoSpacesShareAListener` (lab node, real sandboxed workers): space A's map section lists two udp dialers, B's one; their inbound tables come from `dataplane.AcceptedInbound` of the hand-written sections. Each worker accepts exactly its own dialers' links (identity `<its space>/<node>`), reads their packets, and its replies reach the dialers through the public socket; `WorkerInfo.Shared` shows Forwarded = Replies = its own dialer count, and the worker receives the same figures over IPC. In-process: `TestWorkersGetOnlyTheirOwnLinks` (also: an entry claiming another space is stamped with the space whose map listed it), `TestASecretTwoSpacesShareIsRefused`, and udp's conformance suite run through the supervisor's shared core (`TestConformanceBehindTheSupervisor`).
- [x] bad credentials never reach any worker. Lab: an unknown secret, a one-byte-off copy of a real secret and random junk of four sizes are all counted `Unauthenticated` on the listener (6 of 6), and each worker's own udp listener reports `unauthenticated=0` (nothing it couldn't authenticate was ever forwarded to it). In-process: `TestBadCredentialsNeverReachAWorker` flips every byte of a genuine datagram in turn (all go to the camouflage, none to the worker; the genuine one then goes through); `TestStreamsAreHandedOver` sends a probe without credentials whole to the camouflage, with the consumed bytes.
- [x] (from TP-009's notes) ≥ 50 Mbit/s through the shared listener on a lab node pinned to one CPU. `TestSharedListenerThroughput`: the supervisor and both workers are pinned to CPU 0 (`taskset`, every thread checked in `/proc`), with the load on the other CPUs and 1400-byte packets. **Paced at 100 Mbit/s: loss 0.000 %** (35 720 of 35 720 forwarded; the test asserts < 0.5 %). Overloaded: **≈ 745 Mbit/s one way**, **≈ 280 Mbit/s each way** echoed. See Notes for what that does and doesn't say.

## Notes
- **Decided in the TP-005 review (2026-10-10):** the tls auth token rides in the ClientHello (e.g. an HMAC of the credential and a coarse timestamp in the legacy session id, via uTLS). The supervisor peeks at the ClientHello without terminating TLS and keeps a replay cache. Authenticated: it hands the fd plus the consumed bytes to the space's worker, which terminates TLS with its self-signed, pinned certificate. Anything else is proxied whole to the camouflage target, so probes see the real site's certificate. See DESIGN.md "Server agent: one worker per space".
- **Port seams (TP-005):** `transport.Routable.Router(peers)` gives a `transport.Router`. Use `RouteDatagram(d)` to authenticate a datagram (tag and timestamp) and get its `Identity`, then forward it untouched over the worker socket. On the worker side, `udp.Transport.ListenOn(pc, ListenConfig{Peers, Camouflage})` serves a `net.PacketConn` fed by the supervisor. `RouteStream(conn)` and `transport.HandoffListener.ServeStream(conn, consumed)` are the stream side, implemented here and in TP-028. `udp/router_test.go` is a working in-process sketch.
- When merging the spaces' tables into one `Peers`, stamp `Identity.Space` from the map it came from, never from the map's contents. Charge a space's fair-share bucket after its worker accepts a datagram. A credential shared by two entries is dropped for both and reported (`Router.Rejected`).
- **Replays and fair share (TP-005 delta review):** `Router.RouteDatagram` keeps no replay state, so it forwards replays of the last five minutes to the worker, which drops them. Those datagrams cost the worker a decryption, but charging fair share after the worker accepts means nothing charges for them. If that matters under load, give the supervisor a small replay filter (per credential, a window of recently forwarded nonces or counters) in front of the worker socket.

- **Done in TP-010 (2026-10-11, review fixes included):**
  - **Shape.** `supervisor.SetListeners([]Listener{Transport, Address, Settings, Camouflage})` opens the node's public listeners (from the node owner's map; guests never open ports) for every space; a listener whose settings change is closed and reopened under a new id (its port is free in between, and lost if the reopen fails, which is reported). `Listeners() []ListenerInfo{ID, Transport, Address, Routed, Unauthenticated, NoSpace, StreamsOverloaded, Rejected}`: the node owner's view only, never in any space's telemetry. `Space.Inbound map[transport][]PeerLink` is each space's own inbound table, from `dataplane.AcceptedInbound(section, reg, space, linkMTU)`, the same function `Engine.Apply` uses. The supervisor merges the tables per transport into one `transport.PeerTable` and stamps every entry's `Space` with the space it was listed under, whatever the entry said. A secret listed twice (in one space or across two) is dropped for both and reported in `ListenerInfo.Rejected`. Options: `Transports` (a `transport.Registry`), `FairShare`, `CountersInterval` (10 s). `WorkerInfo.Shared` is the space's `SharedCounters` (= `ipc.SharedCounters`). A rolled-back SetSpaces re-syncs the tables. The core is `supervisor/shared.go` (no build tag, unit-tested on any OS with in-process workers); the Linux wiring is in `supervisor_linux.go`.
  - **Transport port.** `transport.Router{RouteDatagram(d) (Identity, Verdict); RouteStream(conn) (Identity, consumed, ok); Rejected()}`, with `Verdict` one of `Unknown`, `Routed`, `Stale`, `Replayed`. `transport.PacketRoutable{Routable; ListenPacket(ctx, cfg) (*net.UDPConn, error); ListenForwarded(pc, cfg) (Listener, error)}` and `transport.StreamRoutable{Routable; ListenStream(ctx, cfg) (net.Listener, error); Handoff(cfg) (HandoffListener, error)}`. udp implements `PacketRoutable` (`Listen` = `ListenPacket` + `ListenOn`).
  - **Replay filter in the supervisor.** udp's `Router` keeps the same per-credential sender windows as a `Listener` (`senders.admit`), kept across table changes and for five minutes after a secret leaves. A replay or a stale datagram never reaches a worker, never refreshes a reply address and costs its space nothing; it goes to the camouflage, as a Listener does, and is counted per space (`Stale`, `Replayed`). Replays need only a passive tap to capture. Residual: a new Router (a supervisor restart) routes replays of the last five minutes once more; the worker's Listener, if it kept running, still drops them. Found by the flood test and fixed in udp: a credential's evicted-sender history grew without bound and was purged by a full scan on every eviction, so a dialer churning through senders could stall a Router shared by every space. It is now a ring of at most 1024 ids with O(1) expiry (`TestSenderChurnIsBounded`). A forgotten sender is older than the churning current one, so it stays refused while that one is active.
  - **Routing.** One goroutine per public datagram socket reads with `ReadFromUDPAddrPort` (no allocation per datagram), calls `RouteDatagram`, then looks up the space's route: an atomic snapshot of space → route, where a route holds the current incarnation's sockets in an atomic pointer, set after Ready and cleared when that incarnation ends. Then `FairShare.Allow`, then `TrySendDatagram` on the data socket, which never blocks, then the charge. Drops are counted by cause: `NoWorker` (none running, or its socket going away), `WorkerFull` (`ErrFull` only), `OverShare`. Routes are published before the credential tables, so a link that authenticates always has a route, and a space that leaves is unreachable before its worker stops. `Unknown` and `NoSpace` go to the listener's camouflage (`Drop` by default: udp answers nothing).
  - **Streams.** One goroutine per accepted connection, at most 1024 per listener (more go straight to the camouflage, `StreamsOverloaded`). `RouteStream` runs under a 10 s read deadline, cut short when the listener closes. Then the descriptor (`File()`) and the consumed bytes go by `TrySend` on the worker's control socket (`Streams`, else `StreamsRefused`), or the whole connection goes to the camouflage.
  - **Replies only to live remotes.** One goroutine per worker incarnation reads its data socket and sends each reply out of the listener it names. It goes only to a source address that one of the space's own live (authenticated, fresh, not replayed) datagrams came from through that listener in the last 2 minutes. The window is refreshed by every live datagram: an active link sends far more often (the path layer probes every 2 s, and a live WireGuard session sends at least every 2 minutes), and NAT mappings expire on a similar scale. Each link keeps its latest 8 such addresses and a new one evicts that link's own oldest (`ReplyPeersEvicted`), so no link can displace another's. Expiry is swept at most every 10 s. An address held by two links stays until both let go. Zones are kept (the reply goes to the address as received) and an IPv4-mapped name is unmapped. Refusals are counted by cause: `RepliesNotAllowed`, `RepliesNoListener`, `RepliesOverShare`; failed writes as `ReplyErrors`. A malformed message on the data socket ends the incarnation, like an unknown control kind.
  - **IPC (version 3).** Data socket, both ways: `Kind 5 (Datagram) | listener id [4, BE] | family [1: 4 or 6] | address [16, IPv4 in the first 4] | port [2, BE] | datagram` (`DatagramHeaderSize` 23, `MaxDatagramSize` = 64 KiB − 24), sent with `sendmsg` over two iovecs (no copy): `TrySendDatagram` from the supervisor, blocking `SendDatagram` from the worker (backpressure stays in that worker). Every socket of a pair has 2 MiB send and receive buffers (`SO_*BUFFORCE`, best effort). Control socket: `Kind 7 (Listeners)`, JSON `[]ipc.Listener{ID, Transport, Stream, Address}`, after Ready and on every change (ids are never reused within a supervisor's life); `Kind 6 (Stream)`, `listener id [4, BE] | consumed bytes` with the connection's descriptor attached; `Kind 8 (Counters)`, JSON `ipc.SharedCounters`, every `CountersInterval` (`TrySend`, skipped when full). Listeners, Config and Stop go with `SendTimeout(StopTimeout)`. A send that times out means the worker stopped reading: it is killed and restarted with backoff, so it can't hold up SetSpaces, SetListeners or Close (`TestDeafWorkerHoldsNothingUp`). Any other send error means the worker is gone, and its exit is the reason reported.
  - **Worker side.** `Session.Listeners <-chan []worker.SharedListener` (latest-wins) of `{ID, Transport, Stream, Address, Done}`; `SharedListener.Listen(reg, cfg) (transport.Listener, error)` is the worker's counterpart of `Transport.Listen`: `ListenForwarded` on a datagram listener's forwarded socket, or a stream transport's `Handoff` fed with the handed-over connections until `Done`. Listen once per listener: closing it is final. A datagram listener queues up to 1024 forwarded datagrams, a stream listener 64 connections. `Session.SharedDrops() SharedDrops{QueueFull, UnknownListener}`. `Session.SharedCounters <-chan ipc.SharedCounters` delivers the space's own figures from the supervisor, for the worker's sealed telemetry (TP-041).
  - **Fair share (hook only).** `supervisor.FairShare{Allow(space, n) bool; Charge(space, n)}`: asked before forwarding a datagram or sending a reply, charged after the worker's socket accepted it or after it went out. Unauthenticated, stale or replayed traffic, a full socket and a refusal cost nothing (`TestFairShareChargedAfterTheWorkerAccepts`, `TestReplaysCostNothing`).
  - **No head-of-line blocking.** A stuck worker (full data socket) loses only its own datagrams; the other space's flow on the same socket goes on (`TestAStuckWorkerStallsOnlyItsSpace`). `TestASourceFloodStallsNoOtherSpace`: for 2 s, one space's link opens new senders from new source ports as fast as four goroutines can (~32 000 sources, ~27 000 evictions of its own) while another space ping-pongs on the same socket. The calm space's median round trip was 165 µs. Its tail (p99 ~150 ms, 16 of 422 pings resent) is the shared socket's receive buffer overflowing under the flood, which is network-level load, not the reply table. Stream routing is per connection and bounded; handoffs never block.
  - **Performance** (`TestSharedListenerThroughput`, lab node). The supervisor and both workers (one busy, one idle) are pinned to CPU 0, every thread checked in `/proc`. One udp dialer on the other CPUs sends 1400-byte packets.
    - **Paced at 100 Mbit/s** (1 ms bursts, 4 s, twice the target): 35 720 sent, 35 720 routed, 35 720 forwarded, 0 worker full. **Loss 0.000 %.**
    - **Overload** (as fast as the dialer can): ≈ 745 Mbit/s one way into the worker's link, ≈ 280 Mbit/s each way echoed. Before the review fixes this was ≈ 980 and ≈ 480. Two causes: the supervisor's replay filter and reply bookkeeping now cost per datagram, and with 2 MiB buffers an overload is no longer shed cheaply at the data socket; the worker opens datagrams it then drops from its own queues. Under a load the node can carry nothing is lost; past it, the goodput is what these numbers say.
    - **Caveats.** Over loopback the receive softirq runs on the sending CPU, not on CPU 0, so part of the receive cost is charged to the load generator: the figures overstate a real NIC on one vCPU. The lab node's CPU is also a fast desktop core, not a VPS vCPU. Read the margin rather than the absolute number. The path measured is public socket → supervisor (one AEAD open, replay filter) → data socket → worker (a second open and filter) → link. It excludes WireGuard, the TUN and a second hop, which the PRD's end-to-end ≥ 50 Mbit/s includes (TP-012/TP-033 measure that). No batching (recvmmsg/sendmmsg) was needed for the target; that and SO_REUSEPORT fast paths remain options. The lab can't run `-race` (no cgo in nodes); the race detector ran on the host over the in-process tests.
  - **Not done here, with reason.** No lab test drives a stream handoff through real sandboxed workers: there is no stream transport until TP-028. The seam is tested in-process (`TestStreamsAreHandedOver`, `TestStreamRoutingIsBounded`: a line-based fake transport, real TCP connections, the descriptor duplicated as SCM_RIGHTS does). Descriptor passing over the real socket is TP-009's `TestPassesFileDescriptors`. The worker's `KindStream` handling runs only once TP-028 brings a stream transport.
- **For TP-011 (`thinkpol up`):**
  - **Supervisor mode.** Build `supervisor.Options{Transports: registry, …}`. Per served space, verify and open its map, then `Space{ID, Config, Inbound: dataplane.AcceptedInbound(section, reg, transport.SpaceID(id), linkMTU).Links}`. `SetListeners` from the **node owner's** section `Node.Listeners` only (dual-stack: both `0.0.0.0:p` and `[::]:p`). Re-run both on every map change.
  - **Worker mode.** `agent.RunDataPlane` takes one Inbound abstraction in device and worker modes. In device mode it opens `Transport.Listen`; in worker mode, `SharedListener.Listen(reg, ListenConfig{Peers: engine.Inbound(l.Transport)})` for each listener on `Session.Listeners`, then `go engine.Serve(l.Transport, listener)`, stopping when `l.Done` closes. Feed `Session.SharedCounters` and `SharedDrops` into the worker's status and telemetry. Workers' veths carry only their dialed links and egress.
- **For TP-013 (ingress off):** put the filter inside `dataplane.AcceptedInbound`. With ingress off, drop entries whose `netmap.InboundLink.PeerKind` is a device, so they become unauthenticated (camouflage). The engine and the supervisor then both apply it, so the two tables can't disagree.
- **For TP-014 (egress), decided in the TP-010 review:** a worker's outgoing dials to endpoints listed in its own section are allowed through the root namespace (masqueraded) whatever the egress setting; egress off still blocks everything else. M3's entry → exit hops need it.
- **For TP-028 (tls):**
  - Implement `transport.StreamRoutable`. `ListenStream` opens the public TCP listener. `Router(peers).RouteStream` peeks at the ClientHello and must return **every** byte it read: they go to the worker, or to the camouflage, which proxies them first. `Router.Rejected` reports unusable links. `Handoff(cfg)` is the worker's `HandoffListener`; `SharedListener.Listen` feeds it the handed-over connections.
  - The supervisor's routing deadline is 10 s, with at most 1024 connections being routed per listener. The camouflage proxy is the listener's `Camouflage.Stream`; it must not block, so it starts its own goroutine.
  - Add the lab test of a handoff through real workers that TP-010 couldn't.
- **For TP-040 (caps):**
  - Implement `supervisor.FairShare` as per-space token buckets. `Allow` must be cheap and non-blocking: it runs per datagram on the listener's goroutine. It sees both directions of datagram traffic, and replays are already filtered out.
  - Handed-over streams bypass it. A pacing rate (`SO_MAX_PACING_RATE`) set on the descriptor before the handoff caps only the node's sends; uploads need policing (tc ingress or IFB on the uplink) or a read-rate limit. Add TP-009's veth and cgroup limits.
  - Guests' `Inbound` come from the guests' own maps (`AcceptedInbound`); only the owner's listeners are opened.
- **For TP-041 (telemetry):** each worker receives its space's `ipc.SharedCounters` every `CountersInterval` (`Session.SharedCounters`) and its own drops (`Session.SharedDrops`); seal them into the space's telemetry like the rest. They hold only that space's figures. The owner-only `ListenerInfo` (public addresses, every space's rejected links) must never go into any space's telemetry.

## Review findings
Two reviewers (2026-10-11); the routing core held up and no cross-space leak was found. Decided by the orchestrator.

Blocker:
- [x] B1 Reply-table DoS via replays. (a) A supervisor-side replay filter now: per credential, a sliding window on udp's sender and counter, in front of forwarding and of remembering a remote, so replays are dropped before they cost the space anything. (b) Reply peers kept per link identity with a small cap (8 remotes per link, evicting that link's oldest), so nothing one link does displaces another's. (c) Amortized expiry (a sweep at most once per interval). (d) The reply window refreshed only by live (non-replayed) inbound datagrams and shortened to ~2 minutes, with the reason documented. (e) Tests: a replay adds no entry; a flood of new sources on one space doesn't stall another space's flow (measured); full-table behaviour counted.

Should-fix:
- [x] 2 Control sends with a deadline: ipc `SendTimeout` for Listeners, Config and Stop (StopTimeout); on timeout the worker is killed and restarted with backoff. Test: a worker that stops reading fd 3 doesn't hang SetSpaces or Close.
- [x] 3 Precise DESIGN wording for the reply rule (only to source addresses its authenticated, non-replayed datagrams came from in the last ~2 minutes) and the ticket's replay note (replays need only a passive tap).
- [x] 4 Stream routing: at most 1024 connections in flight per listener; on overload the connection goes to the camouflage; counted.
- [x] 5 One source of truth for inbound tables: `dataplane.AcceptedInbound(section, reg, space, linkMTU)`, used by `Engine.Apply` and the supervisor's composition; TP-013's ingress filter goes inside it later. Fix the TP-011/TP-013 notes.
- [x] 6 Counters: NoSpace apart from Unauthenticated; WorkerFull only for ErrFull, otherwise NoWorker; StreamsRefused; RepliesRefused split (NotAllowed, NoListener, OverShare); ReplyErrors; `RouteDatagram` returns a verdict (Unknown, Routed, Stale, Replay) counted per space; worker-side drops (QueueFull, UnknownListener) exposed through the Session. Telemetry: the supervisor periodically sends each space's SharedCounters to its worker (a new IPC kind, IPC v3) so the worker seals them into its own telemetry (TP-041 note); owner-only fields (ListenerInfo.Address, Rejected) never go to telemetry, and the docs say so.
- [x] 7 Honest signatures: `ListenPacket` returns `*net.UDPConn`; `ListenForwarded` returns `(Listener, error)`; `Rejected()` on `Router`; no generic ReadFrom slow path.
- [x] 8 `SharedListener.Listen(reg, cfg) (transport.Listener, error)`, so TP-011's RunDataPlane takes one Inbound abstraction in device and worker modes; the worker's public API copies fields instead of embedding `ipc.Listener`.
- [x] 9 Throughput: a paced run at 100 Mbit/s (1 ms bursts) with loss < 0.5% by the supervisor's counters; SO_SNDBUF/SO_RCVBUF of 1–4 MiB on the data socket pair; Notes: over loopback the receive softirq runs on the sender's CPU.
