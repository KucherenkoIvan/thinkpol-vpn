## Goal
Decide and prototype how to make the device harness a maintainable tool: a small frozen safety core separate from checks that change often, check logic out of bash, and an in-run self-test that validates harness machinery in the first seconds of a run.

## Scope
Real-device testing has found every macOS bug the lab could not: mDNSResponder scoping, the own-IPv6 checksum, the link-liveness issue. Today the harness lives outside this repo as a large private bash kit. It runs as the developer, takes sudo for route/scutil/tcpdump, restores the machine (a dead-man timer, record-based rollback), drives a remote exit container, captures leaks and samples resources. It has grown into a second product, and its bugs cost whole device cycles. Examples: a guard bug voided every leak capture in one run; a truncated-file bug made valid captures read as invalid. Its tests rely on stubs that cannot reproduce root, routing or setuid behaviour.

R&D deliverables:
- a short design doc comparing the options (Go tool in this repo / Python / keep bash), with a recommendation
- what stays private: anything naming real servers stays outside the public repo, provided through config
- a prototype of the safety core and one check
- a migration plan

## Out of scope
Rewriting every check in this ticket.

## Acceptance

## Notes
Per-round lessons from the kit work: stub-only tests gave false greens; bash `$BASHPID` and `set -u` pitfalls; mixing fixes with new checks in one round; long-lived agent contexts.
- Kit bugs found by cross-model analysis of device run 4 (examples of why the harness needs real tests):
  - pcaps were decoded to empty text (stderr dropped), so packet-count checks always saw zero and could never fail. The run-4 conclusions were confirmed only by re-reading the pcaps by hand.
  - log-line counts double-counted a file that is a prefix of another
  - a counter diff subtracted unrelated lines (the N12 checksum figure)
  - the route monitor missed events during a 12k-route burst

### Device checklist (the owner's first run, answer 14)
From a checkout of this branch (or `rewrite` once merged), as yourself, no VPN or thinkpol agent running, Wi-Fi on:
1. Build: `go build -o /tmp/devicetest ./lab/devicetest`. Then `/tmp/devicetest plans TP-096`: expect 2 steps, 9 root reads, one change ("load pf's main ruleset: "set skip on lo", then /etc/pf.conf") with its undo, and a capture on your physical interface. Nothing is asked and nothing runs as root.
2. `/tmp/devicetest selftest`, type `yes`, then your sudo password. Expect `self-test ok in …` (under 10 s), then a last line `devicetest selftest recorded: 0 of 0 steps, selftest ok, restore CLEAN -> …/thinkpol-evidence/<date>-selftest`. If it says SELF-TEST FAILED, go on to step 6 and send the folder: that is what the self-test is for.
3. `/tmp/devicetest run TP-096`, `yes`, password. Expect `recorded: 2 of 2 steps, selftest ok, restore CLEAN`. If a `STOP:` line asks what to do, press Enter (it restores and ends). If the restore says `REBOOT` or `LEFT`, do what each item's `next` says (for pf: one `sudo pfctl -f /etc/pf.conf`; never `pfctl -F` or `pfctl -d`), and reboot if pf still differs.
4. Ctrl-C: run `/tmp/devicetest run TP-096` again, `yes`, password, and press Ctrl-C twice as soon as `step 1 stock` appears. Expect `stopping after the operation running now, then restoring`, then `restoring, wait`, and `restore CLEAN`.
5. A closed terminal: in a new window run `/tmp/devicetest selftest`, `yes`, password, and close the window at once. In another window, after 10 s: `/tmp/devicetest restore` (it asks for sudo). Expect a result with `"verdict": "CLEAN"` (`no unfinished run` if the helper had already restored by itself).
6. Afterwards: `sudo ls /private/var/db/thinkpol-devicetest` lists `run-…` directories and no `active`; `ls -d /private/tmp/tpdt.*` finds nothing. Zip each `~/thinkpol-evidence/<date>-…` folder of the session and send the paths. An agent judges them; no PASS or FAIL comes from the tool.

What the judge reads: `selftest/selftest.json` and the decode beside it; `steps/02-skip-on-lo/cmd-002…Interfaces-v.out` (`lo (skip)`, or `lo0 (skip)` instead); `actions/pf-main-*` (the stock-rules parse, the load and the reloads); `restore/result-*.json`; `snapshots/00-baseline` against `99-after-restore`.

## Review findings
Round 1 (2026-10-23): correctness (fix first), style (fix first), design (fix first), second opinion (fix first). The split is right and the tests are real; the core still has holes that leave the Mac changed under a CLEAN verdict, and every one costs a ticket and the owner's approval once `FROZEN` pins it, so all of them are fixed now.
- [ ] R1.1 `devicetest restore` says CLEAN without comparing anything: `finish` removes `active` whatever the verdict (`restore.go` ~199), and `RestoreRun` with no `active` (or `Active()` failing) answers CLEAN "no unfinished run" (~261). A LEFT/REBOOT/undo-failed run then unblocks the next, which takes a dirty baseline; checklist step 5 expects CLEAN from exactly this. A non-CLEAN result stays pending (a `left` file naming the run); `startRun` refuses while it exists; `restore` reopens that run, takes a fresh after-restore snapshot, diffs it against the stored baseline, and clears `left` only on CLEAN; nothing to restore is its own verdict (not CLEAN); a failed `Active()` is an error. Tests for each; checklist step 5 updated.
- [ ] R1.2 The journal: a torn last line is skipped but never cut off, so the next `O_APPEND` line merges into it and a later restore fails to parse it forever (`journal.go` ~134, ~151). Only the last line can be cut short of its newline: a complete line that doesn't parse is corruption (an error), a fragment without a newline is torn and is truncated (and synced) before anything is appended. `active` is written after `CreateJournal` has synced its header (`helper.go` ~198), so it never points at a run with no journal. Tests append after a torn tail and reopen.
- [ ] R1.3 Captures: the pid is journaled only after the header wait (up to 5 s) and a `startTime` error is dropped (`capture.go` ~162, ~185; `action.go` ~168-177), so a helper killed in that window leaves a root tcpdump the undo treats as gone, under a CLEAN verdict, promiscuous until 200000 packets. Journal the pid and start time right after `Start` (a failed start-time read fails the action and kills the process); the live helper's undo stops what its table holds whatever the journal says; pass `-p`. The filter goes after `--` and one starting with `-` is refused (`-w/etc/pf.conf` today makes root's tcpdump overwrite that file, a change no journal knows). Tests: a helper killed between start and header leaves no tcpdump; a `-w…` filter is refused.
- [ ] R1.4 The helper protocol can overwrite the baseline on disk: `OpSnapshot` takes any name (`helper.go` ~283, `snapshot.go` ~63), and the dead-man and `restore` read the baseline back from disk, so `00-baseline` taken while the skip is loaded makes the undo a no-op and the result CLEAN. Remove `OpSnapshot` (only a test uses it: send an allowed `OpRead`); snapshot files are written once (`O_EXCL`) under names only the core chooses.
- [ ] R1.5 pf-main: `Prepend` accepts any pf.conf line, but the restore compares only the main rules, nat, skip, status and three anchors, so an `anchor`/`load anchor`/`table` line can survive a CLEAN. Restrict the action to `set skip on <ifname>` (all it is for). `Pre` also requires the current skip set to match the stock one, so the undo never drops a skip another app loaded. The comparison must not drop lines: `firewall.ListingLines` drops any line with `ALTQ`, and `pfAnchor` reads any `Invalid argument` stderr as an empty ruleset: compare raw lines (only header noise dropped) and treat only the missing-anchor answer as empty.
- [ ] R1.6 The dead-man: `exists` reads any error but ENOENT as "the stop file is there", so one EMFILE/EIO disarms it (`deadman.go` ~110): only a successful stat counts. It watches the helper by pid alone (`proc.go` ~13, `helper.go` ~224) and SIGKILLs a bare pid (`deadman.go` ~132): use pid plus start time (`sameProcess`) for both. Its budget runs on the monotonic clock, which stops while a Mac sleeps: count the larger of monotonic and wall-clock elapsed, and say so in the doc.
- [ ] R1.7 After a reboot, `/private/tmp` is empty, so `removeRootCopy`'s `Lstat` fails and a complete restore exits 1 `ok:false` (`launch.go` ~114-120, `restore.go` ~262): a missing root-copy directory is already gone. A helper refused before `finish` (lock held, unfinished run, bad flag) removes its root copy too. `root-restore` ignores SIGINT and SIGHUP like the helper and the dead-man (`main.go` ~48). `pfctl -e`'s result is checked and noted (`settle_darwin.go` ~77). When the dead-man restores after the helper took `99-after-restore`, its own snapshot is kept under its own name, not lost to EEXIST (`snapshot.go` ~47). Tests: a restore whose root copy is gone is CLEAN with exit 0.
- [ ] R1.8 Plans are data, enforced: depguard in `strict` mode with allowlists (plans: `time` and `lab/devicetest/plan`; plan: `fmt`, `regexp`, `slices`, `strings`, `time`), and the plans aren't linked into the root modes (helper, dead-man, root-restore), so no plan `init` runs as root. A plan `UndoLast` with no change of its own before it is refused (it would undo the self-test's capture). Plans have one capture (the helper answers one request at a time, so two captures share the 10 s self-test serially), and the self-test loop is sequential.
- [ ] R1.9 The user side when the helper is gone: `restore()` returns an empty `Result` and the terminal prints `THE MAC ISN'T AS IT WAS ()` (`run.go` ~142, `client.go` ~95): read the newest `restore/result-*.json` from the evidence (the dead-man's), else UNKNOWN with "run devicetest restore". Errors are printed once (logged to the transcript, then a sentinel so `main` doesn't print them again).
- [ ] R1.10 Product APIs: replace `firewall.TokenRecordName` with a reader of what the record means (`GuardReferenceHeld(dir)`: a record from another boot, a symlink or a non-regular file holds nothing; it creates no directory), so a restore after a reboot doesn't wait 30 s and ask for a rollback that isn't needed; firewall's doc.go follows. Export one skipped-names reader from firewall and use it in `pfSkips` (today `strings.Contains(l, "(skip)")` beside firewall's own reading) and the anchor's missing answer the same way. `trusteddir.OpenOwnedBy` checks the last component is owned by uid (root not accepted there); delete the second check in `OpenEvidence`; a root-owned-directory test case. `PfEnabled` → a name that says it parses.
- [ ] R1.11 Core correctness and size: `decodeStrict`'s `any(a) == nil` never fires for a typed nil (params `null` panics the root helper): decode into a value. Unexport everything outside callers don't use (`Engine`, `Journal`, `Entry`, `Snapshot`, `Diff`, `Deadman`, `Helper`, `Evidence`, the action types…; doc.go links become prose). Cuts: `boot_darwin.go`/`boot_linux.go` → `trusteddir.BootSession`; `Response.Stdout`/`Run`/`stdoutMax`; `HelperConfig.DeadmanCommand`; the user side's `tcpdumpPath` copies → the core's; `KindPfMain` declared once; `DefaultStateDir`/`rootCopyBase` into `paths_*.go`; one `broadcastLocked`; `runState` embeds `openedRun`; `NewEngine(…, nil)` in restore gets a refusing func; `config.go` and `NeedsExit` go (they load and discard a config for an exit driver that doesn't exist: add them with it). `TestTheSafetyCoreIsFrozen` also pins the core's import set, so a new dependency moves `FROZEN`. The launch script checks `/private/tmp` is a root-owned sticky directory, not a symlink.
- [ ] R1.12 Docs and ticket: the design deliverable is in the repo: lab.md "Device testing" gets, scrubbed, why Go (against Python and keeping bash) and the migration (the phase-end run on the old kit, then the exit driver, then one plan per M2 ticket); "answer N" / "the 14 questions" pointers become what was decided. No private runbook names in the repo (`pfcheck`, `pfrestore`, `waitstop`, `waitrel`, "the phase-end runbook", in safety/doc.go, surfaces_darwin.go, settle_darwin.go): state the rule itself. Ticket names in comments only where a decision is open. doc.go: "the helper and its dead-man (and root-restore) are the only root processes"; `pfctl -e` in the restore is the one change without a journal entry, say so; the capture line in the listing says the pcap is kept; safety/doc.go "# Tests" shrinks to one sentence (the names are in the ticket). Box 3 is unticked (its Mac half waits on checklist step 2): done in this commit.
- [ ] R1.13 Nits: `PlanSHA256` hashes the listing (with the interface name): rename to the listing's hash; the self-test's `Tries` can report one fewer than made; `plan.Make` makes kind `Do` while `UndoLast` makes `UndoNewest` (core: `OpUndoLast`): one name per thing; os_darwin/os_linux shapes match; `t.Helper()` in `newHelperDirs` and `frozenList`; the needless sleep in deadman_test.go ~60 and `time.Sleep(time.Hour)` → `select {}`; test names that say the behaviour (`TestVerdicts`, `TestTheDeadmanWatches`, `TestTheSelfTestControls`); usage lists every flag.
