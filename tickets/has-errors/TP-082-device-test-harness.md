## Goal
Decide and prototype how to make the device harness a maintainable tool: a small frozen safety core separate from checks that change often, check logic out of bash, and an in-run self-test that validates harness machinery in the first seconds of a run.

## Scope
Real-device testing has found every macOS bug the lab could not: mDNSResponder scoping, the own-IPv6 checksum, the link-liveness issue. Today the harness lives outside this repo as a large private bash kit. It runs as the developer, takes sudo for route/scutil/tcpdump, restores the machine (a dead-man timer, record-based rollback), drives a remote exit container, captures leaks and samples resources. It has grown into a second product, and its bugs cost whole device cycles. Examples: a guard bug voided every leak capture in one run; a truncated-file bug made valid captures read as invalid. Its tests rely on stubs that cannot reproduce root, routing or setuid behaviour.

R&D deliverables:
- a short design doc comparing the options (Go tool in this repo / Python / keep bash), with a recommendation
- what stays private: anything naming real servers stays outside the public repo, provided through config
- a prototype of the safety core and one check
- a migration plan

## Out of scope
Rewriting every check in this ticket.

## Acceptance
- [x] design doc with a recommendation, approved by the author
- [x] prototype of the safety core with real (non-stubbed) tests where the OS allows them
- [ ] the in-run self-test catches a broken capture within 10 s

## Notes
Per-round lessons from the kit work: stub-only tests gave false greens; bash `$BASHPID` and `set -u` pitfalls; mixing fixes with new checks in one round; long-lived agent contexts.
- Kit bugs found by cross-model analysis of device run 4 (examples of why the harness needs real tests):
  - pcaps were decoded to empty text (stderr dropped), so packet-count checks always saw zero and could never fail. The run-4 conclusions were confirmed only by re-reading the pcaps by hand.
  - log-line counts double-counted a file that is a prefix of another
  - a counter diff subtracted unrelated lines (the N12 checksum figure)
  - the route monitor missed events during a 12k-route burst

### Device checklist (the owner's first run)
This branch merges into `rewrite` only after these steps are run from a build of it and judged: the core's own rule (a core change merges after one device self-test passes) applies to its first merge; a core change they show is needed is a fix round of this ticket.

Before you start: run everything as yourself in one Terminal window, pasting each block as it is (devicetest asks for your password itself when it needs root), with no VPN and no thinkpol agent running, and Wi-Fi on. Don't pipe devicetest's output into another program: it keeps its own transcript (`harness.log`), and a pipe can keep Ctrl-C from reaching it. Each run has a dead-man that restores the Mac by itself if the run hangs or is killed: after 2 minutes for the self-test and 5 minutes for TP-096. In a restore result, the `left` and `failed` items say what differs or failed, each with what to do; the steps here already do it (a reboot, then `restore`), so act only through them, and note any item that asks for something else (stopping another app, say). `info` items need nothing. Never load, flush, disable or enable pf by hand (no item asks you to): when something isn't as expected, use [If something goes wrong](#if-something-goes-wrong).

#### Step 1: build the binaries
**Do**, in the Terminal window, from a checkout of this repository:
```sh
git fetch origin
git switch tp-082-device-harness
git pull
mkdir -p ~/devicetest-bin
go build -o ~/devicetest-bin/ ./lab/devicetest ./lab/devicetest/devicetest-root
```
**What happens**: two binaries go into `~/devicetest-bin` (outside `/tmp`, so they survive a reboot). `devicetest-root` must sit beside `devicetest`: sudo starts a checked copy of it. Nothing runs as root.

**Expect**: no output from `go build`.

#### Step 2: list the TP-096 plan
**Do**:
```sh
~/devicetest-bin/devicetest plans TP-096
```
**What happens**: it prints everything the run may do. Nothing is asked, nothing runs as root, nothing changes.

**Expect**: 2 steps, 9 root reads, one change (`load pf's main ruleset: "set skip on lo", then /etc/pf.conf`) with its undo, and a capture on your physical interface.

#### Step 3: the self-test
**Do**:
```sh
~/devicetest-bin/devicetest selftest
```
Type `yes`, then your password.

**What happens**: a root helper starts with its dead-man, records the Mac (pf, DNS) as the baseline, writes and removes one file of its own, checks a capture on Wi-Fi with two marker packets, then compares the Mac with the baseline. pf isn't changed.

**Expect**: `self-test ok in …` (under 10 s), then the last line `devicetest selftest recorded: 0 of 0 steps, selftest ok, restore CLEAN -> …/thinkpol-evidence/<date>-selftest`.
- If it says `SELF-TEST FAILED`, or the helper doesn't start and names `the baseline can't read …`: copy that line into your notes and skip to [step 9](#step-9-the-evidence). Nothing was changed.

#### Step 4: the TP-096 run
**Do**:
```sh
~/devicetest-bin/devicetest run TP-096
```
Type `yes`, then your password. If a `STOP:` line asks what to do, press Enter (it restores and ends the run).

**What happens**: the self-test again, then step 1 records pf's listings; step 2 loads `set skip on lo` before the stock rules, records the listings, undoes it (loads /etc/pf.conf), and records them again; then the restore compares the Mac with the baseline. The dead-man restores by itself after 5 minutes if the run hangs.

**Expect** one of:
- the last line `devicetest TP-096 recorded: 2 of 2 steps, selftest ok, restore CLEAN -> …`: skip to [step 7](#step-7-ctrl-c);
- on a Mac whose pfctl marks no skipped interface in its listing (the 2026-10-24 run's marked none): a `STOP:` line for the undo whose error says `pf listed no skipped interface even right after this run's load`, then, after Enter, a result with `"verdict": "LEFT"` and the last line `devicetest TP-096 recorded: 1 of 2 steps, selftest ok, restore LEFT -> …`. That is the expected answer there: go on to step 5.

Anything else that isn't CLEAN: go on to step 5 too.

#### Step 5: reboot (only if step 4 didn't end CLEAN)
**Do**: Apple menu → Restart.

**What happens**: the reboot clears whatever the run left in pf (pf's state lives in the kernel). The run stays pending on disk, and no run starts until step 6 closes it.

**Expect**: the Mac restarts.

#### Step 6: after the reboot, close step 4's run
**Do**, in a new Terminal window:
```sh
~/devicetest-bin/devicetest restore
```
Type your password.

**What happens**: it reopens the pending run, checks each change of the run's is gone with the old boot, and compares the Mac with the run's baseline. It changes nothing in this boot.

**Expect** one of:
- `"verdict": "RESET-BY-REBOOT"` and `devicetest restore: RESET-BY-REBOOT, run … closed: every change it made was undone or went with its boot; …`. (A `CLEAN` closes it too.)
- `"verdict": "NOTHING-TO-RESTORE"` and `devicetest restore: NOTHING-TO-RESTORE, no run was pending; nothing was compared`: step 4's run was closed already (after an `UNKNOWN`, its dead-man restored it later). Note it.

Either way, go on to step 7. Anything else: [If something goes wrong](#if-something-goes-wrong).

#### Step 7: Ctrl-C
**Do**, in the window you type in. If step 4 ended `restore CLEAN`:
```sh
~/devicetest-bin/devicetest run TP-096
```
Otherwise:
```sh
~/devicetest-bin/devicetest selftest
```
Type `yes`, then your password. As soon as the line `the helper is up: from now on Ctrl-C stops the run …` appears, press Ctrl-C twice in this same window. The self-test ends a second or two after that line, so press at once; for TP-096 you may wait for `step 1 stock`.

**What happens**: the run stops after the operation running now, undoes what it changed and compares the Mac with the baseline; the second Ctrl-C doesn't stop the restore.

**Expect**, within a second of the first Ctrl-C, the line `interrupt: stopping after the operation running now, then restoring`; after the second, `restoring, wait: a second Ctrl-C doesn't stop the restore`; then a last line ending `restore CLEAN -> …`.
- The last line (`devicetest selftest recorded: …` or `devicetest TP-096 recorded: …`) came before your first Ctrl-C: you were too late, and the Ctrl-C went to zsh. Run the same block again, pressing sooner.
- `interrupt:` but no `restoring, wait:` line: the run had ended before your second Ctrl-C. Note it; that's fine.
- A `SELF-TEST FAILED` line naming the decode (`tcpdump -n -A -r`) next to the `interrupt:` line: your Ctrl-C reached the decode, which says nothing about the capture. Note it; the last line then says `selftest FAILED, restore CLEAN`.
- No `interrupt:` line, though the last line came after your first Ctrl-C: the Ctrl-C didn't reach the run. Note it.

Anything but CLEAN: [If something goes wrong](#if-something-goes-wrong).

#### Step 8: a closed terminal
**Do**: open a new Terminal window (Cmd-N) and run:
```sh
~/devicetest-bin/devicetest selftest
```
Type `yes`, then your password, press Enter, and close the window at once (Cmd-W); confirm Terminate if Terminal asks. Wait 10 s, then in your first window run:
```sh
~/devicetest-bin/devicetest restore
```
Type your password.

**What happens**: closing the window ends the run's user side; the root helper sees its input end and restores by itself. The restore then finds nothing pending, or closes what was.

**Expect**: usually `"verdict": "NOTHING-TO-RESTORE"` and `devicetest restore: NOTHING-TO-RESTORE, no run was pending; nothing was compared`. If the restore ran only now: `"verdict": "CLEAN"` and `devicetest restore: CLEAN, run … restored; a new run may start`. Anything else: [If something goes wrong](#if-something-goes-wrong).

#### Step 9: the evidence
**Do**:
```sh
sudo ls /private/var/db/thinkpol-devicetest
ls -d /private/tmp/tpdt.*
```
**What happens**: the first lists root's state directory; the second looks for root copies left in the temporary directory.

**Expect**: `run-…` directories (the newest 10) and `devicetest.lock`, with no `active` and no `left`. The second prints `zsh: no matches found: /private/tmp/tpdt.*`, which is the good answer. If it lists directories, leave them (the next reboot removes them; don't delete them by hand) and note the names.

**Do**, to pack each evidence folder of the session:
```sh
cd ~/thinkpol-evidence && for f in "$(date +%F)"-*/; do zip -qr "${f%/}.zip" "$f"; done; ls ~/thinkpol-evidence/*.zip
```
**What happens**: one zip per folder of today's runs (a session that crossed midnight: zip the earlier date's folders the same way).

**Expect**: the zips' paths. Send them; an agent judges them. The tool says no PASS or FAIL.

#### If something goes wrong
A result's `left` and `failed` items say what to do; the steps below do it (a reboot, then `restore`). Never pfctl by hand: no item asks you to.
- F1. A restore says `LEFT` or `REBOOT`, or a restore fails: Apple menu → Restart.
- F2. After the reboot, in a new Terminal window:
  ```sh
  ~/devicetest-bin/devicetest restore
  ```
  Expect `RESET-BY-REBOOT` or `CLEAN`, or `NOTHING-TO-RESTORE` (the run was closed already), then continue with the step after the one that sent you here.
- F3. If F2 still says `LEFT` or `REBOOT`, or fails the same way: close the run by name, typing the run id F2 named in place of `RUN`:
  ```sh
  ~/devicetest-bin/devicetest restore -forget RUN
  ```
  Expect `FORGOTTEN` and what the journal and the comparison still say (never CLEAN; the next run may start). Note it and continue with the step after the one that sent you here.
- A run that prints nothing more for minutes: wait for its dead-man (2 minutes for the self-test, 5 for TP-096, then its restore), then go to F2 without rebooting.

## Review findings
Round 1 (2026-10-23): correctness (fix first), style (fix first), design (fix first), second opinion (fix first). The split is right and the tests are real; the core still has holes that leave the Mac changed under a CLEAN verdict, and every one costs a ticket and the owner's approval once `FROZEN` pins it, so all of them are fixed now.
- [x] R1.1 `devicetest restore` says CLEAN without comparing anything: `finish` removes `active` whatever the verdict (`restore.go` ~199), and `RestoreRun` with no `active` (or `Active()` failing) answers CLEAN "no unfinished run" (~261). A LEFT/REBOOT/undo-failed run then unblocks the next, which takes a dirty baseline; checklist step 5 expects CLEAN from exactly this. A non-CLEAN result stays pending (a `left` file naming the run); `startRun` refuses while it exists; `restore` reopens that run, takes a fresh after-restore snapshot, diffs it against the stored baseline, and clears `left` only on CLEAN; nothing to restore is its own verdict (not CLEAN); a failed `Active()` is an error. Tests for each; checklist step 5 updated.
- [x] R1.2 The journal: a torn last line is skipped but never cut off, so the next `O_APPEND` line merges into it and a later restore fails to parse it forever (`journal.go` ~134, ~151). Only the last line can be cut short of its newline: a complete line that doesn't parse is corruption (an error), a fragment without a newline is torn and is truncated (and synced) before anything is appended. `active` is written after `CreateJournal` has synced its header (`helper.go` ~198), so it never points at a run with no journal. Tests append after a torn tail and reopen.
- [x] R1.3 Captures: the pid is journaled only after the header wait (up to 5 s) and a `startTime` error is dropped (`capture.go` ~162, ~185; `action.go` ~168-177), so a helper killed in that window leaves a root tcpdump the undo treats as gone, under a CLEAN verdict, promiscuous until 200000 packets. Journal the pid and start time right after `Start` (a failed start-time read fails the action and kills the process); the live helper's undo stops what its table holds whatever the journal says; pass `-p`. The filter goes after `--` and one starting with `-` is refused (`-w/etc/pf.conf` today makes root's tcpdump overwrite that file, a change no journal knows). Tests: a helper killed between start and header leaves no tcpdump; a `-w…` filter is refused.
- [x] R1.4 The helper protocol can overwrite the baseline on disk: `OpSnapshot` takes any name (`helper.go` ~283, `snapshot.go` ~63), and the dead-man and `restore` read the baseline back from disk, so `00-baseline` taken while the skip is loaded makes the undo a no-op and the result CLEAN. Remove `OpSnapshot` (only a test uses it: send an allowed `OpRead`); snapshot files are written once (`O_EXCL`) under names only the core chooses.
- [x] R1.5 pf-main: `Prepend` accepts any pf.conf line, but the restore compares only the main rules, nat, skip, status and three anchors, so an `anchor`/`load anchor`/`table` line can survive a CLEAN. Restrict the action to `set skip on <ifname>` (all it is for). `Pre` also requires the current skip set to match the stock one, so the undo never drops a skip another app loaded. The comparison must not drop lines: `firewall.ListingLines` drops any line with `ALTQ`, and `pfAnchor` reads any `Invalid argument` stderr as an empty ruleset: compare raw lines (only header noise dropped) and treat only the missing-anchor answer as empty.
- [x] R1.6 The dead-man: `exists` reads any error but ENOENT as "the stop file is there", so one EMFILE/EIO disarms it (`deadman.go` ~110): only a successful stat counts. It watches the helper by pid alone (`proc.go` ~13, `helper.go` ~224) and SIGKILLs a bare pid (`deadman.go` ~132): use pid plus start time (`sameProcess`) for both. Its budget runs on the monotonic clock, which stops while a Mac sleeps: count the larger of monotonic and wall-clock elapsed, and say so in the doc.
- [x] R1.7 After a reboot, `/private/tmp` is empty, so `removeRootCopy`'s `Lstat` fails and a complete restore exits 1 `ok:false` (`launch.go` ~114-120, `restore.go` ~262): a missing root-copy directory is already gone. A helper refused before `finish` (lock held, unfinished run, bad flag) removes its root copy too. `root-restore` ignores SIGINT and SIGHUP like the helper and the dead-man (`main.go` ~48). `pfctl -e`'s result is checked and noted (`settle_darwin.go` ~77). When the dead-man restores after the helper took `99-after-restore`, its own snapshot is kept under its own name, not lost to EEXIST (`snapshot.go` ~47). Tests: a restore whose root copy is gone is CLEAN with exit 0.
- [x] R1.8 Plans are data, enforced: depguard in `strict` mode with allowlists (plans: `time` and `lab/devicetest/plan`; plan: `fmt`, `regexp`, `slices`, `strings`, `time`), and the plans aren't linked into the root modes (helper, dead-man, root-restore), so no plan `init` runs as root. A plan `UndoLast` with no change of its own before it is refused (it would undo the self-test's capture). Plans have one capture (the helper answers one request at a time, so two captures share the 10 s self-test serially), and the self-test loop is sequential.
- [x] R1.9 The user side when the helper is gone: `restore()` returns an empty `Result` and the terminal prints `THE MAC ISN'T AS IT WAS ()` (`run.go` ~142, `client.go` ~95): read the newest `restore/result-*.json` from the evidence (the dead-man's), else UNKNOWN with "run devicetest restore".
