## Goal
The device data plane runs on macOS with the same behaviour as on Linux.

## Scope
- utun via `wireguard-go/tun`.
- netcfg adapter for macOS: addresses, MTU, routes (route sockets via `golang.org/x/net/route`; `ifconfig`/`route` exec only as a documented fallback).
- Route-table enforcement parity with TP-018, including gateway change detection (Wi-Fi switches, sleep/wake).
- Runs as root through the CLI; installing as a service is TP-046.

The pure-Go group lookup reads `/etc/group` only: pass the `thinkpol` group's gid (`THINKPOL_API_GROUP=<gid>`).
**Done in TP-019 (2026-10-13), agent-tp-019.** Nothing here has run on a real network yet: every system call sits behind a small interface with a fake, and the device half is the checklist below. No test on this branch touches the host (verified after `make test` on a Mac: no utun created, no `RTF_PROTO2` route, no dynamic-store key, no `/var/run/thinkpol`).

*What exists (DESIGN.md "Route table on macOS", "DNS is routing", "Desktop client" updated):*
- **TUN** (`tun_darwin.go`): `wgtun.CreateTUN("utun", mtu)`; `tun.DefaultName` is per OS (`utun` on macOS: the kernel picks utunN). The agent goes by the TUN's own name once it exists (`runner.tun`: DNS binding, blobs, the OS resolver), on every OS.
- **netcfg adapter** (`netcfg_darwin.go`, `kernel_darwin.go`, `record_darwin.go`): routes over a `PF_ROUTE` socket with `golang.org/x/net/route` messages (as route(8) writes them: host routes without netmask, IPv6 link-local gateways with the zone embedded, interface routes with an `AF_LINK` gateway), RIB dumps by sysctl, addresses/MTU/flags by ioctl (`SIOCAIFADDR`, `SIOCAIFADDR_IN6`, `SIOCDIFADDR`, `SIOC[GS]IFFLAGS`, `SIOCSIFMTU`). One documented exec fallback: removing an IPv6 address (`/sbin/ifconfig <if> inet6 <addr> -alias`), since `SIOCDIFADDR_IN6`'s argument size isn't stable across releases. Owners: overlay and route table (a supervisor is Linux-only: `ErrUnsupported`). **Ownership needs both** `RTF_PROTO2` on the route **and** its destination in the owner's record (`/var/run/thinkpol/netcfg/<owner>.routes`, next to `<owner>.lock`, flocked): a real Mac showed another VPN client's routes carrying `RTF_PROTO1`, the kernel marks expiring clones with `RTF_PROTO3`, and clones inherit their parent's flags. The record is written ahead of every change, so a crash at any point leaves nothing unrecorded; clones (`RTF_WASCLONED`) and scoped routes (`RTF_IFSCOPE`) are never anyone's and never conflict. Metrics, tables, throw routes, policy rules and default routes are refused (`errors.ErrUnsupported`). A route that only moves (a new gateway or interface) is changed in place (`RTM_CHANGE`, falling back to delete and add), so traffic doesn't fall through meanwhile; a change of kind (into the utun ↔ rejected) is delete and add. A Close that fails still frees the owner's place (unlike Linux); what is left stays in the record for the next configurator. utun is point-to-point, so the adapter adds the overlay networks' routes into it itself (owned), unless the kernel already routes them there. `Survey` adds `Defaults` (unscoped default routes), `Routes` (foreign unscoped routes that can take traffic ahead of the tunnel) and `Held` (every unscoped identity no owner holds, whatever the route does); Linux leaves them empty. `netcfg.DefaultInterface(f)` asks the kernel for the default route's interface (`RTM_GET`, like `route -n get default`). Watch: a routing socket; relevant are interface and address messages and unscoped, non-cloned route changes but our own adds.
- **Route table** (`routetable/split.go`, `SplitRoutes`; Linux's layout is now `PolicyRouting`, `Config`/`Ahead` pick the OS's): IPv4 `0/1`+`128/1` into the utun (reject while it is down); IPv6 `::/2`×4 into the utun while it carries IPv6, reject `::/1`+`8000::/1` always behind (IPv6 stays blocked after a crash, as on Linux; IPv4 follows the physical default, D4); direct prefixes and endpoints via the family's default gateway, except inside on-link subnets and the OS's link-local/multicast/loopback ranges; the overlay never direct (its ULA /48 is carved out of a direct `fc00::/7`). **TunnelVision/LocalNet**: untrusted on-link subnets (same rule as Linux: inside `lists.Local()` ∩ direct) and foreign routes over tunneled destinations are **shadowed** by more specific routes into the utun covering what isn't direct, gateways excluded (they stay reachable on-link); no route of the layout ever takes an identity another route holds (`Held`): split routes, rejects and pieces covered by another VPN's `0/1`/`::/1` or someone's reject route are split into more specific halves instead, so applying never conflicts with what is there. Foreign host routes can't be outranked: counted in `RulesAhead` (health `policy_rules_ahead`). The Enforcer, its watcher and the engine's shrink/grow ordering are unchanged.
- **Socket binding** (`internal/dataplane/ifbind`, new, builds for Android): `SO_BINDTODEVICE` on Linux, `IP_BOUND_IF`/`IPV6_BOUND_IF` on macOS, an error elsewhere. `dns.BindToInterface` and `blobs.bindTo` use it (TP-017's darwin refusal is gone). `routetable.SocketControl()` on macOS binds links and the direct DNS upstream to the default route's interface, looked up per socket (a dead link is redialed after `DeadAfter`, so links follow a network change); no default route for the family → the socket fails to open.
- **DNS** (`dns/system_darwin.go`, `scutil_darwin.go`). Chosen: **configd's dynamic store through `/usr/sbin/scutil`** (pure Go). Every active network service's `State:/Network/Service/<id>/DNS` (and its `Setup:` key where DNS servers were set by hand, which wins over State) is overridden with the overlay resolver and the space's zone, marked `ThinkpolOverride`; the originals go into the store first (`State:/Network/thinkpol/DNS`, base64 JSON), which like the overrides lives until reboot; `RestoreSystem` at every start puts a crashed run's back; a 2 s check re-overrides what the system republishes (DHCP renew, new network, a new service), takes it as the new original and tells the resolver its new domestic upstream; restore never clobbers what the system published since. Fail closed: no active service → error; an original scutil can't re-create exactly (nested dictionaries, data) is left alone and reported; other software's supplemental resolvers (another VPN's split DNS, `/etc/resolver` files) → `dns_not_protected`. Rejected: `/etc/resolver/<zone>` alone (per-domain only: no default resolver, so R4 can't hold); `networksetup -setdnsservers` (persistent preferences: a crash leaves DNS broken across reboots, and needs a backup file on disk).
- **Agent**: device mode runs on macOS; server mode refuses before touching anything (`supported(mode)`). The node's start-time cleanups (`routetable.Clear`, `dns.RestoreSystem`) are package hooks the agent tests swap (`host_test.go` `TestMain`, real only under `THINKPOL_LAB`), and `cmd/thinkpol`'s `TestUpRefusesAnUnsupportedHost` no longer brings a device up on a Mac — both would have reached the real host now that macOS has adapters.
- **Local API**: default socket `/var/db/thinkpol-api/api.sock` (`/var/db` is root:wheel 0755 all the way up; `/var/run` is root:daemon 0775 and fails the parent check). Group names are also looked up in Directory Services (`dscl . -read /Groups/<name> PrimaryGroupID`) when `/etc/group` lacks them. `LOCAL_PEERCRED` now has a test on a real socket pair.

*Residual risks, honestly (macOS, route-table mode):*
- A foreign **host route** (`/32`, `/128`: a DHCP option-121 host route, a static one) over a tunneled destination wins; it is only counted (`policy_rules_ahead`). Blocking needs pf (TP-021, TP-048).
- **Interface-bound sockets** (apps and daemons using `IP_BOUND_IF`, scoped lookups) route by their interface's scoped routes, around the utun: as on Linux, the firewall's job (TP-021, TP-048).
- **Another VPN** with its own `0/1`+`128/1` (seen on a real Mac): ours go one level more specific (`/2`s) and win; with the overlay carrying IPv6 the reject behind IPv6 is then missing where the other VPN holds `::/1` (crash safety only). Its own interface routes are shadowed like any foreign route unless direct. Run the checklist with other VPNs off first, then optionally on.
- **Network change**: direct routes name the gateway, so a Wi-Fi switch changes them all (thousands with a country list) in place; if the kernel refuses `RTM_CHANGE` they are deleted and added, and direct destinations go into the utun for that moment (dropped, never leaked). Links redial within ~6 s + backoff.
- **After a crash** (kill -9): the utun and its routes go, IPv4 (overlay included — on Linux the overlay stays unreachable) follows the physical default; IPv6 stays rejected but for direct destinations; the DNS overrides stay (names don't resolve) until the next start or a reboot. `thinkpol up -connect=false` (then stop) clears both.
- Unverified on hardware (checklist step 15): `in6_aliasreq` layout (`SIOCAIFADDR_IN6` = 0x8080691a), routing-socket semantics for link-local gateways, deletes and `RTM_CHANGE`, the short `sockaddr_dl` (index only) as an interface route's gateway and how it dumps back, whether ICMP-redirect host routes (`RTF_DYNAMIC`, unscoped) can take tunneled destinations around the split routes, `DefaultInterface` (`RTM_GET`) under a routing-socket flood, whether scutil keeps every original intact, the cost of ~23k routes through a routing socket.

**Device checklist (for the owner; run as root on the Mac, other VPNs off).** Every step only changes what thinkpol owns; rollback is at the end. Record each step's result here.

0. *Prepare (read-only baseline).* `make build` → `bin/thinkpol`. A device state dir of a space that has a server with ingress and egress reachable from here: `sudo mkdir -p /var/lib/thinkpol && sudo chmod 700 /var/lib/thinkpol`, copy the device's `node.key`, `space.pub`, `map.bin` into it (root-owned). Baseline: `netstat -rn > /tmp/tp019-routes-before.txt; scutil --dns > /tmp/tp019-dns-before.txt; printf 'list State:/Network/Service/[^/]+/DNS\n' | scutil > /tmp/tp019-dnskeys-before.txt; ifconfig -l > /tmp/tp019-ifs-before.txt`. Expect `netstat -rn -f inet | grep -E '^(0/1|128.0/1) '` empty (no other VPN).
1. *Up.* `sudo ./bin/thinkpol up -state /var/lib/thinkpol -mode device -log-level debug`. Expect log lines `starting mode=device`, `map applied ... route_table_routes=<n>`, `route table applied routes=<n>`, `DNS: the system resolves through the node`; no `ErrConflict`.
2. *Interface.* `ifconfig -l` shows one new `utunN`; `ifconfig utunN` → `inet 100.64.x.y --> 100.64.x.y netmask 0xffc00000` (or the space's prefix), `inet6 fd…::y prefixlen 48`, `mtu 1328` (or the overlay MTU), flags `UP`.
3. *Routes.* `netstat -rn -f inet | grep utunN` → `0/1`, `128.0/1`, the overlay network (`100.64/10`), all with flag `2`; `netstat -rn -f inet6 | grep -E '^(::/1|8000::/1|::/2|4000::/2|8000::/2|c000::/2) '` → the rejects (`UGRS2`, gateway `::1`) and, if the overlay carries IPv6, the `/2`s on utunN. `route -n get 1.1.1.1` → `interface: utunN`; `route -n get <server endpoint IP>` → `gateway: <router>`, `interface: en0`; with the preset "all but domestic", `route -n get <a domestic IP>` → via the router. `netstat -rn | awk '$3 ~ /2/' | wc -l` ≈ the logged route count (plus the overlay's). `sudo cat /var/run/thinkpol/netcfg/route-table.routes | wc -l` matches.
4. *Overlay ping.* `ping -c3 <server overlay IPv4>` and, with IPv6 on, `ping6 -c3 <server overlay IPv6>` → replies. `./bin/thinkpol status` (as root) → connected, links up, `route_table` enforced, no health problems (or `dns_not_protected` only if another resolver is configured, see 6).
5. *Browse through the egress.* `curl -s https://ifconfig.me` (any IP echo) → the exit's public address, not the home one. `sudo ./bin/thinkpol rules preset all-but-domestic` then a domestic IP-echo site → the home address. Leak check: `sudo tcpdump -ni en0 -c 200 'not arp and not host <server endpoint IP> and not (udp port 67 or 68 or 5353)'` while loading a tunneled site → only direct destinations, nothing to the site.
6. *DNS / overlay names.* `scutil --dns | sed -n 1,15p` → resolver #1 `nameserver[0] : 100.64.x.y`, `search domain[0] : <space>.internal`; `printf 'show State:/Network/thinkpol/DNS\n' | scutil` → a dictionary with `Originals`. `dscacheutil -q host -a name <server>.<space>.internal` → its overlay address (N3); `dig +short example.com @100.64.x.y` → answers; `dig +short nonexistent.<space>.internal @100.64.x.y` → nothing (NXDOMAIN). `thinkpol status` shows no `dns_not_protected` unless `scutil --dns` lists another resolver with domains (another VPN, `/etc/resolver`).
7. *Sleep/wake.* Sleep the Mac for ≥ 1 min, wake. Within ~15 s: `thinkpol status` connected with links up; `netstat -rn -f inet | grep utunN` as in 3; log `route table applied` after the wake.
8. *Wi-Fi change.* Switch to another network (a phone hotspot). Within ~15 s: `route -n get <a direct IP>` → the new router; `route -n get 1.1.1.1` → utunN; links up again (`thinkpol status`); `curl -s https://ifconfig.me` → the exit; `scutil --dns` still the overlay resolver, and the new service's key has `ThinkpolOverride` (`printf 'show State:/Network/Service/<id>/DNS\n' | scutil`, id from `printf 'show State:/Network/Global/IPv4\n' | scutil`).
9. *A hostile route (optional).* `sudo route -n add -net 8.8.8.0/24 <router>` (stands in for a DHCP classless route) → within ~1 s `netstat -rn -f inet | grep '^8.8.8'` also shows `8.8.8/25` and `8.8.8.128/25` on utunN, `route -n get 8.8.8.8` → utunN. `sudo route -n add -host 9.9.9.9 <router>` → `thinkpol status` health `policy_rules_ahead`. Remove both: `sudo route -n delete -net 8.8.8.0/24; sudo route -n delete -host 9.9.9.9` → the shadows go.
10. *Disconnect/connect.* `sudo ./bin/thinkpol disconnect` → no flag-`2` routes, `scutil --dns` back to the baseline; `sudo ./bin/thinkpol connect` → as in 1–6.
11. *Down leaves nothing.* Ctrl-C the `up`. Then `netstat -rn > /tmp/tp019-routes-after.txt; diff /tmp/tp019-routes-before.txt /tmp/tp019-routes-after.txt` → only neighbour/cache entries differ, no flag-`2` route, no utunN; `scutil --dns` equals the baseline (`diff` modulo reach flags); `printf 'show State:/Network/thinkpol/DNS\n' | scutil` → `No such key`; `ls /var/run/thinkpol/netcfg` → lock files only, no `.routes`.
12. *Crash recovery.* Start as in 1, then `sudo pkill -9 -f 'thinkpol up'`. Expect: utunN gone, IPv4 browsing works without the tunnel, `curl -6` fails (IPv6 rejected), names don't resolve (overrides left). Then `sudo ./bin/thinkpol up -state /var/lib/thinkpol -mode device -connect=false` → logs show nothing failing; stop it (Ctrl-C) → step 11's checks pass.
13. *Local API.* `ls -ld /var/db/thinkpol-api` → `drwxr-x--- root thinkpol` with the group (`drwx------ root wheel` without); as a non-root member of `thinkpol`, `./bin/thinkpol status` works and `logs` is refused; a non-member gets "permission denied". (Make the group: `sudo dscl . -create /Groups/thinkpol PrimaryGroupID 790; sudo dscl . -append /Groups/thinkpol GroupMembership <user>`; remove: `sudo dscl . -delete /Groups/thinkpol`.)
14. *Timing.* With a country list ("all but domestic", ~23k prefixes): the `route table applied ... took=` of connect, a Wi-Fi change and disconnect.
15. *Kernel semantics (review suspicions; observe, don't guess).* (a) `netstat -rn -f inet | grep utunN` shows the utun routes with `utunN` as gateway (the index-only `sockaddr_dl` was taken) and a second `up` re-apply logs no route changes (it dumps back the same). (b) During a Wi-Fi change, `route -n get <direct IP>` never answers `utunN` (if it does, the kernel refused `RTM_CHANGE` and the routes were deleted and added) (run it in a loop: `while true; do route -n get <direct IP> | grep interface; sleep 0.2; done`). (c) `netstat -rn -f inet | awk '$3 ~ /D/'` (dynamic, from ICMP redirects): any entry for a tunneled destination outside the utun is a leak — record it. (d) Run `./bin/thinkpol status` repeatedly during step 1's connect (thousands of route messages): links come up without "no answer from the routing socket" in the log. (e) With another VPN up (optional): ours appear as `/2`s, `route -n get 1.1.1.1` → utunN.

*Rollback, at any point:* stop thinkpol (Ctrl-C, or `sudo pkill -TERM -f 'thinkpol up'`; if it hangs, `-9` then step 12's `-connect=false` start and stop, which removes what a crash left). By hand: every thinkpol route is listed in `/var/run/thinkpol/netcfg/{route-table,overlay}.routes` — `sudo route -n delete -net <prefix>` (IPv6: `sudo route -n delete -inet6 -net <prefix>`; `/32`, `/128`: `-host`); DNS: `printf 'show State:/Network/thinkpol/DNS\n' | scutil` shows the originals; turning Wi-Fi off and on makes the system republish its State keys (manual DNS: re-save the network settings), then `sudo scutil` → `remove State:/Network/thinkpol/DNS`, and `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`. **A reboot undoes everything** (routes, the utun, the dynamic store, `/var/run`).

## Review findings
Adversarial review (2026-10-13), orchestrator decision: fix every proven finding; suspicions go to the Device checklist.

- [x] 1 (high, fail-open) Split routes never consulted the identities others hold: another VPN's `/1`s (or a reject route on an endpoint) made every Apply conflict and roll back, leaving nothing in the utun — `Survey.Held` (every unscoped identity no owner holds, reject/local/loopback/redirect routes included); the layout covers a held prefix with more specific halves (`cover`), skips direct routes on held identities, and drops the reject behind IPv6 only where the utun's routes already win. `TestSplitRoutesNeverTakeAnIdentityAnotherRouteHolds`, Survey test checks `Held`.
- [x] 2 (medium) The write-ahead undo forgot a destination even when undoing its add failed: the route stayed tagged in the kernel but not in the record — such routes are pinned and stay recorded (`TestARouteUndoCantRemoveStaysRecorded`).
- [x] 3 (medium) Close kept the flock on error, so the next start got `ErrBusy` — Close always frees the owner's place; the record carries what is left to the next configurator (`TestAFailedCloseFreesTheOwnersPlace`; port contract documents the macOS difference).
- [x] 4 (medium) `DefaultInterface` matched replies on a constant sequence number, without the family: concurrent IPv4/IPv6 lookups could read each other's replies — a sequence number per lookup, the reply's family checked.
- [x] 5 (medium) A DNS original with values scutil can't pass back as one token (`Options : ndots:2 timeout:1`) was overridden for good — such originals are left alone and reported (`restorable`, `TestAnOriginalWithSpacesIsLeftAlone`); `ServerTimeout` is numeric.
- [x] 6 (low) Write-ahead could record a destination a foreign `RTF_PROTO2` route holds — confirmed fixed in bdea2ee (conflicts are checked before anything is recorded).
- [x] 7 (low) Delete-then-add left a window where the physical default carried traffic — routes that only move are changed in place (`RTM_CHANGE`, fallback delete and add; `TestMovedRoutesChangeInPlace`); a change of kind (TUN up ↔ down) stays delete and add, while the utun can't take traffic anyway.
- Suspicions (short `sockaddr_dl`, ICMP-redirect host routes, `RTM_GET` under a routing-socket flood) are Device checklist step 15.

### Round 2 (formal review, 2026-10-13)
Orchestrator decisions: fix every proven finding and the lower ones; the suspicion is verified on the device first.

- [ ] R2.1 Crash: overlay IPv4 and DNS leak out en0 (nothing rejects the overlay's IPv4 range after the utun dies; the DNS overrides point at the overlay address and survive). The utun gets the overlay networks' halves and a reject route for each whole overlay network stays behind, surviving a crash (Linux parity).
- [ ] R2.2 Shadows exclude every default gateway: a hostile DHCP gateway inside the overlay or on an untrusted public on-link subnet gets that address on-link in the clear. Exclude only gateways inside trusted on-link subnets (links bind to en0 and use its scoped routes); foreign host routes inside the overlay are an explicit overlay-hijack residual with its own health flag.
- [ ] R2.3 DNS fails open: an original scutil can't re-create is left un-overridden. Override anyway; restore such a key by removing it, so the system republishes it (fails closed meanwhile); documented.
- [ ] R2.4 DNS watch event-driven (`scutil` `n.add`/`n.watch`), polling kept as a backstop.
- [ ] R2.5 A host-wide agent lock before the start-time cleanups, so a second `thinkpol up` can't revert a running instance's DNS overrides and routes.
- [ ] R2.6 `DefaultInterface`: on ENOBUFS or a read timeout keep reading or ask again instead of failing.
- [ ] R2.7 Document the TunnelVision window on macOS (a new on-link subnet or classless route wins until the watcher re-applies; Linux fails closed).
- [ ] R2.8 Suspicion (device first): source-address interface selection may let sockets with an en0 source address bypass the split routes — Notes get the candidate fixes; Device checklist gets the test.
- [ ] R2.9 Device checklist additions (crash capture, source-bound sockets, DNS captures, overlay host route, group login, encrypted DNS/Private Relay baseline, rollback after crash + network change).
