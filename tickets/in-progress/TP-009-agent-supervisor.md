## Goal
A server node runs a supervisor and one worker process per space, each worker in its own network namespace, from the start, even while it serves one space.

## Scope
- Supervisor in the root namespace: reads which spaces the node serves, creates a network namespace and a veth pair per space, starts `thinkpol worker --space <id>` inside it, restarts crashed workers with backoff, stops everything cleanly.
- Entering the namespace safely from Go (locked OS thread before exec, or re-exec into the namespace).
- One Unix socket per worker for control and connection handoff (used by TP-010).
- Linux only (build tags).

## Notes
**Process model.**
- `supervisor.New(Options)` takes the node's supervisor role (`netcfg.New(OwnerSupervisor)` in the root namespace, held for life: a second supervisor gets `netcfg.ErrBusy`), sweeps a dead predecessor's leftovers (proto-85 routes, `tp-space*` links, its nftables tables), installs the isolation tables and sets up the cgroup parent (best-effort). `SetSpaces([]Space)` reconciles (serialized by `setMu`; waits for removed workers to be gone, then rebuilds the isolation tables for the current slots before any new veth carries a packet); `Workers()` → `WorkerInfo`; `Output(space)`; `Close()`. Linux `&& !android`; elsewhere `New` returns `ErrUnsupported`.
- A worker is `thinkpol worker -space <hex>` (hidden command), exec'd by default from `/proc/self/exe`, so it is always the supervisor's own build even after an update replaces the file (the IPC version in Init confirms it). `SysProcAttr`: `Cloneflags` NEWUSER|NEWNS|NEWPID|NEWNET|NEWIPC|NEWUTS|NEWCGROUP (the user namespace is created first, the rest inside it); `UidMappings`/`GidMappings` map container 0 → host `UIDBase+slot` (size 1, setgroups denied); `Credential{Uid:0,Gid:0}` so the child actually becomes the mapped namespace-root (it inherits host uid 0, outside the map, which would otherwise be the overflow uid); `AmbientCaps` SYS_ADMIN, NET_ADMIN, NET_RAW, NET_BIND_SERVICE carried across exec (a namespace-root whose host uid isn't 0 would otherwise lose all caps on exec, because the kernel's "root keeps caps" shortcut checks the global root uid); `Setsid`; `Pdeathsig` SIGKILL; `cmd.Dir` "/"; `UseCgroupFD` when a cgroup was made. Started from a goroutine locked to its OS thread for the process's life (the parent-death signal follows the forking thread), and the thread opens the worker's netns before `Wait` can reap it, so the pid can't be recycled under the open.
- No orphans, three ways: parent-death SIGKILL (re-armed by the worker on all its threads), control-socket EOF (the worker exits when the supervisor's end closes), and namespaces that live only as long as their worker (the supervisor holds the netns fd, no `/run/netns` bind). A SIGKILLed supervisor leaves only its nftables tables, which the next one replaces.
- Per incarnation: `ipc.NewPair` (control + data) → start → netns opened in the start goroutine → veth with the peer created directly in the netns (`PeerNamespace`) + permanent neighbours → Init → wait Ready (`ReadyTimeout` 10 s) → send Config, then push it again on change → serve. Stop: `KindStop`, `StopTimeout` (5 s), then SIGKILL. Cleanup order: process killed+reaped, space configurator closed, root veth deleted (takes the pair, addresses, neighbours and connected routes), netns fd closed; the per-space cgroup is removed when the space leaves. A crashed worker restarts in a fresh namespace.
- Backoff: `Initial` 500 ms, doubling to `Max` 30 s; a worker that ran `ResetAfter` (1 min) starts over. `WorkerInfo` reports `StartedAt`, `ReadyAt`, `NextStart`, `Starts`, `LastExit`, `OutputDropped`.
- Worker sandbox (`worker.Run`): confirms it is in a non-initial user namespace mapping 0→its host uid; `pivot_root`s into a fresh tmpfs holding only `/dev/{null,zero,urandom,net/tun}` (bind-mounted — mknod isn't allowed in a userns), a fresh `/proc` (its pid namespace) and read-only `/sys` (its net namespace), and empty `/run`+`/tmp`; makes `/run/thinkpol` for netcfg's lock dir; sets `RLIMIT_NPROC` from `PidsMax` as a cgroup fallback; sets `no_new_privs` and re-arms the parent-death signal on all threads (`syscall.AllThreadsSyscall`; per-thread settings, Go runs goroutines across threads); reads `/proc/self/status` back. The worker keeps its capabilities, confined to its own namespaces — the isolation is the user namespace, not cap-dropping. NET_ADMIN opens the namespace's own `/proc/sys/net`, so the data plane sets its own net sysctls.
- **Not done, with reason:** `close_range` of inherited fds (should-fix 7) — doing it from Go after the runtime has started would close the runtime's own epoll/eventfd/pipe descriptors; instead the worker relies on Go's O_CLOEXEC-by-default (only fds 3 and 4 are passed via `ExtraFiles`) and the probe asserts the worker has exactly two unix-socket fds (the control and data conns), so a leaked supervisor socket would be caught.

**IPC protocol** (`internal/agent/ipc`): two unnamed `AF_UNIX SOCK_SEQPACKET` pairs per worker incarnation — a control socket (`ControlFD` 3) and a data socket (`DataFD` 4). One packet = one message: `Kind` byte + payload, ≤ `MaxMessageSize` (64 KiB), ≤ `MaxFiles` (4) descriptors via `SCM_RIGHTS` (received close-on-exec). `Conn.Send`/`TrySend` are concurrency-safe; `Receive` is one reader; EOF = the other side is gone. `TrySend` (data socket) is non-blocking (`MSG_DONTWAIT`): `ErrFull` and a `Drops()` counter when the buffer is full, so a stuck worker can't block the supervisor. Control messages today: `Init` (JSON `ipc.Init{Version, Space, Interface, Addrs, Gateways, UID, GID, PidsMax}` — `DecodeInit` refuses a version mismatch), `Config` (opaque per-space bytes, or a sealed memfd for a large one), `Ready`, `Stop`. `KindDatagram` (data) and `KindStream` (control) are reserved for TP-010. An unknown kind after Init ends the worker (killed after `StopTimeout`, then restarted).

**Namespace and veth layout** (slot n, stable while a space is served, reused after): root `tp-space<n>` 169.254.100.(4n+1)/30 and fd74:7073:7061:n::1/64 (set directly with netlink, `IFA_F_NODAD`; the supervisor created the link, so everything on it is its own, and a shared root configurator would couple spaces); space `veth0` .(4n+2)/30 and ::2/64, `lo` up, default routes via the root end, through `netcfg.NewInNamespace(..., OwnerSupervisor)` (routes tagged 85, so the worker's `OwnerOverlay` can't clobber them). Permanent neighbour entries on both ends for each other, so real traffic needs no ARP/ND. Transit prefixes: `Options.TransitIPv4` (default 169.254.100.0/22: link-local, clear of 100.64.0.0/10 overlays and 169.254.169.254) and `TransitIPv6` (default fd74:7073:7061::/48); room for 256 workers by default, capped at 60000 (conntrack zone is 16-bit). Worker host uid/gid = `UIDBase+slot` (`DefaultUIDBase` 2 000 300 000, above SSSD's default id-map ceiling and below 2^31; no passwd entry needed).

**Root-namespace isolation** (`internal/agent/supervisor/isolation_linux.go`, google/nftables, pure Go; both tables rebuilt from the whole slot set in one atomic flush on every `SetSpaces`, deleted on Close): `table inet thinkpol-supervisor` with `ct_pre`/`ct_out` (prerouting/output, raw) setting a per-space conntrack zone (slot+1) so a space's connections never share conntrack with the root's zone 0; `antispoof_fwd`/`antispoof_in` (forward/input, priority -10) dropping a space's packets whose source isn't that slot's transit address, before any accept; `forward` (filter) dropping everything to/from `tp-space*`; `input` (filter) accepting only `ct state established,related` from a space (replies to what the root started, in the space's zone) and dropping the rest. `table arp thinkpol-supervisor-arp` drops a space's ARP. Together with the permanent neighbours, a space can't spoof a source into a root flow, forge a "related" error, cross to another space or the node, or flood the root neighbour table. TP-014's egress accepts go into `forward` ahead of the drops (regenerated by the same builder).

**Logs (S2)**: `internal/agent/logring.Ring`: bounded, line-oriented `io.Writer` using a ring with a head index and amortised compaction (lines cut at 4 KiB, oldest dropped, `Dropped()` counted; tested with a newline flood), safe for slog handlers and child output. Supervisor events → `Options.Log` (discarded by default); each space's worker output → its own ring. Nothing on disk.

**Lab change (sanctioned by the review):** lab nodes run with `security_opt: systempaths=unconfined` (lab/compose.go) and the harness skips its `/proc/sys/net` rw bind when `/proc/sys` is already writable (lab/lab.go). Docker's masked and read-only `/proc` submounts are locked, so a process in a child user namespace can't clear them to mount its own `/proc`; a real server's `/proc` is unmasked, so this only matches production in the throwaway lab nodes and grants no host access (nodes stay unprivileged). The worker also unmounts any `/proc`//`/sys` submounts it can before mounting fresh ones (a no-op where they're locked or absent).

**For downstream tickets:**
- **TP-010** (shared listener): the supervisor owns the listeners (root namespace). The data socket (`DataFD`, `TrySend`/`Drops`) carries `KindDatagram` both ways; the control socket carries `KindStream` (fd + consumed bytes). Worker side: extend `readControl`/add a data reader and hand `serve` a `net.PacketConn` over the data socket for `udp.Transport.ListenOn`; `Session.Config` already delivers config. The supervisor must route to the current incarnation (its sockets die on restart; look up per message, drop while a space restarts); fair share is charged after the worker accepts. Perf: batch with recvmmsg/sendmmsg and pooled buffers first; acceptance should include ≥ 50 Mbit/s through the shared listener on a lab node pinned to one CPU; connected-socket fast paths (SO_REUSEPORT + BPF) later.
- **TP-011** (`thinkpol up`): build `supervisor.New(Options{Log: slog over a logring.Ring, MemoryMax, PidsMax})` and `SetSpaces([]Space{ID, Config, Egress})` from the node's maps; `Config` is the worker's opaque per-space config (sent after Ready and on change; large ones as a sealed memfd — the worker reads config off the socket, never the state dir, which it can't as its own user). Replace `worker.Idle` in `cmd/thinkpol/worker.go` with the data plane, composed in `internal/agent` (e.g. `agent.RunDataPlane(ctx, SpaceConfig, Inbound)`) and adapted to IPC by `worker.Run`; device mode passes real dialers. Add a depguard rule: `internal/dataplane` must not import `internal/agent`. `Close` on SIGTERM leaves nothing behind (tested).
- **TP-014** (egress): generate the egress rules in the supervisor's `inet` table (it owns the table; `Egress{Uplink, IPv4, IPv6}` is already on `Space`): forward-accept `iifname tp-space<n> oifname <uplink>` after the anti-spoof, established replies back by conntrack zone, and masquerade only the transit ranges out the uplink. The worker SNATs the overlay range → its transit address inside its namespace (so the root only ever sees transit sources, which the anti-spoof already pins). Gotchas: other tables' drops still win (Docker/ufw FORWARD); enabling IPv6 forwarding needs `accept_ra=2` on an RA-configured uplink; forwarding inside the space's namespace is the worker's own sysctl. Keep spaces off 169.254.169.254 and the node's addresses (the input chain already drops those).
- **TP-040** (hosting grants): `SetSpaces` adds/removes guest workers without touching others. Caps = a token bucket at the supervisor's forwarding point (TP-010) plus veth tc limits for egress, plus the per-worker cgroup (`Options.MemoryMax`/`PidsMax`; `WorkerInfo.Link` is the per-slot veth).
- **TP-041** (telemetry): worker output already stays in memory per space (`Output`); a guest's worker output is readable by the node owner's supervisor, so keep anything space-private out of plain logs (sealed telemetry instead).
- **TP-022/TP-042** (CLI/admin): `Output(space)` and worker output can contain arbitrary bytes a space emits — renderers must sanitize control characters/escapes.
- **TP-044** (self-update): a re-exec of the supervisor restarts every worker (they die with it); treat the node as healthy only once every worker is `Ready` again.
- **TP-008** (TUN): a sandboxed worker can create a TUN, address it with netlink and bind :53; `/dev/net/tun` is in its minimal root and `netcfg.New(OwnerOverlay)` works (private `/run/thinkpol`).
- **Gotcha:** vishvananda/netlink 1.3 returns `ErrDumpInterrupted` when a dump races a change (e.g. veths going away with a dying netns); the supervisor's stale-link sweep and the tests retry. The behavioural link-netnsid escape op (raw `RTM_SETLINK` with `IFLA_TARGET_NETNSID`) returns ENODEV in the lab kernel rather than resolving the peer, so `TestNetnsidEscapeBlocked` gates on the structural proof (the netns is owned by the worker's own non-initial user namespace) and logs the behavioural op's result.
- Nits done: close the control socket before `awaitExit` on a protocol error; uid base above SSSD's default range; address arithmetic without math/big. Not done: close received fds asynchronously (low value; `CloseFiles` is synchronous); remove netcfg's lock file on Close (TP-007 leaves lock files in place on tmpfs by design).

## Review findings

Blockers:
- [x] B1 netnsid escape — the worker runs in a new user namespace (uid/gid maps; net, mount, pid, ipc, uts, cgroup inside it), so NET_ADMIN applies only to its own namespaces. `TestNetnsidEscapeBlocked` asserts the worker has NET_ADMIN in its ns but its netns is owned by its own non-initial user namespace, and the link-netnsid op is refused; `TestWorkersAreSandboxed` asserts the uid_map is non-initial. The raw-netnsid behavioural op is logged best-effort (ENODEV in the lab kernel; see Notes). No product weakening; the lab node spec change (systempaths=unconfined) is documented.
- [x] B2 conntrack bypass — per-space conntrack zones (`ct_pre`/`ct_out`) and per-space anti-spoof before any accept. `TestNoPacketCrossesSpaces` sends from each worker to the other space, both veths' root ends, the node's addresses and a source-spoofed datagram at the root end: nothing arrives; `TestNoPacketCrossesSpacesWithoutTable` deletes the tables and shows traffic then crosses (the control isn't vacuous).
- [x] B3 Close race — `Close` marks closed under `mu`, then takes `setMu` (waiting for an in-flight `SetSpaces`), stops all workers, and only then removes the tables, the cgroup and the netcfg lock. `SetSpaces` rechecks closed after acquiring `setMu`.
