## Goal
`TestResolvConfProblemReportsAWriteThatDoesNotSettle` (internal/dataplane/dns/resolvconf_settle_test.go) fails 15 of 30 under SIGSTOP freezes (seen during TP-220, 2026-11-16). Its writer rewrites the file every 50 ms against a 200 ms settle; during a stall one in-between file stays unchanged for 200 ms, so the node settles it and reports that file's server, as designed. Make the test not depend on timing.

## Scope
- Reproduce under the freezes, confirm the cause, and fix it in the test or the code.

## Notes
- **The cause: the tests, not the product.** Each of the four tests runs its writer in the test's own process and paused it for a set time (50 to 150 ms) between its writes, against a settle of 200 or 300 ms. A stall of the process (a loaded machine, a SIGSTOP) stops the writer and the watch together; when the process runs again the quiet timer has passed its deadline, the watch reads the file the writer left before the stall, finds it unchanged, and takes it: the file did stay the same for the settle, so the product settles it as doc.go says it should ("the file stays the same, with no change event, for 500 ms"). A real writer is another process, which a stall of the node doesn't stop: if it writes during the node's stall, the watch's read finds the file changed (or takes in the pending change event) and the settle goes on. Under SIGSTOP freezes of the test binary (gaps of 0 to 300 ms, stops of 50 to 700 ms, TP-217's and TP-220's method), 30 runs each on 8f21c8b7 (the package as on rewrite): ProblemReportsAWriteThatDoesNotSettle failed 21, each telling one or two of the writer's in-between files before its last (e.g. `told [[192.0.2.12] [192.0.2.20] [192.0.2.7 2001:db8::7]], want only [192.0.2.7 2001:db8::7]`); APollThatReadsAnInPlaceWriteEmptyWaits failed 4 (3 told the half-written file's `[192.0.2.7]` first, 1 not taken back with the whole file); AFileCreatedAtThePathSettles 5 and AFileCreatedDuringTheTakeOverSettles 4, all "not taken back": the new file settled empty during the stall and was renamed over, and the writer's line went into the replaced file.
- **The fix (tests only).** The four tests step their writer instead of racing it: they start with an hour's settle, so no stall can end one; after each write they wait until the watch has read the file as it now is and is settling it (`seenSettling`, which compares the watch's last read under its lock); once the writer is done, `settleSoon` shortens the settle to 100 ms and wakes the watch, which then takes the writer's whole file. What they assert is unchanged: no in-between file is taken or told, the whole file is, and (ProblemReports) Problem reports unprotected while each write goes on. They now also prove the watch read every in-between state (the empty file, each part), which the timed pauses only hoped for. The product, doc.go and RR5 are unchanged. The four take about 0.3 s each on a host (the three-subtest one 1.1 s), from 2 to 3 s.
- **Review round 1.** Stepping with an hour's settle lost the check that a change restarts the settle. decide now records when the quiet timer it resets fires (`foreignWrite.quietUntil`, set in `restartQuiet` at both resets: an internal field, no behaviour change), and seenSettling waits until the watch read the file as it is now and restarted its settle at or after the writer's step began; the stepped tests' cap is two hours, past the settle, so the cap doesn't measure the quiet from the settle's start. The poll tests (APollThatReadsAnInPlaceWriteEmptyWaits, AFileCreatedAtThePathSettles/poll) get no change events on any OS (`pollOnly`, as on a bind mount), so the poll-only restart is checked on Linux too. AnInPlaceWriterSettlesBeforeItIsRead and ARewriteOfTheSameContentKeepsTheSettleGoing are stepped the same way (the same-content one asserts each rewrite's change event restarts the settle though the read is unchanged). The take-back tests wait for the wanted tell (`toldAtLast`) instead of a 200 ms quiet spell, which a take-back's slow directory sync between its rename and its tell can outlast (AFileRenamedInRightAfterTheTakeOverIsTakenAtOnce, 7 of 20 in a lab container; ASlowWriterPastTheCapKeepsItsServers shared the helper).
- TP-220 left this test out of its scope as a separate flake (its Log, 2026-11-16). The same Log names three more settle tests in the same class under the freezes (TestResolvConfAPollThatReadsAnInPlaceWriteEmptyWaits, TestResolvConfAFileCreatedAtThePathSettles, TestResolvConfAFileCreatedDuringTheTakeOverSettles); worth checking whether one fix covers them.

## Review findings
Review round 1 (2026-11-18). The premise holds: the product was right, the tests' in-process writer froze with the watch. But stepping the tests with an hour's settle lost an oracle.
- [x] R1.1 (should-fix) APollThatReadsAnInPlaceWriteEmptyWaits and AFileCreatedAtThePathSettles/poll: nothing checks that a change seen only by the poll restarts the settle (the bind-mount case in doc.go). decide resetting the quiet timer only on a change event, or measuring the quiet from the first change rather than the last, survives all four tests. Record when the current settle ends (an internal field set where decide resets the quiet timer), have seenSettling return it, and assert after each writer step that it moved later; both mutations must then fail, on the poll path and the event path. Minimal product change: an internal field only, no behaviour change.
- [x] R1.2 (should-fix) ProblemReportsAWriteThatDoesNotSettle: the Problem check only restates seenSettling's condition, and no write now outlasts a settle, so the name is false. Add the R1.1 assertion to each step (a write that keeps changing is never taken and is reported unprotected), or rename it to what it proves.
- [x] R1.3 (ticket) AFileCreatedDuringTheTakeOverSettles: M1b never brought its cause back (0 of 30). Record a mutation that does fail it (e.g. the empty created file taken at once) with its result, and word the acceptance tick to what was shown.
- [x] R1.4 (nit) settleSoon's send on the wake channel can block without bound: a select with a 5 s deadline that fails the test.
- [x] R1.5 (should-fix) the same class remains in AnInPlaceWriterSettlesBeforeItIsRead (1 s settle, writer in the test process with 50 ms pauses) and ARewriteOfTheSameContentKeepsTheSettleGoing (a write every 100 ms): a stall over the settle under lab load flakes them the same way. Step the writer and assert the restart, keeping what each proves.
- [x] R1.6 (should-fix) TestResolvConfAFileRenamedInRightAfterTheTakeOverIsTakenAtOnce failed 7 of 20 in a lab container under load: test timing, not a product ordering bug (the take-back tells only after the rename and the directory fsync; the test's 200 ms quiet window can end during a slow fsync and see the old tell last). Drain the tells until the wanted servers arrive (5 s deadline), then assert nothing different follows within a short window.
