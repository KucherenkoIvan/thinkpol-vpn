## Goal
The client runs as a proper background service on macOS and Linux (Windows: TP-047).

## Scope
- `thinkpol service install | uninstall`: launchd daemon (macOS), systemd unit (Linux). Windows service: TP-047.
- Connect-on-boot toggle, default off.
- Permissions on the local API socket or pipe.

## Acceptance
- [ ] install, reboot, uninstall on macOS and Linux leave the system clean (Linux: lab TestServiceUnderSystemd; macOS: device checklist below, not run yet)
- [x] connect-on-boot is off by default after install (PRD D5); the toggle enables it (Linux: lab, across reboots; launchd: the plist as plutil reads it and the fake launchctl; macOS boot: checklist step 5)
- [ ] macOS: an agent the launchd daemon starts at boot before the system has loaded `/etc/pf.conf` doesn't run without its IPv6 guard: it waits for the `com.apple/*` hook (or retries until it is there) and stays fail-closed meanwhile; a boot test on a device shows it (fake pfctl tests pass; the device boot is checklist step 6, not run yet)
- [x] after a simulated crash the service restarts the agent and restores the persisted connect state; fail-closed during the gap is verified in TP-048 (Linux: lab, `systemctl kill -s KILL`, connected and disconnected; macOS: checklist step 3)

## Notes
- **From TP-022's review (acceptance items when this starts):**
  - Install with `THINKPOL_CONNECT=false` (PRD D5: connect-on-boot defaults off); the toggle sets it.
  - Persist the user's last requested connect state (or tell a boot from a restart), so a crash-restart neither silently drops a connected user (traffic leaks until the kill switch, TP-048) nor undoes an explicit disconnect.
  - Create the `thinkpol` group and add the installing user; run the service as root. Leave `/run/thinkpol-api` to the service (it creates it 0750 root:thinkpol and fixes a leftover of its own); don't use systemd's `RuntimeDirectory=` for it unless it ends up exactly that.
- **Crash posture (independent design review, 2026-10-13; TP-062).** The service must restart after a crash and the device must stay fail-closed until it does (default for the "everything" and "all but domestic" presets, opt-out; the guard is TP-048's). The persisted connect state above tells a crash from a deliberate disconnect, which still follows the kill-switch toggle (PRD D4). macOS must meet this too (launchd's restart and the pf guard).
- **Host lock needs a stable inode (TP-060).** The agent lock `/run/thinkpol/agent.lock` only works while its inode survives. Do NOT use `RuntimeDirectory=thinkpol`: systemd deletes the directory when the unit stops, including when the unit stops because it lost the lock, and a later agent would then lock a fresh inode while the old holder still runs. Create `/run/thinkpol` yourself (the agent does, root 0700), or set `RuntimeDirectoryPreserve=yes`.
- **pf boot race (DESIGN, "The leak guard on macOS").** The guard's anchor hangs under Apple's `anchor "com.apple/*"` hook from `/etc/pf.conf`. An agent started at boot before the system loads that file finds no hook; DESIGN hands this race to this ticket.

- **What was built (TP-046).** With `-keep-connect` (THINKPOL_KEEP_CONNECT, which the service sets), the boot's connect choice is recorded next to the host lock (`connect`, stamped with the boot session): the first start of a boot follows `THINKPOL_CONNECT` (connect-on-boot) and records it, each local API Connect/Disconnect is recorded before it is acted on, and a later start in the same boot follows the record (package agent, "A device's connection"). A node run by hand, without it, starts as its flags say. `thinkpol service install|uninstall|connect-on-boot` (package agent/service: the unit and the plist, why each line is there, what uninstall leaves). Early in a boot (5 minutes) a missing pf hook is retried, not terminal (package firewall, "macOS: a pf anchor"). The lab can run systemd as a node's PID 1 (lab/README.md).
- **Device checklist (macOS), record, don't judge.** Run on the Mac from a checkout of this branch, as yourself in a terminal; `sudo` where shown. Each step saves files into an evidence directory outside the repository (they hold your node's ids; don't commit them); an agent reads them afterwards. `thinkpol diag` (TP-091) isn't there yet, so the steps save `status`, `logs`, `launchctl print` and pfctl listings instead. To undo at any point: `sudo /usr/local/bin/thinkpol service uninstall`.
  0. Prerequisites: the node's state directory at `/private/var/lib/thinkpol` (`node.key`, `space.pub`, `map.bin`) as for earlier device runs; `make build`; `mkdir -p ~/tp046-evidence; E=~/tp046-evidence`.
  1. Install: `sudo ./bin/thinkpol service install 2>&1 | tee $E/01-install.txt`; then `ls -l /usr/local/bin/thinkpol /Library/LaunchDaemons/org.thinkpol.agent.plist > $E/01-files.txt 2>&1; plutil -p /Library/LaunchDaemons/org.thinkpol.agent.plist >> $E/01-files.txt; dscl . -read /Groups/thinkpol >> $E/01-files.txt 2>&1; thinkpol service connect-on-boot > $E/01-cob.txt 2>&1; sleep 5; sudo launchctl print system/org.thinkpol.agent > $E/01-launchctl.txt 2>&1; sudo thinkpol status > $E/01-status.txt 2>&1`. If install refuses (for example a `/usr/local/bin` others can write to), save its output and stop.
  2. The group from your account, before and after a new login: `thinkpol status > $E/02-status-user.txt 2>&1`; log out and in; `thinkpol status > $E/02-status-user-relogin.txt 2>&1`.
  3. A crash while connected, then while disconnected: `sudo thinkpol connect > $E/03-connect.txt 2>&1; date > $E/03-crash.txt; sudo pkill -KILL -x thinkpol; sleep 15; sudo launchctl print system/org.thinkpol.agent > $E/03-launchctl.txt 2>&1; sudo thinkpol status > $E/03-status.txt 2>&1; sudo thinkpol logs -n 300 > $E/03-logs.txt 2>&1`; then `sudo thinkpol disconnect > $E/03-disconnect.txt 2>&1; sudo pkill -KILL -x thinkpol; sleep 15; sudo thinkpol status > $E/03-status-after-disconnect.txt 2>&1`.
  4. Connect, then reboot with connect-on-boot off: `sudo thinkpol connect > $E/04-connect.txt 2>&1`; reboot.
  5. After the login: `sysctl kern.boottime > $E/05-boot.txt; date >> $E/05-boot.txt; sudo launchctl print system/org.thinkpol.agent > $E/05-launchctl.txt 2>&1; sudo thinkpol status > $E/05-status.txt 2>&1; sudo thinkpol logs -n 300 > $E/05-logs.txt 2>&1`.
  6. The boot race: `sudo thinkpol service connect-on-boot on 2>&1 | tee $E/06-cob.txt`; reboot; right after the login, the same reads as step 5 into `07-*` files, plus `sudo pfctl -s rules > $E/07-pf-main.txt 2>&1; sudo pfctl -a com.apple/000.thinkpol -s rules > $E/07-pf-anchor.txt 2>&1; sudo pfctl -s info > $E/07-pf-info.txt 2>&1`. The log keeps one process's lines only: if launchd restarted the agent during the boot, `launchctl print` (runs, last exit) is what tells.
  7. Uninstall: `sudo /usr/local/bin/thinkpol service uninstall > $E/08-uninstall.txt 2>&1`; then `ls -la /usr/local/bin/thinkpol /Library/LaunchDaemons/org.thinkpol.agent.plist /private/var/db/thinkpol /private/var/db/thinkpol-api > $E/08-files.txt 2>&1; sudo launchctl print system/org.thinkpol.agent > $E/08-launchctl.txt 2>&1; dscl . -read /Groups/thinkpol > $E/08-group.txt 2>&1; sudo pfctl -a com.apple/000.thinkpol -s rules > $E/08-pf-anchor.txt 2>&1; sudo pfctl -s References > $E/08-pf-refs.txt 2>&1; ifconfig > $E/08-ifconfig.txt; netstat -rn > $E/08-routes.txt; scutil --dns > $E/08-dns.txt`.
  8. Reboot once more; after the login, step 7's reads (not the uninstall) into `09-*` files.
