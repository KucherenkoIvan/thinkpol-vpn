## Goal
The device data plane runs on macOS with the same behaviour as on Linux.

## Scope
- utun via `wireguard-go/tun`.
- netcfg adapter for macOS: addresses, MTU, routes (route sockets via `golang.org/x/net/route`; `ifconfig`/`route` exec only as a documented fallback).
- Route-table enforcement parity with TP-018, including gateway change detection (Wi-Fi switches, sleep/wake).
- Runs as root through the CLI; installing as a service is TP-046.

- [x] everything in Scope is implemented behind small OS interfaces, builds for darwin (`make lint`: vet + golangci-lint for darwin/linux/windows, Android build, no cgo) and is unit-tested with fakes that touch no system state (`make test` on a Mac): utun (`tun_darwin.go`), the netcfg adapter (`netcfg_darwin_test.go`: apply/close back to the snapshot, re-apply is a no-op, foreign and other owners' routes never touched, crash takeover, a failed Apply leaves nothing, record written ahead, recreated utun, refused metrics/tables/throws/rules; `kernel_darwin_test.go`: routing messages round-trip, ioctl argument sizes), route-table layout (`split_test.go`: home network, IPv6 off, TUN down, everything direct, hostile network shadowing), socket binding (`ifbind_darwin_test.go`, `control_darwin_test.go`: `IP_BOUND_IF` set on real sockets, nothing sent), DNS (`system_darwin_test.go`, `scutil_darwin_test.go`), local API (`peercred_darwin_test.go`: `LOCAL_PEERCRED` on a real Unix socket pair) — see Notes

macOS state paths (round 4: every default names the real path, since `/var`, `/etc`, `/tmp` are symlinks into `/private` and the trusted walk refuses them): state directory `/private/var/lib/thinkpol` (`agent.DefaultStateDir`, per OS; Linux keeps `/var/lib/thinkpol`); agent lock `/private/var/db/thinkpol/agent.lock`; netcfg owner locks and route records `/private/var/db/thinkpol/netcfg/{overlay,route-table}.{lock,routes}`; local API `/private/var/db/thinkpol-api/api.sock` (beside `/private/var/db/thinkpol`, not in it: that one is 0700 and the API group must reach the socket); nothing under `/var/run/thinkpol` any more. `TestTheDefaultPathsPassTheTrustedWalk` and `TestTheDefaultSocketsParentPassesTheParentCheck` check them on the Mac, read-only. Read by the OS's own rules, not our walk, and left as they are: `/etc/resolver` (other software's supplemental resolvers), `/etc/group` (the standard library's group lookup).

*What exists (DESIGN.md "Route table on macOS", "DNS is routing", "Desktop client" updated):*
- **TUN** (`tun_darwin.go`): `wgtun.CreateTUN("utun", mtu)`; `tun.DefaultName` is per OS (`utun` on macOS: the kernel picks utunN). The agent goes by the TUN's own name once it exists (`runner.tun`: DNS binding, blobs, the OS resolver), on every OS.
- **netcfg adapter** (`netcfg_darwin.go`, `kernel_darwin.go`, `record_darwin.go`): routes over a `PF_ROUTE` socket with `golang.org/x/net/route` messages (as route(8) writes them: host routes without netmask, IPv6 link-local gateways with the zone embedded, interface routes with an `AF_LINK` gateway), RIB dumps by sysctl, addresses/MTU/flags by ioctl (`SIOCAIFADDR`, `SIOCAIFADDR_IN6`, `SIOCDIFADDR`, `SIOC[GS]IFFLAGS`, `SIOCSIFMTU`). One documented exec fallback: removing an IPv6 address (`/sbin/ifconfig <if> inet6 <addr> -alias`), since `SIOCDIFADDR_IN6`'s argument size isn't stable across releases. Owners: overlay and route table (a supervisor is Linux-only: `ErrUnsupported`). **Ownership needs both** `RTF_PROTO2` on the route **and** its destination in the owner's record (`/private/var/db/thinkpol/netcfg/<owner>.routes`, next to `<owner>.lock`, flocked; stamped with the boot session, round 3): a real Mac showed another VPN client's routes carrying `RTF_PROTO1`, the kernel marks expiring clones with `RTF_PROTO3`, and clones inherit their parent's flags. The record is written ahead of every change, so a crash at any point leaves nothing unrecorded; clones (`RTF_WASCLONED`) and scoped routes (`RTF_IFSCOPE`) are never anyone's and never conflict. Metrics, tables, throw routes, policy rules and default routes are refused (`errors.ErrUnsupported`). A route that only moves (a new gateway or interface) is changed in place (`RTM_CHANGE`, falling back to delete and add), so traffic doesn't fall through meanwhile; a change of kind (into the utun ↔ rejected) is delete and add. A Close that fails still frees the owner's place (unlike Linux); what is left stays in the record for the next configurator. utun is point-to-point, so the adapter adds the overlay networks' routes into it itself, as each network's two halves (`netcfg.ConnectedRoutes`, owned), unless the kernel already routes the network there. `Survey` adds `Defaults` (unscoped default routes), `Routes` (foreign unscoped routes that can take traffic ahead of the tunnel) and `Held` (every unscoped identity no owner holds, whatever the route does); Linux leaves them empty. `netcfg.DefaultInterface(f)` asks the kernel for the default route's interface (`RTM_GET`, like `route -n get default`). Watch: a routing socket; relevant are interface and address messages and unscoped, non-cloned route changes but our own adds.
- **Route table** (`routetable/split.go`, `SplitRoutes`; Linux's layout is now `PolicyRouting`, `Config`/`Ahead` pick the OS's): IPv4 `0/1`+`128/1` into the utun (reject while it is down); IPv6 `::/2`×4 into the utun while it carries IPv6, reject `::/1`+`8000::/1` always behind (IPv6 stays blocked after a crash, as on Linux; IPv4 follows the physical default, D4); direct prefixes and endpoints via the family's default gateway, except inside on-link subnets and the OS's link-local/multicast/loopback ranges; the overlay never direct (its ULA /48 is carved out of a direct `fc00::/7`), and a reject route for each whole overlay network behind the overlay's halves, outliving the utun (round 2). **TunnelVision/LocalNet**: untrusted on-link subnets (same rule as Linux: inside `lists.Local()` ∩ direct) and foreign routes over tunneled destinations are **shadowed** by more specific routes into the utun covering what isn't direct, a default gateway excluded only inside a trusted on-link subnet (round 2); no route of the layout ever takes an identity another route holds (`Held`): split routes, rejects and pieces covered by another VPN's `0/1`/`::/1` or someone's reject route are split into more specific halves instead, so applying never conflicts with what is there. Foreign host routes can't be outranked: counted in `RulesAhead` (health `policy_rules_ahead`), or, on overlay addresses, in `OverlayAhead` (health `overlay_routes_ahead`, down; counter `route_table.overlay_routes_ahead`). The Enforcer, its watcher and the engine's shrink/grow ordering are unchanged.
- **Socket binding** (`internal/dataplane/ifbind`, new, builds for Android): `SO_BINDTODEVICE` on Linux, `IP_BOUND_IF`/`IPV6_BOUND_IF` on macOS, an error elsewhere. `dns.BindToInterface` and `blobs.bindTo` use it (TP-017's darwin refusal is gone). `routetable.SocketControl()` on macOS binds links and the direct DNS upstream to the default route's interface, looked up per socket (a dead link is redialed after `DeadAfter`, so links follow a network change); no default route for the family → the socket fails to open.
- **DNS** (`dns/system_darwin.go`, `scutil_darwin.go`). Chosen: **configd's dynamic store through `/usr/sbin/scutil`** (pure Go). Every active network service's `State:/Network/Service/<id>/DNS` (and its `Setup:` key where DNS servers were set by hand, which wins over State) is overridden with the overlay resolver and the space's zone, marked `ThinkpolOverride`; the originals go into the store first (`State:/Network/thinkpol/DNS`, base64 JSON), which like the overrides lives until reboot; `RestoreSystem` at every start puts a crashed run's back; configd's notifications (a long-lived `scutil` `n.add … pattern` + `n.watch`; 30 s backstop, 2 s polling when watching fails) re-override what the system republishes (DHCP renew, new network, a new service), takes it as the new original and tells the resolver its new domestic upstream; restore never clobbers what the system published since. Fail closed: no active service → error; an original scutil can't re-create exactly (nested dictionaries, data, values with spaces) is overridden all the same and put back by removing the key (the system republishes State: at the next renewal or network change, Setup: when settings are saved or at reboot; no DNS meanwhile, never a leak); other software's supplemental resolvers (another VPN's split DNS, `/etc/resolver` files) → `dns_not_protected`. Rejected: `/etc/resolver/<zone>` alone (per-domain only: no default resolver, so R4 can't hold); `networksetup -setdnsservers` (persistent preferences: a crash leaves DNS broken across reboots, and needs a backup file on disk).
- **Agent**: device mode runs on macOS; server mode refuses before touching anything (`supported(mode)`). One agent per Mac: `/private/var/db/thinkpol/agent.lock` (flock, TP-060's lock in `Adapters`) is taken before the start-time cleanups, so a second `thinkpol up` can't undo a running agent's routes and DNS (round 2). The node's start-time cleanups (`routetable.Clear`, `dns.RestoreSystem`) are package hooks the agent tests swap (`host_test.go` `TestMain`, real only under `THINKPOL_LAB`), and `cmd/thinkpol`'s `TestUpRefusesAnUnsupportedHost` no longer brings a device up on a Mac — both would have reached the real host now that macOS has adapters.
- **Local API**: default socket `/private/var/db/thinkpol-api/api.sock` (`/private/var/db` is root:wheel 0755 all the way up; `/var/run` is root:daemon 0775 and fails the parent check). Group names are also looked up in Directory Services (`dscl . -read /Groups/<name> PrimaryGroupID`) when `/etc/group` lacks them. `LOCAL_PEERCRED` now has a test on a real socket pair.

*Residual risks, honestly (macOS, route-table mode):*
- A foreign **host route** (`/32`, `/128`: a DHCP option-121 host route, a static one) over a tunneled destination wins; it is only counted (`policy_rules_ahead`). Blocking needs pf (TP-021, TP-048).
- **Interface-bound sockets** (apps and daemons using `IP_BOUND_IF`, scoped lookups) route by their interface's scoped routes, around the utun: as on Linux, the firewall's job (TP-021, TP-048).
- **Another VPN** with its own `0/1`+`128/1` (seen on a real Mac): ours go one level more specific (`/2`s) and win; with the overlay carrying IPv6 the reject behind IPv6 is then missing where the other VPN holds `::/1` (crash safety only). Its own interface routes are shadowed like any foreign route unless direct. Run the checklist with other VPNs off first, then optionally on.
- **Network change**: direct routes name the gateway, so a Wi-Fi switch changes them all (thousands with a country list) in place; if the kernel refuses `RTM_CHANGE` they are deleted and added, and direct destinations go into the utun for that moment (dropped, never leaked). Links redial within ~6 s + backoff.
- **After a crash** (kill -9): the utun and its routes go; IPv4 outside the overlay follows the physical default (D4); the overlay's networks stay rejected (so the DNS overrides, which point at the overlay address, resolve nothing rather than leak); IPv6 stays rejected but for direct destinations. `thinkpol up -connect=false` (then stop) clears routes and DNS. After a crash and a network change, direct routes point at the old gateway until then (or a reboot).
- **TunnelVision window**: a new on-link subnet or classless route a network hands out wins until the watcher re-applies (debounced after the routing socket's event, ~200 ms); Linux fails closed here.
- **Untrusted gateway**: on a network whose gateway lies on an untrusted public subnet or in the overlay's range, direct destinations go into the utun (dropped) — fail closed, like Linux's cost for public on-link LANs.
- **Suspicion, device first (round 2, R2.8)**: macOS may pick a route by a socket's source address (scoped routing): a socket with an en0 source address (connections opened before `up`, WebRTC host candidates, `curl --interface <en0 IP>`) might bypass the split routes. Checklist step 16. Candidate fixes if it does: scoped reject routes `0/1`+`128/1` (and `::/1`+`8000::/1`) with `RTF_IFSCOPE` on the physical interface, plus scoped routes for the endpoints and direct prefixes (the links bind to it and must keep working); or pf in TP-048.
- Unverified on hardware (checklist step 15): `in6_aliasreq` layout (`SIOCAIFADDR_IN6` = 0x8080691a), routing-socket semantics for link-local gateways, deletes and `RTM_CHANGE`, the short `sockaddr_dl` (index only) as an interface route's gateway and how it dumps back, whether ICMP-redirect host routes (`RTF_DYNAMIC`, unscoped) can take tunneled destinations around the split routes, `DefaultInterface` (`RTM_GET`) under a routing-socket flood, whether scutil keeps every original intact, the cost of ~23k routes through a routing socket.

**DNS on macOS (round 6).** The approach was chosen with cross-model research (Grok) into how VPN clients without a Network Extension do it: Tailscale's tailscaled, wg-quick, Tunnelblick, OpenVPN 3 and its dns-updown, vpnc-script, ZeroTier, and configd's and mDNSResponder's public source. - **The resolver is a network service of the node's own.** `State:/Network/Service/8E3C1F52-6B0D-4E7A-9C25-0D4B7A61F3E9/DNS` holds `ServerAddresses` (the node's overlay addresses), `SupplementalMatchDomains` = one empty string, `SearchOrder` 100000 and the `ThinkpolOverride` mark.
  - configd turns an empty supplemental domain into an additional default resolver. It is unscoped, and it is asked before the services' own, whose default order is 200000.
  - It has no IPv4 or IPv6 entity on purpose: an entity's `InterfaceName` is what makes a resolver scoped.
  - Tailscale's tailscaled publishes the same key.
  - Expected in `scutil --dns`: nameserver A, flags `Supplemental`, `order : 100000`, and no `if_index` line.
- **Reflection stays.** An unscoped query follows `A A UH utunN` into the utun, and the router hands it back.
- **Fail-closed overrides stay.** Every active service's `State:` DNS is still overridden with the resolver, so the services' own resolvers lead nowhere else. Those are asked after the node's, on failover, or for questions scoped to an interface; an en0-scoped send to A fails rather than reaching the ISP.
- **`Setup:` keys are no longer written.** They are configd's copy of the network preferences, and every reviewer and client source treats them as persistent. scutil writes the dynamic store only, which configd rebuilds at boot (an inference; check 7 below confirms it). A `Setup:` override an earlier version left in this boot is put back from the backup.
  - A service with DNS set by hand keeps its servers as a fallback, which is `dns_not_protected`.
  - So is another program's default resolver (its own empty supplemental domain), which may come first.
- **The resolver answers NXDOMAIN for `resolver.arpa`**, so the OS never discovers an encrypted resolver to upgrade to (DDR).
- **Leaks this can't close** (residual risks):
  - questions scoped to an interface still go to that interface's resolver (overridden, so to A, unreachable from en0: they fail);
  - iCloud Private Relay, Limit IP Address Tracking and encrypted-DNS profiles bypass the system resolver;

- **Fallback, not built:** if the device still shows an `if_index` on the order-100000 resolver, try a synthetic `IPv4` entity with `InterfaceName = utunN` and `OverridePrimary = 1` (vpnc-script's full-tunnel shape; `Router` unset or `127.0.0.1`, as ZeroTier does).
