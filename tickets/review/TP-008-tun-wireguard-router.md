## Goal
Packets written to the overlay interface reach the right peer through WireGuard and the path layer, and back.

## Scope
- TUN via `wireguard-go/tun` (Linux now).
- Router reading the TUN and dispatching to WireGuard devices through virtual `tun.Device`s, structured for one WireGuard device per egress (only the overlay device for now).
- WireGuard devices configured from the node's map section: peers, allowed IPs = overlay addresses, dual-stack.
- No WireGuard UDP socket is ever opened: the Bind is the path layer.

## Acceptance
- [x] two nodes in separate namespaces ping each other over overlay IPv4 and IPv6 — `TestNamespacesPingOverTheOverlay` (`internal/dataplane/engine_lab_test.go`, `make lab-gotest PKG=./internal/dataplane/`): device-a, server-1 and device-b each in a network namespace with a real TUN (`tun.CreateInNamespace`) configured by `netcfg.NewInNamespace(…, OwnerOverlay)` (addresses /16 and /48, MTU 1328), links over real udp sockets (device-a over IPv4, device-b over IPv6 loopback); the kernel's `ping` and `ping -6` succeed a↔server-1 directly and a↔b through server-1 as relay (server-1's `Forwarded` > 0, device-a's first hop to b is server-1); closing an engine removes its TUN. In process the same M0 topology runs on the memory transport, datagram and stream (`TestDevicesReachEachOtherDirectlyAndThroughARelay`: ping and UDP both families, both directions)
- [x] the router is ready for several WireGuard devices (test with two dummy egress devices) — `TestRoutesEachDestinationToItsEgress` (two egresses: overlay peers first, then rules by longest prefix, block, no route, an overlay address without a peer never falls through to the exit's default), `TestAFullQueueDropsInsteadOfBlocking`; and with two real WireGuard devices on one node: `wg.TestTwoDevicesBehindOneRouter` (overlay device with a device peer, an egress device whose exit has `0.0.0.0/0` + `::/0`, both Binds set in one `Node.SetPeers`)

## Notes
- From TP-003's review: `netmap`'s reader (`(*Map).Open`) checks only that a section is well formed. It accepts what only `netmap.Build` rejects: repeated or overlapping overlay addresses, addresses outside the overlay, empty `Paths`, `NextHops` or `Endpoints`, invalid (zero) `netip.AddrPort`s, and routing loops across several nodes. Don't assume them away: never configure overlapping WireGuard allowed IPs (refuse a peer whose addresses collide with another peer's or the node's own, or fall outside the overlay), and tolerate peers without usable paths.
- From TP-006 (path layer API in its ticket's Notes): one `path.NewNode` per space worker with `Options.Space` set, `Update(dataplane.PathConfigFrom(section, registry).Table)` on each map, `Serve(name, listener)` per listener; one `NewBind()` per WireGuard device, all devices' peers set in one `Node.SetPeers` call so a peer can move between devices. A peer key lives in exactly one device: a chain's exit is a peer of that chain's device only. `Release` a Bind with its device.
- WireGuard peers get `endpoint=<node id hex>`, never a UDP address; no `listen_port`; never `fwmark` (the Bind's `SetMark` refuses it, so `Up` fails loudly).
- MTU: `path.MessageBudget(t, shaping, maxUnit)` per link (maxUnit = path MTU less IP and UDP headers; it applies `transport.MaxPacket` and the path header); the TUN MTU is the minimum over the node's links less 32 (WireGuard's data overhead): 1328 for a 1500-byte IPv6 path over unshaped udp. Refuse IPv6 on the overlay when that is below 1280, and surface it in status.
- **From TP-027:** fill `DialConfig.Shaping` / `PeerLink.Shaping` with `transport.ParseShaping(endpoint.Shaping)` / `(inbound.Shaping)` before `CheckEndpoint` / `CheckInbound`. udp's overhead is now 74 bytes (not 72): TUN MTU on a 1500-byte IPv6 path over unshaped udp is 1328; with shaping budget from `transport.MaxPacket(t, s, 1452)` (minus the path header and WireGuard's 32). `memory.NewNetwork(sem, memory.AcceptShaping())` runs shaped maps in-process. Links and listeners that shape are `transport.SendReporter`s for telemetry.

**API** (TP-008):
- `internal/dataplane` (engine, builds for Android): `NewEngine(EngineConfig{ID, Space, WireGuardKey, Registry, TUN tun.Device, Interface netcfg.Configurator, LinkMTU, Path path.Options, Log *slog.Logger}) (*Engine, error)`; `(*Engine).Apply(ctx, netmap.Section) error`, `Serve(transportName, transport.Listener) error`, `Inbound(transportName) transport.Peers`, `Status() Status`, `Close() error`. The engine creates the `path.Node` (Options.Space = Space) and owns the TUN and the configurator (closes both). `Interface` nil leaves the TUN alone (in-process tests). `Status{MTU, IPv6, IPv6Off, Peers []PeerStatus{ID, Device, Addresses, FirstHop, LastHandshake}, Skipped []string, Router router.Counters, Path path.Counters}`: no addresses but overlay ones.
- Conversions next to `PathConfigFrom`: `InboundFrom(section, reg, space) InboundConfig{Links map[transport][]PeerLink, Skipped}` (space stamped by the caller, never from the map; `CheckInbound` with parsed shaping); `OverlayMTU(PathConfig, InboundConfig, reg, linkMTU) int`; `OverlayConfigFrom(section, ownWGPublic, mtu) (OverlayConfig{Addrs, Networks, MTU, IPv6Off, Peers []OverlayPeer{ID, Key, Addresses}, Skipped}, error)`. Constants `DefaultLinkMTU` 1500, `MinOverlayMTU` 576 (`ErrMTUTooSmall`), `MinIPv6MTU` 1280, `OverlayDevice = "overlay"`.
- `router` (Android too): `New(tun.Device) *Router` (owns the TUN, drains its events), `NewEgress(name, mtu) (*Egress, error)`, `SetTable(Table{Overlay []netip.Prefix, Peers []Route, Rules []Route}) error`, `Counters()`, `Close()`; `Route{Prefix, Egress}` (nil Egress = block); `Egress` is a `tun.Device` (+ `SetMTU`, which raises `EventMTUUpdate`). `MaxPacket` 8192, `QueueLen` 512 per egress (full → drop, `QueueFull`; a slow device never stalls the others).
- `wg` (Android too): `New(name, tun.Device, *path.Bind, *slog.Logger) *Device`, `Configure(netmap.WireGuardPrivateKey, []Peer{Key, Node, AllowedIPs}) error` (brings it up on first call), `Peers() ([]PeerStatus, error)`, `Bind()`, `Close()` (closes TUN and Bind, `Release`s the Bind); `wg.Overhead` 32.
- `tun` (desktop only): `Create(name, mtu)`, `CreateInNamespace(nsPath, name, mtu)` (Linux; a fresh goroutine locks its thread, enters the namespace and dies with it), `DefaultName` "thinkpol0", `ErrUnsupported` elsewhere.
- `packettest`: IPv4/IPv6 ICMP echo and UDP builders/parsers with valid checksums, for tests on virtual TUNs.

**Layout and behaviour:**
- `TUN → router → egress (virtual tun.Device) → wg.Device → path.Bind → path.Node → links`. The real TUN is only in the router; every WireGuard device reads an egress. One device per egress: M0 has only `overlay`; `Engine.setDevices` already takes `map[device][]OverlayPeer`, removes peers leaving a device first, then sets every Bind in one `Node.SetPeers`, then configures each device, so a peer can move between devices.
- **Router classification:** a destination inside the space's overlay networks is decided by the peer routes alone (each peer's /32 and /128 → its device's egress); an overlay address without a peer is dropped (`NoRoute`), never handed to a rule. Everything else goes by `Rules` (empty in M0: dropped). Longest-prefix match is a map per prefix length; a trie can replace it behind `lpm` if TP-015's tables need it.
- **WireGuard config** by diff through `IpcSet` (no UAPI socket): `private_key` only when it changes; new peers get `endpoint=<node id hex>` and their allowed IPs; existing peers get `update_only` + `replace_allowed_ips` and never a new endpoint (re-setting it would overwrite the endpoint WireGuard adopted, which tells the Bind the path the leader chose); gone peers `remove`. A failed `IpcSet` makes the next Configure start over with `replace_peers`. Never `listen_port`, never `fwmark` (`TestNoListenPortOrMark`). Sessions survive re-applying a map (`TestReapplyKeepsSessionsAndDropsRemovedPeers`, `TestConfigureKeepsSessionsAndRefusesBadPeers`).
- **Peers skipped** (TP-003's caveats; `Status.Skipped` says why): zero or own WireGuard key, an address outside the overlay networks (IPv4-mapped included) or the node's own, no address the overlay carries, and *every* peer of a key or an address two peers claim. `wg.Configure` refuses overlapping allowed IPs itself too. A peer without usable first hops stays in WireGuard (the Bind's Send fails with `ErrNoPath`).
- **MTU:** `OverlayMTU` = min over every dialed endpoint and accepted link (each with its transport and its sending end's shaping) of `path.MessageBudget(t, shaping, linkMTU − 48)` − 32. Links are budgeted as IPv6 (40 + 8) whatever their endpoint's family, so nodes on IPv4 and IPv6 links agree: 1328 for unshaped udp over 1500, 1402 on the memory transport. No usable link: the registry's transports, unshaped. Capped at `path.MaxMessageSize − 32`. Below 576 Apply fails and changes nothing; below 1280 (`TestIPv6IsOffBelowItsMinimumMTU`) or without a usable own IPv6 address the TUN gets no IPv6 address, peers lose their IPv6 allowed IPs and routes, and `Status.IPv6Off` says why (DESIGN "IPv6" now says so). The TUN's MTU and the egresses' MTU follow every Apply.
- **Interface:** one `netcfg.Interface{Name, Addrs: [IPv4/<network bits>, IPv6/<network bits>], MTU, Up: true}`; the kernel's connected routes for those prefixes route the overlay into the TUN, so Linux needs no extra routes (an explicit route with the same key would collide with the kernel's).

**For downstream tickets:**
- **TP-011 (`thinkpol up`):** create the TUN (`tun.Create(tun.DefaultName, 1420)`; any MTU, Apply sets it) and `netcfg.New(OwnerOverlay)`, build the `Registry` (with TP-018's socket `Control`), `NewEngine`, `Apply` the opened section (and every newer one), then open each `Section.Node.Listeners` entry with `ListenConfig{Address, Settings, Peers: engine.Inbound(transport)}` and `go engine.Serve(transport, l)`; `Close` on SIGTERM removes the TUN, its addresses and the path layer. Status and logging: `Engine.Status()`, `EngineConfig.Log`. A worker in its namespace (TP-009) does the same inside it; from outside use `tun.CreateInNamespace` + `netcfg.NewInNamespace`.
- **TP-015 (rules):** the seam is `router.Table.Rules` (prefixes compiled from first-match rules into disjoint, longest-prefix routes; nil `Egress` = block). The engine sets only `Overlay` and `Peers` now: add a rules input to `Apply` (or a setter) that maps `chain:<name>` to that chain's device egress and keeps the overlay networks first. `direct` never enters the TUN in route-table mode.
- **TP-019 (macOS):** `tun_darwin.go` implementing `Create` with `wgtun.CreateTUN("utun", mtu)` (utun names itself; `Name()` gives the real name, which the engine already reads), and netcfg's darwin adapter. utun is point-to-point, so an address with a prefix length may not route the overlay networks into it: check, and if not, route them there (the engine sends only `Addrs`; add the routes in the darwin adapter or have the engine pass `Routes` on darwin). The router reads with a 16-byte offset (utun's 4-byte header fits).
- **TP-021 (IPv6 leaks):** while the overlay is IPv4-only (`Status.IPv6Off`), the kernel has no IPv6 route into the TUN (Linux disables IPv6 on an interface below 1280), so overlay IPv6 destinations would follow the physical default route: block them, and IPv6 generally (D6).
- **TP-030 (chains):** add a device per chain to the `want` map in `Engine.Apply` (its exit as the only peer, allowed IPs `0.0.0.0/0` + `::/0`; a key in one device only, which `Node.SetPeers` enforces), and rules → that device's egress. `wg.TestTwoDevicesBehindOneRouter` is the working shape. The builder's space-wide MTU should equal `OverlayMTU` of every node.
