## Goal
Waits only where no watcher can see the result. The owner wants a full lab to take at most 15 minutes on the remote runner. Measured 2026-11-16: a clean full lab takes 2823 s, and the remote runner's Docker starts only ~18–20 containers a minute, while a run starts 836 containers: the censor matrix 574 of them in 90 labs, each cell in use only 5–30 s.

## Scope
- (a) Blocked-probe windows (`blockedWindow`, lab/results_test.go:947–954, 8 s per family) and log-absence polls (`pollLog`, lab/results_test.go:1274, 3 s each): censord writes a flushed-through watermark, and probes stop as soon as the verdict log shows the blocking verdict.
- (b) Reality's blocked cells: `realityUp` waits 60 s for `link up` even when the cell expects a block (lab/reality_matrix_test.go:72–84). Stop on the censor verdict.
- (c) Kill switch: `time.Sleep(45 s)` and 4 × 10 s re-apply ticks (lab/killswitch_test.go:357–381), plus firewall `DirectTimeout` (const 30 s, internal/dataplane/firewall/killswitch.go:77) in internal/dataplane/firewall/killswitch_linux_test.go:485–499. Make the timeout and tick injectable, or watch the nft set element's `expires` refresh.
- (d) dns 500-iteration loop (115 s): fewer iterations with the false-pass probability stated, or the file on tmpfs. The per-update cost of 0.23 s needs a look.
- (e) Prober settle windows (settleWithin 2 min, judgedAfter 1 s sleep): lab prober settings with shorter timeouts.
- Every `lab.Eventually` bound stays as it is; they poll at 200 ms and cost only when slow.

## Out of scope
- Fixed sleeps in unit tests outside the lab and in-node tests: TP-173.

- What the early stop (R1.4) can still miss: the log has one decision per flow, verdict and module, so a flow the censor accepted, then dropped, then accepted again shows no second accept and looks blocked after the drop; a censor that blocks a flow for a while and then lets it through (by time, not by packet) is scored blocked at the first attempt it dropped, where the full window might have seen it cross. It never stops a tunnel whose one underlay flow got its verdict before the probe (udp, wireguard, openvpn-udp): those cells probe the whole blockedWindow, as before TP-241.

## Review findings
Review round 1 (four reviewers, two model families): two proven defects (R1.1, R1.4) and smaller ones.
- [x] R1.1 (should-fix) cmd/thinkpol/platform.go: `3*d >= firewall.DirectTimeout` overflows for d ≳ 854 h ("855h", "1000000h"): 3*d wraps negative, the check passes, and a negative direct timeout reaches nftables as a huge uint64 (direct destinations stay allowed long after the agent dies, or every Apply fails). Compare `d >= firewall.DirectTimeout/3`, and SetDirectTimeout treats d <= 0 as the default. Tests: "855h" and "1000000h" in TestLabKillSwitchReapply; SetDirectTimeout(negative) keeps 30 s; the default stays 30 s when the variable is unset (the mutation newKillSwitch(3*reapply) → newKillSwitch(3*time.Second) passes every test today).
- [x] R1.2 (should-fix) The "timeout = three re-apply periods" rule lives in cmd/thinkpol with a different constant than the agent's killSwitchReapply, while SetDirectTimeout's comment says "the agent keeps it above twice": put the rule in one place (the agent's kill-switch keeper sets the timeout from the resolved period) and make the comments say what the code does (firewall doc.go, internal/agent/doc.go, killswitch_linux.go, platform.go).
- [x] R1.3 (docs) docs/design/api-overview.md says lab variables are never read by a node and lists 14 THINKPOL_* keys: add THINKPOL_LAB_KILL_SWITCH_REAPPLY and correct THINKPOL_LAB's "Read by". docs/design/security.md states 30 s / 10 s as fixed: a lab node may shorten both, same ratio, and why a real install can't reach that.
- [x] R1.4 (should-fix) The early stop (`probeBudget.blocked`, untilAnswerOr, realityUp) counts any blocker drop/reset already in the cell's log (settle probe, hold, warm-up, an earlier attempt) and stops after the first failed attempt: a censor that drops only a flow's first packet, or one ping lost under load, scores "blocked" and a later attempt that would cross is never sent. Count only verdicts on this attempt's packets and stop only on those; otherwise probe to the old window. Tests: "stop always true" must fail one; a censor dropping only the first packet is scored as crossing. Say what the early stop can still miss.
- [x] R1.5 (should-fix) lab/reality_matrix_test.go: once.Do keeps the first caller's budget; in active-module rows the warm-up has no `blocked`, so blocked reality cells still wait 60 s. Pass the blocked check to the warm-up when the cell expects "fail".
- [x] R1.6 (should-fix) caughtUp: a packet the kernel drops before censord (QueueDropped, UserDropped) still takes an id (corrected in R2.5: only UserDropped's do, and a rare failed table insert's), so the read waits 30 s and blames the watermark: fail at once with the count when they rose since `queued`. Nit: the reader keeps the max watermark; check whether a lower id can be delivered later, and say.
- [x] R1.7 (should-fix, likely flake) lab/killswitch_test.go: a renewal is counted only when `left > last`; polls near a multiple of the period alias and report "renewed 0 times". Count a renewal when the absolute expiry (read time + left) moves later.
- [x] R1.8 (should-fix, likely flake) internal/dataplane/firewall/killswitch_linux_test.go: ~0.75 s between the loop's end and the renewed expiry; widen the margin so one slow nft read or ping can't fail it.
- [x] R1.9 (nit) lab/reality_matrix_test.go: statusWithin returns at once on errSchemaVersion and the loop has no sleep → 60 s of docker exec spin; return on errors.Is(err, errSchemaVersion).
- [x] R1.10 (nit) the lab prober's 1 s timeout: check it holds for a camouflage site under load and widen if needed, with the reason.
- [x] R1.11 (nits) the watermark test passes with eng.Handled(id) moved before decide: make the in-node test read only lines before the watermark so it fails; wrap long comment lines (dataplane.go, firewall doc.go, killswitch_linux.go).
