## Goal
Nodes that allow egress forward a space's internet traffic, IPv4 and IPv6, and nothing leaks across spaces.

## Scope
- Forwarding inside the space's namespace, out through its veth; masquerade once in the root namespace (nftables via a pure-Go library such as `google/nftables`).
- IPv6: NAT66 when the VPS has IPv6, otherwise reject with ICMPv6 unreachable so clients fall back fast.
- Nodes without egress drop internet-bound traffic.
- Full cleanup on stop.

## Acceptance
- [x] in the lab, a device fetches from the `internet` target through `server-2` (IPv4, and IPv6 where the lab has it): `lab/egress_test.go` `TestEgressThroughAnExit`, every server in server mode; device-a's chain ends at server-2, relayed by server-1's worker; `curl` over IPv4 and IPv6 returns the page and ping answers, and a capture at the internet node sees requests only from server-2's own two addresses. On a VPS without IPv6 (server-2's IPv6 default route deleted), IPv6 gets ICMPv6 "no route" at once and no IPv6 packet reaches the internet, while IPv4 goes on
- [x] an egress-off node refuses the same traffic: same test, server-2's egress turned off while device-a keeps its older map (same link secrets, `-insecure-secrets-seed`) and still sends its internet traffic to server-2: no fetch succeeds, nothing reaches the internet, the overlay through server-1 to server-2 still answers. Root-namespace rules on their own: `internal/agent/supervisor` `TestEgress` (lab node): a space with egress reaches a namespace behind the uplink over IPv4 and IPv6 masqueraded to the uplink's addresses, an overlay source SNATed first; a second space on the same node without egress gets nothing out (not through the first's egress either) but the endpoint its section dials, and only on that port; egress off closes it; a LAN namespace's forwarded traffic keeps its source (no masquerade of non-transit sources); forwarding is turned on and restored by `Close`

- **Done in TP-014 (2026-10-12, review round included):**
  - **Root table** (`supervisor/isolation_linux.go`, `inet thinkpol-supervisor`, rebuilt from every slot in one flush): `antispoof` (prerouting, raw−10: any source but the slot's transit address dropped *before conntrack*); `ct_pre`/`ct_out` (zone N+1 for what a space exchanges with its root end and its broadcasts, and what the root sends it); `forward`: invalid/untracked from a space drop → per slot `iifname != tp-space* oifname tp-spaceN ct state established,related ct original saddr <transit> accept` → `oifname tp-space* drop` → `iifname tp-space* goto space_out` → for each family whose forwarding the supervisor turned on, `iifname != tp-space* oifname != tp-space* drop`; `space_out`: per slot `ct state new ct count over MaxFlowsPerSpace drop` → `EgressAllowed` → goto `space_accept` → `egressBlocked` (0/8, 10/8, 100.64/10, 127/8, 168.63.129.16, 169.254/16, 172.16/12, 192.168/16, 224/3, ::/127, ::ffff:0:0/96, fc00::/7, fe80::/10, ff00::/8) and both transit ranges drop → goto `space_accept`; `space_accept`: per slot and family granted and carried `iifname tp-spaceN oifname <uplink> ct original saddr <transit> accept`, per dial `… daddr A meta l4proto <proto> th dport P …`, then drop; `input`: per slot `ct state established ct original daddr <transit> accept` (no related), then drop; `postrouting` (nat): transit ranges masqueraded to ports 32768–60999 when not leaving to a space; `postrouting_guard` (srcnat+10): a transit source still there dropped.
  - **Isolation** (B1, deviates from TP-009's zones): anti-spoof before conntrack plus every accept bound to the conntrack entry's original-direction address. Conntrack takes an ICMP error as related to the flow it quotes; a forged one quoting another space's flow or a root flow gets that flow's entry, which no accept of the forger's slot matches, and the input chain takes no related at all. Forwarded flows (egress, dials) stay in zone 0, because replies arrive on the uplink before anything could tell their zone; zones (for what a space exchanges with its root end) are belt and braces. google/nftables sends a ct direction as 4 bytes (the kernel reads the first, 0 = original, all this uses) and can't read such rules back: tests read counters from `nft list chain`.
  - **Space table** (`supervisor/egress_linux.go`, `inet thinkpol-space` in each space's namespace, installed by the supervisor through `nftables.WithNetNSFd` when the namespace is wired and again when the space's egress changes; a failure is logged and retried with the next change): forward policy drop: established accept, per family granted and carried `oifname veth0 accept`, a family not carried rejected with icmpx no-route when the space has egress; postrouting SNAT of any other source to the transit address, fully random in 32768–60999 (google/nftables can't combine a port range and fully-random in `masquerade`, so the randomness is here and the root's masquerade keeps the port). The namespace's forwarding sysctls are always on; the table decides. Deviation from TP-013's note: the SNAT is the supervisor's, not the worker's.
  - **Uplink** (S7): the supervisor's (`Options.Uplink`, default `egress.FindUplink`), found in `New`, on every `SetSpaces` and on route changes (netlink subscription, debounced); a name the tables can't match counts as none. `Space.Egress` is an `EgressGrant{IPv4, IPv6}` the supervisor intersects with the uplink's families. `FindUplink`: the lowest-metric IPv4 default route's link (IPv6's on a v6-only node), IPv6 only with a v6 default route by the same link and a global, not unique local, address.
  - **Root forwarding** (`supervisor/forwarding.go`, unit-tested with a fake /proc/sys that has the kernel's side effects): turned on per family only when off and some space needs it (egress or a dial); `accept_ra` 1 → 2 first on every interface but `all` and the spaces' veths; side effects recorded (IPv4: every `accept_redirects` and per-interface `forwarding`; IPv6: per-interface `forwarding`) and put back after the switch; each value put back only if it still holds what was written; recorded in `Options.RuntimeDir` (`/run/thinkpol/forwarding.json`, a tmpfs like the sysctls' lifetime; the state directory stays read-only) and adopted by a successor; turned off when no space needs it and on `Close`. Root veth ends get `accept_ra` 0.
  - **Flows:** a slot's conntrack entries (original source its transit addresses) are flushed when its egress changes and when the slot is freed. Each space's new flows are capped (`Options.MaxFlowsPerSpace`, default a quarter of `nf_conntrack_max`). Listeners can't bind inside 32768–60999 (`SetListeners` refuses them).
  - **Dials** (S4): `Space.Dials []Dial{Address, Network}` from the section's link endpoints with their transport's `Transport.Network()` ("udp"; tls will say "tcp"), accepted only out of the uplink and only to non-blocked destinations: the lab allows its private networks with `-egress-allowed` (`THINKPOL_EGRESS_ALLOWED`, `Options.EgressAllowed`).
  - **Engine and router:** `router.Table.Forward []*Egress`; `dataplane.EngineConfig.Forward` + `Status.Exit`: the overlay device forwards when the section is a server's with `AllowEgress` and `Forward` is set, which only `ServeSpace` (the worker) does; a server in `-mode device` logs `exit=off` and warns. Chain-exit devices never forward. `router.Counters.Forwarded`/`EgressStatus.Forwarded`, counted before the write (a TUN with offloads coalesces packets in place and its `Write` returns bytes: `Delivered` counts bytes there, a TP-008 leftover noted for TP-018).
  - **Logs and status:** `map applied` says `egress=on|off`, with egress `uplink=<if> egress_ipv4=on|off egress_ipv6=on|off` (or `uplink=none` and a warning), the worker's `exit=on|off`; `Supervisor.Egress() EgressInfo{Uplink, IPv4, IPv6, Forwarding4, Forwarding6, Err}` is the server status's `uplink` (local API `Status.uplink`, rendered by `thinkpol status`); `router.forwarded` in a device's counters. Counters and names only: no destination is logged or counted (S4).
  - **devmap:** the spec's rules and chains are TP-020's (space-wide `rules` and `chains`, the exit checked where it is written, the path to it by node); this ticket's per-device ones gave way to them at the merge. `dev map build -insecure-secrets-seed` derives each link's secret with HMAC-SHA256 of its ends and transport (`Plan`/`Build` take a `Secrets` source); inspect no longer says egress isn't enforced. `lab/maps/egress.yaml`. `lab/ingress_test.go` runs server-1 in server mode.
  - **Not done, with reason:** device-mode egress (devices can't allow egress, and a server in device mode is for debugging). Guests on a shared node (TP-040) aren't servable yet, so cross-space egress isolation is proven at the supervisor level (two spaces in `TestEgress`, `TestForgedICMPErrorsAreRefused`). nft rule counters on the accepts were removed rather than read into `WorkerInfo` (only drops count).
