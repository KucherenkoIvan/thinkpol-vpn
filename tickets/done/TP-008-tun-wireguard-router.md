## Goal
Packets written to the overlay interface reach the right peer through WireGuard and the path layer, and back.

## Scope
- TUN via `wireguard-go/tun` (Linux now).
- Router reading the TUN and dispatching to WireGuard devices through virtual `tun.Device`s, structured for one WireGuard device per egress (only the overlay device for now).
- WireGuard devices configured from the node's map section: peers, allowed IPs = overlay addresses, dual-stack.
- No WireGuard UDP socket is ever opened: the Bind is the path layer.

## Acceptance
- [x] two nodes in separate namespaces ping each other over overlay IPv4 and IPv6 — `TestNamespacesPingOverTheOverlay` (`internal/dataplane/engine_lab_test.go`, `make lab-gotest PKG=./internal/dataplane/`): device-a, server-1 and device-b each in a network namespace with a real TUN (`tun.CreateInNamespace`) configured by `netcfg.NewInNamespace(…, OwnerOverlay)` (addresses /16 and /48, MTU 1328), links over real udp sockets (device-a over IPv4, device-b over IPv6 loopback); the kernel's `ping` and `ping -6` succeed a↔server-1 directly and a↔b through server-1 as relay (server-1's `Forwarded` > 0, device-a's first hop to b is server-1); closing an engine removes its TUN. In process the same M0 topology runs on the memory transport, datagram and stream (`TestDevicesReachEachOtherDirectlyAndThroughARelay`: ping and UDP both families, both directions)
- [x] the router is ready for several WireGuard devices (test with two dummy egress devices) — `TestRoutesEachDestinationToItsEgress` (two egresses: overlay peers first, then rules by longest prefix, block, no route, an overlay address without a peer never falls through to the exit's default), `TestAFullQueueDropsInsteadOfBlocking`; and with two real WireGuard devices on one node: `wg.TestTwoDevicesBehindOneRouter` (overlay device with a device peer, an egress device whose exit has `0.0.0.0/0` + `::/0`, both Binds set in one `Node.SetPeers`)

## Notes
- From TP-003's review: `netmap`'s reader (`(*Map).Open`) checks only that a section is well formed. It accepts what only `netmap.Build` rejects: repeated or overlapping overlay addresses, addresses outside the overlay, empty `Paths`, `NextHops` or `Endpoints`, invalid (zero) `netip.AddrPort`s, and routing loops across several nodes. Don't assume them away: never configure overlapping WireGuard allowed IPs (refuse a peer whose addresses collide with another peer's or the node's own, or fall outside the overlay), and tolerate peers without usable paths.
- From TP-006 (path layer API in its ticket's Notes): one `path.NewNode` per space worker with `Options.Space` set, `Update(dataplane.PathConfigFrom(section, registry).Table)` on each map, `Serve(name, listener)` per listener; one `NewBind()` per WireGuard device, all devices' peers set in one `Node.SetPeers` call so a peer can move between devices. A peer key lives in exactly one device: a chain's exit is a peer of that chain's device only. `Release` a Bind with its device.
- WireGuard peers get `endpoint=<node id hex>`, never a UDP address; no `listen_port`; never `fwmark` (the Bind's `SetMark` refuses it, so `Up` fails loudly).
- MTU: `path.MessageBudget(t, shaping, maxUnit)` per link (maxUnit = path MTU less IP and UDP headers; it applies `transport.MaxPacket` and the path header); the TUN MTU is the minimum over the node's links less 32 (WireGuard's data overhead): 1328 for a 1500-byte IPv6 path over unshaped udp. Refuse IPv6 on the overlay when that is below 1280, and surface it in status.
- **From TP-027:** fill `DialConfig.Shaping` / `PeerLink.Shaping` with `transport.ParseShaping(endpoint.Shaping)` / `(inbound.Shaping)` before `CheckEndpoint` / `CheckInbound`. udp's overhead is now 74 bytes (not 72): TUN MTU on a 1500-byte IPv6 path over unshaped udp is 1328; with shaping budget from `transport.MaxPacket(t, s, 1452)` (minus the path header and WireGuard's 32). `memory.NewNetwork(sem, memory.AcceptShaping())` runs shaped maps in-process. Links and listeners that shape are `transport.SendReporter`s for telemetry.

**API** (TP-008, as of the review fixes):
- `internal/dataplane` (engine, builds for Android): `NewEngine(EngineConfig{ID, Space (non-zero), WireGuardKey, Registry, TUN tun.Device, Interface netcfg.Configurator, LinkMTU, Path path.Options, Log *slog.Logger}) (*Engine, error)`; `(*Engine).Apply(ctx, netmap.Section) error`, `Serve(transportName, transport.Listener) error`, `Inbound(transportName) transport.Peers`, `Status() Status`, `Close() error`. The engine creates the `path.Node` (Options.Space = Space) and owns the TUN and the configurator once NewEngine succeeds (on error the caller still owns and closes them). `Interface` nil leaves the TUN alone: in-process tests, and platforms where the OS configures the TUN (VpnService, NetworkExtension).
- `Status{MTU, IPv6, IPv6Off, Peers []PeerStatus{ID, Device, Addresses, FirstHop, LastHandshake, RxBytes, TxBytes}, Neighbors []path.NeighborStatus, Egresses []router.EgressStatus, Skipped []Skip, LastApplyError, Router router.Counters, Path path.Counters}`. No addresses but overlay ones, nothing quoted from the map: `Skip{Node, What Item, Reason Reason}` (fixed vocabularies, `skip.go`); `IPv6Off` is `ErrIPv6MTU`'s or `ErrNoIPv6Address`'s text; `LastApplyError` is a step name (`StepSection`, `StepRemovals`, `StepInterface`, `StepDevices`, `StepRouter`). The details (`SkipDetail{Skip, Err}`, the failed step's error) go only to `EngineConfig.Log` at debug level (`TestStatusQuotesNothingFromTheMap`).
- Conversions next to `PathConfigFrom` (whose `Skipped` is now `[]SkipDetail` too): `InboundFrom(section, reg, space) InboundConfig{Links map[transport][]PeerLink, Skipped}` (space stamped by the caller, never from the map); `OverlayMTU(*PathConfig, *InboundConfig, reg, linkMTU) int` (drops links that leave less than `MinOverlayMTU`); `OverlayConfigFrom(section, ownWGPublic, mtu) (OverlayConfig{Addrs, Local, Networks, MTU, IPv6Off, Peers []OverlayPeer{ID, Key, Addresses}, Skipped}, error)`. Constants `DefaultLinkMTU` 1500, `MinOverlayMTU` 576, `MinIPv6MTU` 1280, `OverlayDevice = "overlay"`.
- `router` (Android too): `New(tun.Device) *Router` (owns the TUN, drains its events), `NewEgress(name, mtu) (*Egress, error)` (names unique), `SetTable(Table{Overlay, Peers, Rules []Route, Local []netip.Addr}) error`, `Counters()`, `Egresses() []EgressStatus`, `Close()`; `Route{Prefix, Egress}` (nil Egress = block); `Egress` is a `tun.Device` (+ `SetMTU` raising `EventMTUUpdate`, `Status() EgressStatus{Name, MTU, Queued, Routed, Delivered, NotLocal, QueueFull, TooLarge}`). `QueueLen` 512 per egress (full → drop; a slow device never stalls the others); queue buffers sized by the egress's MTU. `MaxPacket` 8192 bounds reads and egress MTUs; the overlay MTU is always below it.
- `wg` (Android too): `New(name, tun.Device, *path.Bind, *slog.Logger) *Device`, `Configure(netmap.WireGuardPrivateKey, []Peer{Key, Node, AllowedIPs}) error` (brings it up on first call), `Peers() ([]PeerStatus, error)` (parse errors reported), `Bind()`, `Close() error` (closes TUN and Bind, `Release`s the Bind); `wg.Overhead` 32. WireGuard's errors caused by `path.ErrNoPath` (every packet and handshake retry to a pathless peer) are logged at debug; the path layer counts them as `NoPath` (`TestPathlessPeersDoNotFloodTheLog`).
- `path`: new counters `TooLarge` (a message longer than WireGuard's maximum, or a write the transport refused as too long for the network path) and `WriteFailed` (other write errors); before, both were swallowed. `transport.ErrPacketTooLong` is the port's sentinel for the latter; udp wraps EMSGSIZE (WSAEMSGSIZE on Windows) in it.
- `netcfg`: deleting an address now treats ENXIO as gone: a TUN whose MTU drops below 1280 loses IPv6 and its IPv6 addresses before the delete (`TestIPv6GoesAndComesBackWithTheMTU`).
- `tun` (desktop only): `Create(name, mtu)`, `CreateInNamespace(nsPath, name, mtu)` (Linux; a fresh goroutine locks its thread, enters the namespace and dies with it), `DefaultName` "thinkpol0", `ErrUnsupported` elsewhere (Android included).
- `packettest`: IPv4/IPv6 ICMP echo and UDP builders/parsers with valid checksums, for tests on virtual TUNs.

**Layout and behaviour:**
- `TUN → router → egress (virtual tun.Device) → wg.Device → path.Bind → path.Node → links`. The real TUN is only in the router; every WireGuard device reads an egress. One device per egress: M0 has only `overlay`. The layout is `Engine.assign(OverlayConfig) map[device][]devicePeer`, where `devicePeer{OverlayPeer, AllowedIPs}` keeps the router's peer routes (the peer's overlay addresses) apart from WireGuard's allowed IPs (a chain's exit adds the default routes). `TestAPeerMovesBetweenDevices` moves a peer to a second device and back through an internal hook; a device left without peers is closed after the router stops using its egress.
- **Apply order (revocation first):** a section of another node is refused before anything changes (`StepSection`). Otherwise: convert; set the listeners' tables and the path table; take every peer, and every peer address, the new section no longer allows off WireGuard, the Binds and the router (closing departing devices last); only then stop if the section can't run here (no usable IPv4 address, MTU); then the interface (netcfg), the devices' additions, the router table. A failed step is `Status.LastApplyError`; the engine then runs the earlier steps of the new section and the rest of the old one, and re-applying converges. `TestRevocationIsNotHeldBackByABadLink` (dropped peer plus an unusable link: the link is skipped, the peer is cut off at WireGuard, its packets never reach the stack) and `TestASectionThatCannotRunStillRevokes`. A peer re-added after removal has a fresh WireGuard state; the far end's old session recovers on the next handshake from this side, or after WireGuard's 15 s.
- **Router classification:** a destination inside any of the space's overlay networks, carried or not, is decided by the peer routes alone (each peer's /32 and /128 → its device's egress); an overlay address without a peer is dropped (`NoRoute`), never handed to a rule (`TestIPv6IsOffBelowItsMinimumMTU` installs `::/0` → overlay through a test hook and shows the ULA still has no route). Everything else goes by `Rules` (empty in M0). Longest-prefix match is a map per prefix length; a trie can replace it behind `lpm` if TP-015's tables need it.
- **Decrypted packets** reach the TUN only for the node's own (carried) overlay addresses, `Table.Local`; anything else is dropped and counted `NotLocal`, so a peer that allows itself everything can't route through the node into its LAN (`wg.TestTwoDevicesBehindOneRouter`, `TestEgressWritesOnlyLocalDestinations`).
- **WireGuard config** by diff through `IpcSet` (no UAPI socket): `private_key` only when it changes; new peers get `endpoint=<node id hex>` and their allowed IPs; existing peers get `update_only` + `replace_allowed_ips` and never a new endpoint (re-setting it would overwrite the endpoint WireGuard adopted, which tells the Bind the path the leader chose); gone peers `remove`. A failed `IpcSet` makes the next Configure start over with `replace_peers`. Never `listen_port`, never `fwmark`. Sessions survive re-applying a map.
- **Peers skipped** (TP-003's caveats): zero or own WireGuard key, an address outside the overlay networks (IPv4-mapped included) or the node's own, no address the overlay carries, and *every* peer of a key or an address two peers claim. `wg.Configure` refuses overlapping allowed IPs itself too. A peer without usable first hops stays in WireGuard.
- **MTU:** `OverlayMTU` = min over every dialed endpoint and accepted link (each with its transport and its sending end's shaping) of `path.MessageBudget(t, shaping, linkMTU − 48)` − 32, budgeted as IPv6 whatever the link's family: 1328 for unshaped udp over 1500, 1402 on the memory transport. A link below `MinOverlayMTU` is skipped (`ReasonMTUTooSmall`), not the section. It is the node's own floor until the builder computes a space-wide MTU (TP-030; DESIGN "IPv6" says so); relays drop and count what is too long for their next link (`path.Counters.TooLarge`). Below 1280, or without a usable own IPv6 address, the TUN gets no IPv6 address, peers lose their IPv6 allowed IPs, and `Status.IPv6Off` says why; the lab test turns IPv6 off and on again across Applies.
- **Interface:** one `netcfg.Interface{Name, Addrs: [IPv4/<network bits>, IPv6/<network bits>], MTU, Up: true}`; the kernel's connected routes for those prefixes route the overlay into the TUN, so Linux needs no extra routes.

**For downstream tickets:**
- **TP-011 (`thinkpol up`):** the agent's job, around the engine; this is the body of `agent.RunDataPlane` (DESIGN "Repository layout", engine and agent): create the TUN (`tun.Create(tun.DefaultName, 1420)`; Apply sets the MTU) and `netcfg.New(OwnerOverlay)`, build the `Registry` (with TP-018's socket `Control`), `NewEngine` (close TUN and configurator yourself if it fails), `Apply` the opened section and every newer one, then open each `Section.Node.Listeners` entry with `ListenConfig{Address, Settings, Peers: engine.Inbound(transport)}` and `go engine.Serve(transport, l)`, reconciling listeners when a map changes them; `Close` on SIGTERM removes the TUN, its addresses and the path layer. Status: `Engine.Status()` (safe for the local API and telemetry); give `EngineConfig.Log` a local logger only. A worker in its namespace (TP-009) does the same inside it; from outside use `tun.CreateInNamespace` + `netcfg.NewInNamespace`. depguard keeps `dataplane`, `netmap` and `lists` from importing `agent`.
- **TP-015 (rules):** the seam is `router.Table.Rules` (first-match rules compiled into disjoint longest-prefix routes; nil `Egress` = block), filled through `Engine.rules` (now nil; the tests' hook shows the shape). The overlay networks stay first. `direct` never enters the TUN in route-table mode.
- **TP-019 (macOS):** `tun_darwin.go` implementing `Create` with `wgtun.CreateTUN("utun", mtu)` (utun names itself; the engine reads `Name()`), and netcfg's darwin adapter. utun is point-to-point, so an address with a prefix length may not route the overlay networks into it: check, and if not, route them there. The router reads with a 16-byte offset (utun's 4-byte header fits).
- **TP-021 (IPv6 leaks):** while the overlay is IPv4-only (`Status.IPv6Off`), the kernel has no IPv6 route into the TUN (Linux disables IPv6 on an interface below 1280), so overlay IPv6 destinations would follow the physical default route: block them, and IPv6 generally (D6). Also on a running node: when an Apply turns IPv6 off, open IPv6 connections keep retransmitting, and those retransmits leave by the physical default route the moment the TUN's IPv6 route goes; the firewall must already block it then.
- **TP-022 / TP-041 (local API, telemetry):** `Engine.Status()` carries peers (handshake, bytes, first hop), neighbors (links, RTT, up), per-egress counters, router and path counters and typed skips; nothing in it quotes the map.
- **TP-030 (chains):** return a device per chain from `Engine.assign` (its exit as the only `devicePeer`, `AllowedIPs` its overlay addresses plus `0.0.0.0/0` + `::/0`; router peer routes stay the exit's overlay addresses; a key in one device only, which `Node.SetPeers` enforces), and rules → that device's egress. An exit's decrypted traffic is for internet destinations, so the chain's egress must relax the `Local` check (e.g. a per-egress option): today every egress writes only to the node's own addresses. `wg.TestTwoDevicesBehindOneRouter` and `TestAPeerMovesBetweenDevices` are the working shapes. The builder's space-wide MTU should be at most every node's `OverlayMTU`.
