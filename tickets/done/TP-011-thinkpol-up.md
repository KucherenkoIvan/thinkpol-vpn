## Goal
One command starts a node from its keys and map: device mode on a device, supervisor mode on a server.

## Scope
- Configuration with go-kernel `config` (env + flags: state dir, map path, mode).
- Composition with go-kernel `app.Run`: TUN, WireGuard, path layer, transports, supervisor or worker; logging with `observability`.
- Map loaded and verified at start; refuse to start on an invalid map.
- State dir layout (`/var/lib/thinkpol`): only the node's own keys and its map (S1).
- Graceful shutdown with netcfg cleanup.

## Acceptance
- [x] lab nodes start with `thinkpol up` — `lab/up_test.go` `TestUpRunsTheM0Space`: the M0 space (`lab/maps/m0.yaml`) on the standard topology, server-1 in server mode (supervisor + sandboxed worker), device-a and device-b in device mode; pings device-a → server-1 (IPv4, IPv6), device-a ↔ device-b through server-1 (IPv4 and IPv6, both ways), device-b → server-1 (IPv4), then again after a new map taken by file change (server-1, device-a) and by SIGHUP (device-b)
- [x] SIGTERM leaves no interfaces, routes or namespaces behind — same test: every `thinkpol up` exits 0 on SIGTERM; then no `thinkpol0` or `tp-space*` link, no route of proto 84/85/86 (IPv4, IPv6, every table), no `thinkpol` nftables table, no `thinkpol up`/`worker` process, no named namespace (the workers' namespaces die with them); the test first checks the TUN, veth, table and worker exist while running
- [x] the state dir contains nothing but keys and the map — same test: `ls -A /var/lib/thinkpol` is `map.bin node.key space.pub` after the run, and `find / -xdev -newer <start>` finds no file written outside /proc, /sys, /dev, /run, /tmp (no log, pid or lock file); `LoadState` refuses `space.key`/`recovery.key` in it and reports anything else unexpected

## Notes
- Keys and maps (from TP-004's review): `thinkpol up` defines its own state-dir and key-file format in `internal/agent`. It may reuse the on-disk layout of TP-004's dev key files (`<name>.key` with quoted hex `node-id`, `map-key`, `wireguard-key`; `space.pub` with `space-id`, `signing-key`, `recovery-key`; private files 0600, refused when others can read them), but the reader lives outside `internal/devmap`, which depguard keeps to `cmd/thinkpol`'s dev commands. The runtime key types are in `internal/netmap`: `NodePrivateKey`, `WireGuardPrivateKey` (`ParseNodePrivateKey`, `ParseWireGuardPrivateKey`, redacted `String`), and `netmap.Trust`. Load with `netmap.Verify(env, trust)` then `(*Map).Open(mapKey)`; the node's id is `Section.Node.ID`.
- Listeners: a dual-stack server's map has `udp 0.0.0.0:p` and `udp [::]:p`; the udp adapter binds each to its own family (fixed in TP-004), so open both.
- From TP-006: the composition root builds the transport `Registry` with the socket `Control` from TP-018 (`udp.New(udp.Options{Control})`); the path layer and WireGuard never mark sockets themselves.
- **From TP-010 (`thinkpol up`):**
  - **Supervisor mode.** Build `supervisor.Options{Transports: registry, …}`. Per served space, verify and open its map, then `Space{ID, Config, Inbound: dataplane.AcceptedInbound(section, reg, transport.SpaceID(id), linkMTU).Links}`. `SetListeners` from the **node owner's** section `Node.Listeners` only (dual-stack: both `0.0.0.0:p` and `[::]:p`). Re-run both on every map change.
  - **Worker mode.** `agent.RunDataPlane` takes one Inbound abstraction in device and worker modes. In device mode it opens `Transport.Listen`; in worker mode, `SharedListener.Listen(reg, ListenConfig{Peers: engine.Inbound(l.Transport)})` for each listener on `Session.Listeners`, then `go engine.Serve(l.Transport, listener)`, stopping when `l.Done` closes. Feed `Session.SharedCounters` and `SharedDrops` into the worker's status and telemetry. Workers' veths carry only their dialed links and egress.

- **Done in TP-011 (2026-10-11):**
  - **State directory** (`/var/lib/thinkpol`, `-state`/`THINKPOL_STATE_DIR`): `node.key` (`node-id`, `map-key`, `wireguard-key`, quoted hex: the layout `dev keygen node` writes, so TP-012 copies `<name>.key` to `node.key`; refused unless 0600 on Unix), `space.pub` (as `dev keygen space` writes it; refused if group/other-writable), `map.bin` (or `-map`/`THINKPOL_MAP`). The directory is refused if group/other-writable, and if it holds `space.key` or `recovery.key`; other entries are logged and ignored. Reader: `internal/agent/keyfile.go` (line-based, no devmap). `up` only reads it and writes nothing to disk; netcfg's locks are under `/run/thinkpol`. DESIGN.md "Node safety" says so.
  - **Start.** `agent.LoadConfig` (go-kernel `config`, environment `THINKPOL_*`, no `.env` files: it loads `os.DevNull`), flags override (`-state -map -mode -log-level -interface -link-mtu -map-poll`). `agent.Prepare(cfg, logs)` → `LoadState`: `netmap.Verify(map, trust)`, `Open(map-key)`, section's node id = key file's; any failure exits 1 before anything is touched. `(*Node).Run` refuses an unsupported host first (`agent.ErrUnsupported`; `platform_other.go`: everything but `linux && !android`), so macOS gets "no data plane on darwin yet" without a change to the host (TP-019 flips it).
  - **Modes.** `-mode auto` (default) picks by the node's kind in its own section: server → server mode, device → device mode; `device`/`server` override (a server in device mode listens on its own sockets: handy for debugging). A map that changes the node's kind is applied with a warning; the mode changes only on restart.
  - **Device mode:** go-kernel `app.Run` with a map watcher and `agent.RunDataPlane(ctx, DataPlane{Keys, Map, Maps, Registry, Inbound: DirectInbound(reg), Interface, LinkMTU, Log})`: `netcfg.New(OwnerOverlay)` first (a second node agent fails with `ErrBusy` before a TUN exists), `tun.Create(name, 1420)`, `dataplane.NewEngine`, the first `Apply` (fatal if it fails: the node shouldn't look up), then the listeners and the loop.
  - **Server mode:** `supervisor.New(Options{Transports, Log, Env: THINKPOL_LOG_LEVEL, Output})`, then per map `SetSpaces([]Space{{ID, Config: WorkerConfig, Inbound: dataplane.AcceptedInbound(section, reg, space, linkMTU).Links}})` and `SetListeners` from the node's own `Node.Listeners` (both `0.0.0.0:p` and `[::]:p` from devmap). Only the owner's space for now. The first `SetSpaces` failing is fatal; later failures (and `SetListeners` errors, whose other listeners are served) are retried every 5 s. `thinkpol worker` runs `agent.ServeSpace(log)` under `worker.Run`: it waits for the `WorkerConfig` (JSON: version, node id and private keys in hex, the trust, the envelope, interface, link MTU; sent by the supervisor after Ready, as a sealed memfd when large), `Verify`s it again, and runs the same `RunDataPlane` with `SharedInbound(ctx, reg, Session.Listeners)`; each later config feeds `Maps`, and a config with other keys or trust ends the worker. `Session.SharedCounters` and `SharedDrops` go into the worker's debug status line (`DataPlane.StatusAttrs`; no telemetry yet).
  - **One Inbound abstraction:** `agent.Inbound{Listeners(section) []Listener; Changed()}` with `Listener{Key, Transport, Open(ctx, peers), Done}`. RunDataPlane reconciles by key: closes what went, opens what's new with `engine.Inbound(transport)` as peers and `go engine.Serve`; a listener that fails to open or stops on its own is retried every 5 s (a shared listener whose `Done` closed never is).
  - **Reload semantics** (no controller, DESIGN rule 2): the map file is polled every `-map-poll` (5 s; changed = replaced, resized or touched) and read at once on SIGHUP. A map is taken only through `(*Map).Next` (valid signature, same space and keys, strictly newer); `ErrNotNewer` is ignored at debug, anything else is logged and the node keeps running on its current map, as it does when the new map has no section for its key (a revoked node keeps its last map; the other nodes drop it). Trust and keys are fixed for the process: change `space.pub` or `node.key` → restart. An `Apply` that fails is retried every 5 s until it or a newer map succeeds.
  - **Shutdown:** SIGTERM/SIGINT end `app.Run`; listeners close, `Engine.Close` removes the TUN, its addresses and the path layer, netcfg's `Close` its routes; in server mode `Supervisor.Close` stops the workers and removes veths and nftables tables. Exit 0.
  - **Logs (S2):** `agent.NewLogs(level, stderr)`: slog text to stderr and a 256 KiB `logring.Ring` (`Logs.Ring`, for TP-022). go-kernel `observability.NewLogger` isn't used: it writes JSON to stdout only. go-kernel's `app` logs through `slog.Default`, which `up` sets. Worker output goes to its space's ring in the supervisor and, line by line prefixed `worker space=<id>`, into the node's log stream (new `supervisor.Options.Output`). Debug level adds a status line every 30 s.
  - **Changes outside `internal/agent`:** `netcfg.New` works without `/proc` (the worker's sandbox has none): it falls back to `SIOCGSKNS` for the namespace handle (lock file) and opens netlink in the current namespace without vishvananda's namespace switch, which needs `/proc` to switch back; found by the lab test (the worker died with "netcfg: current namespace: no such file or directory"). `supervisor.Options.Output` (see Logs). DESIGN.md: "Node safety" (state directory) and "Engine and agent" (`thinkpol up`'s two modes, reload).
  - **Not done, with reason:** socket marking (no `udp.Options.Control` yet: M0 routes only the overlay into the TUN, TP-018 adds it in `agent.Transports`); key generation on the node (A4 is `node add`, TP-038); guest spaces (TP-040); the local API reading `Logs.Ring` and `Engine.Status` (TP-022).
- **Review round (2026-10-11):**
  - **State and map files (SEC-1/2):** the state directory is opened `O_NOFOLLOW|O_DIRECTORY`, every file `openat` relative to it with `O_NOFOLLOW|O_NONBLOCK`, then checked with `fstat` on the open descriptor: a regular file, owned by the euid or root, `node.key` not readable by others, nothing writable by group/other; reads are bounded (4 KiB keys, `netmap.MaxEnvelopeSize` maps). The map file and its directory follow the same rules wherever `-map` points, also in the watcher (a FIFO there never blocks: refused as not a regular file). Why: an older signed map put back in `map.bin` is taken at the next start (rollback), and `space.pub` decides which maps are trusted. `internal/agent/trusted_unix.go` (`trusted_other.go` reads without checks: no data plane there). A warning says when `-map` points elsewhere and the state directory has a `map.bin` too.
  - **Removed from the space (D1):** a valid newer map without the node's section is taken (no older map can bring the node back) and stops the data plane (device mode: listeners, engine, TUN, routes) or the space's worker and listeners (server mode: `SetSpaces(nil)`, `SetListeners(nil)`); the process stays up, logs `removed from space` once, and starts again (`back in space`) on a later map with the node. DESIGN "Engine and agent".
  - **Listeners (B1):** a listener whose `Serve` ends on its own is marked failed, then done, then signalled, and reopened after `RetryAfter`; failed opens wait the same. **Server start (S1):** listener errors at the first apply are retried, only `SetSpaces` failing is fatal. **First Apply** interrupted by SIGTERM exits 0.
  - **Worker output (SEC-3):** only the owner space's worker output is copied into the node's log (`supervisor.Options.Output` returns nil for others, never a guest's: DESIGN rule 6), with control bytes (< 0x20 but tab, 0x7f) written as `\xNN`.
  - **Renames:** `MapFile` → `MapFileName`, `agent.Worker` → `agent.ServeSpace`, `DataPlane.Status` → `StatusAttrs`. Defaults: `-interface ""` = `tun.DefaultName`, `-link-mtu 0` = `dataplane.DefaultLinkMTU`. `netcfg.New` keeps its thread locked across `SIOCGSKNS` and the netlink handle.
  - **Round 2:** `Prepare` cleans the paths; `openTrustedDir` walks the path from `/` with `openat(O_NOFOLLOW)`, every directory on it owned by root or the euid and not writable by others (a sticky one, like `/tmp`, is passed through: others can add entries there but not swap ours, and a foreign entry fails the owner check; the state directory and the map's directory themselves never). Tests resolve macOS's `/var` symlink (`tempDir`). Worker output is sanitized by rune (invalid UTF-8, C0, DEL, C1, bidi overrides escaped). A node whose on-disk map is valid but has no section for it starts idle (`State.Removed`, `Node.awaitSection`), deciding its mode once a map includes it. The watcher says a repeated read failure once.
  - **Deferred** (Notes there): TP-022 (`app.Run` out of the agent, a status handle, the supervisor), TP-037 (MapSource, one follower, persisting maps, first boot), TP-038 (shared key-file codec, `node.key` written on the node).
- **For TP-012 (M0 acceptance):** `lab/up_test.go` already does the setup TP-012 needs and can be its base: keys and map built on the `internet` node (`dev keygen` + `dev map build /src/lab/maps/m0.yaml` with `SERVER_1_IPV4/6`), each node gets `/var/lib/thinkpol/{node.key (0600), space.pub, map.bin}` in a 0700 directory, then `thinkpol up` (auto mode). Overlay: server-1 `100.64.0.1`/`<ula>::1` (inside its worker's namespace: ping it from a device, not from server-1's root namespace), device-a `.2`, device-b `.3`; the ULA is `ipv6-network` in `keys/space.key`. Ready = the log line `msg="map applied"` (the server's worker's is prefixed `worker space=`); pings converge within a few seconds. Left to TP-012: the capture at the router (no WireGuard signatures), the relay proof, the full matrix in `make lab-test`.
- **For TP-013 (ingress/egress settings):** the filter belongs in `dataplane.AcceptedInbound`, which both the supervisor (`serverSpaces.apply`) and the engine use. Node settings reach `up` through the section only.
- **For TP-014 (egress):** fill `supervisor.Space.Egress` in `serverSpaces.apply` (`internal/agent/node.go`) from the section; a worker's dials to its own section's endpoints need the root namespace's forward accept (TP-010 decision) — M0 needs none since devices dial the server.
- **For TP-018 (route table):** put the socket `Control` into `agent.Transports()`, the one registry the supervisor, workers and devices build; the route-table configurator (`OwnerRouteTable`) belongs next to `RunDataPlane` in device mode.
- **For TP-022 (local API/CLI):** a device-mode `Node` has everything to serve: `Logs.Ring`, the engine's `Status()` (thread it out of `RunDataPlane`, e.g. a `DataPlane.Started func(*dataplane.Engine)` hook), and the supervisor's `Workers()`/`Listeners()`/`Output(space)` in server mode. connect/disconnect = cancel/restart `RunDataPlane` with the space's state.
- **For TP-037 (gossip):** write a newer envelope to the map file atomically (temp + rename in the state dir, as `devmap.WriteMap` does) and send SIGHUP or let the poll see it; or feed `DataPlane.Maps`/the server's `maps` channel directly. The node already refuses anything `(*Map).Next` refuses.
- **For TP-040 (guests):** `serverSpaces.apply` builds the one `[]supervisor.Space`; guest spaces need their own key set and trust per space (DESIGN "Node safety"), e.g. `/var/lib/thinkpol/guests/<space-id>/{node.key,space.pub,map.bin}`, and `LoadState` would list that directory as expected.
- **For TP-041 (telemetry):** worker side, `Session.SharedCounters`/`SharedDrops` are collected in `agent.Worker` (now only logged at debug).
