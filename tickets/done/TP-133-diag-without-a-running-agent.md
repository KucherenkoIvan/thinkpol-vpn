## Goal
After a crash (kill -9, power loss) `thinkpol diag` still records what the dead agent left on the host: the evidence a device run needs most is the state after a crash, and today `diag` needs a running agent to answer.

## Scope
- When the local API doesn't answer, root's `diag` reads the host itself with the same readers the agent uses (netcfg, firewall, dns: routes and records, the guard's table/anchor and pf reference, the resolvers) and writes the same versioned snapshot, with `agent: "not running"` and the agent-only parts (status, TUN, last Apply) unreadable with that reason.
- Read-only, exactly as the agent's readers are: no lock taken, no directory made. A non-root caller without an agent gets an error, not a partial snapshot.
- The schema version stays 1 if only a value is added; say so.

## Acceptance
- [x] lab: SIGKILL a connected device's agent, then `diag -o` as root records its leftover routes, guard and resolver configuration, matching `ip -j`, `nft -j` and resolvectl
- [x] a unit test: no agent and no root → an error
- [ ] macOS: with no agent, root's diag records the guard's and kill switch's pf anchors and references, routes and the resolver configuration, through the agent's own read-only readers; unit tests with fakes; checked for real in the M2 device run (S5)

Exit codes against TP-167's table: no agent running (nothing accepts the socket: none, or a SIGKILLed agent's stale one) → the snapshot, 0, since it is all there is to take; an agent that holds the socket but gives no snapshot within a minute (or drops the connection unanswered) → the snapshot is written all the same and diag exits 69 (EX_UNAVAILABLE, `service_not_answering`, a new client-side refusal): the evidence is kept, but the result is short of the agent's snapshot, and "anything short of the requested state is not 0"; anyone but root → 77 and no snapshot, in both cases. Offline, `last_run` is read from the crash trace file as it is (never fixed, cut or emptied as a start does), and `agent_version`/`os` are the CLI's. macOS refuses a full socket backlog as it refuses a dead agent's socket, so a hung agent there with every slot taken reads as `not_running`.
- **Device checklist (M2 device run, S5), for the macOS box.** Why SIGSTOP first (review round 1, R1.1(a), the orchestrator's method): the service definition has KeepAlive with ThrottleInterval 5, so launchd restarts a SIGKILLed agent within seconds, and the new agent's first steps put the kill switch back and restore the host. A SIGKILL alone would leave diag the new agent's snapshot, or a half-restored host. A stopped process keeps its socket and doesn't exit, so launchd starts no other, and nothing of the agent runs, as after a crash. `launchctl kill` takes any signal name for a service target (launchctl(1): `kill signal-name | signal-number service-target`), so either command below works for the launchd job; `kill -STOP` needs the pid from `launchctl print`. Neither was run on a real Mac by an agent. In the lab, `pkill -STOP` on Linux (the same signal) gave exit 69, the waiting line and the snapshot. Do it with the kill switch on, then again with it off:
  1. Freeze the agent: `sudo launchctl kill SIGSTOP system/org.thinkpol.agent` (or `sudo launchctl print system/org.thinkpol.agent | grep pid`, then `sudo kill -STOP <pid>`). Check with `ps -o stat= -p <pid>`: expect `T`.
  2. `sudo thinkpol diag -o /tmp/diag-stopped.json; echo $?`. Expect a stderr line "the agent at … holds the socket but hasn't answered: waiting up to 60 s for it, then the host is read without it", then a `[service_not_answering]` line and exit 69: in the lab after about 23 s (gRPC gives up on the handshake the frozen agent never answers after 20 s, then 3 s to ask again), at most about a minute. The file holds `"agent": "not_answering"`, `status` null; `guard` and `kill_switch` (the latter only with the switch on) present with their pf anchors' rules, `pf.enabled`, and `pf.reference` recorded with the frozen agent's pid; `routes` the agent's; `dns` matching `scutil --dns`. Compare with `sudo pfctl -a com.apple/000.thinkpol -sr`, `sudo pfctl -a com.apple/001.thinkpol-killswitch -sr`, `sudo pfctl -s References`, `netstat -rn`.
  3. `thinkpol diag` as the member: exit 77, nothing on stdout.
  4. Kill it to test the restart: `sudo kill -KILL <pid>` (a stopped process takes SIGKILL). launchd starts a new agent within about 5 s. Run `sudo thinkpol diag -o /tmp/diag-after.json; echo $?` at once: if it caught the gap, exit 0 and `not_running`, or exit 69 and `restarted_during_read` when the new agent came up during the read; once the new agent answers, exit 0 and `running`. A `not_running` with exit 0 after the new agent was already up would be a bug.
  5. To end: `sudo launchctl bootout system/org.thinkpol.agent` (rollback is refused, exit 75, while the installed service runs), then `sudo thinkpol rollback` and `sudo thinkpol diag`: `not_running`, guard and kill switch gone. `sudo launchctl bootstrap system /Library/LaunchDaemons/org.thinkpol.agent.plist` brings the service back.
